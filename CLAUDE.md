Инструкции для Claude Code при работе с этим репозиторием.

## Язык общения

Всегда общайся с пользователем на русском языке.

## Справочники экономики (Cost V2)

Поля payload описываются только схемами в `cost/v2/schemas/`: единица
измерения — `x-unit`, ссылка на другой раздел — `x-ref`, короткая подпись
поля — `title`, пояснение — `description`. Новый раздел добавляется схемой,
записью в `SECTION_SCHEMAS` и в `REFERENCE_SECTION_DEFINITIONS`.

Интерфейс строит формы по каталогу схем и не хранит собственных знаний о
полях: не заводи разделоспецифичных компонентов (единственное исключение —
матрица условий бурения) и не показывай пользователю JSON — ни в поле ввода,
ни в подсказке.

## Модель себестоимости блока (TASK-007)

Нормы живут только в `cost/model/`, цены — только в справочниках. Новая
статья вида «цена × существующий драйвер» — это запись в `cost_rules`, а не
код; код нужен лишь для нового типа натуральной величины.

ТОиР и запчасти техники по возрасту — `cost/model/age_scale.py`: режим
`maintenance_mode = AGE_SCALE` типа техники, шкала `maintenance_age_tiers`
(процент первоначальной стоимости в год, ступени по годам с
`commissioned_on` основного средства); чего не хватает — предупреждение и
прежние ставки «₽ за смену».

Отсутствующая запись справочника даёт предупреждение и нулевую строку, а не
исключение. Постоянные затраты юнита распределяются по плановому объёму
юнита, постоянные затраты техники — по её плановым сменам; оба плана —
параметры вкладки. Подробности — `Docs/COST_MODEL.md`.

## Модель ФОТ по объектам (TASK-010)

Формулы — `cost/model/payroll.py` (приведённые метры, эффективные смены,
сдельная премия, месячный ФОТ, доля в марже), чтение справочников —
`cost/model/payroll_inputs.py`, превью — `POST /economics/payroll/preview`
(`cost/model/payroll_preview.py`). Премия — только на среднем темпе вахты, не
посменно; НДФЛ в затраты компании не входит; взносы — из ставок организации,
календарь и МРОТ — из «Параметров ФОТ» года. Экипаж бурения блока считается по методике при параметре вкладки `payroll_source = PAYROLL` (`cost/model/block_payroll.py`, плановый темп — `cost/model/pace.py`, цена метра и доля в марже — `cost/model/block_margin.py`), по умолчанию `PAYROLL` (снимок сценария без `parameters_version = 2` открывается на методике). Статьи ФОТ должности для кольца цены метра — `BlockEconomics.payroll_parts` (`inputs.PAYROLL_PARTS`). Подробности — `Docs/PAYROLL_MODEL.md`.

Цена метра бурения для листа «Расчёт» (блок 1.2) — тоже модель блока:
`cost/model/drilling_price.py`, параметры приходят в `context.drilling_model`
из активного черновика сметы; без них цена нулевая с пояснением в `notes`
(`Docs/COST_MODEL.md`, «Цена метра бурения для листа «Расчёт»»). Старого
калькулятора `cost/drilling.py` нет.

## Модель подбора q (Kuz-Ram)

Лист «Расчёт» подбирает q по Каннингему: формулы —
`simulation/fragmentation/cunningham.py`, подбор — `Blast.py::optimize_blast`,
окно «Модель Kuz-Ram» — `frontend/src/pages/calc/kuzram/`.
Прогноз одной точки собирает `cunningham.predict_point` — единственное место,
где формулы складываются вместе. Движок «Проектирования»
(`simulation/fragmentation/engine.py`) зовёт её во всех трёх моделях через
`simulation/fragmentation/base.py::region_point`; прежние формулы —
`simulation/fragmentation/legacy/` под именами `*_legacy`. Настройки модели
«Проектирование» берёт из объекта работ
(`api/services/fragmentation_settings.py`). ML-калибровки кусковатости
хранят базу (модель и версию baseline) и накладываются только на прогноз
той же базы, а пространственная модель считает физику скважин формулами
своей базы (модель другой версии той же формулы — текущей версией, с
просьбой переобучить) — `intelligence/calibration/base.py`; подробности —
`Docs/KUZRAM_MODEL.md`.

## Импорт чертежа маркшейдера (TASK-013)

Окно «Импорт чертежа» (`frontend/src/pages/design/cadImport/`) читает DXF/DWG
целиком и раскладывает сущности по ролям. Чтение и роли —
`design/spatial/cad/`, хранение — таблицы `cad_*`, API — `/design/cad`
(не `/spatial`: это ML-роутер, на проде он выключен). `$INSUNITS` не
масштабирует чертёж: масштаб 0,001 только предлагается по размеру. Шаблон
«имя слоя → роль» хранится на объекте (`site_code`). Контур блока (PR 2) — `design/spatial/cad/` (`rings`,
`stitch`, `contour`, `two_contours`, shapely ≥ 2), предпросмотр —
`POST /design/cad/sources/{id}/contour`; в паспорте — `contour.cad`, ключ
пишется только когда поле есть (иначе сменится хэш утверждённых паспортов).
Кровля (PR 3) — `design/spatial/cad/surface*.py`: CDT через PythonCDT
(запасной путь scipy — `BLASTEX_SURFACE_BUILDER`), предпросмотр —
`POST /design/cad/sources/{id}/surface`. Длина скважины — одна формула
L = (S − Z)/cos α + Δ (`geometry.hole_depth_m`), пересчёт —
`design/hole_recompute.py` и `POST /design/holes/recompute`; `surfaces.top.cad`,
`Hole.manual` и `contour.cad.map_volume_m3` пишутся только когда заданы.
Ситуация и СК (PR 4) — `design/spatial/cad/situation.py`, `crs.py`,
`api/services/cad_situation_service.py`: серии источников по названию, вид
объектов слоя, СК объекта в `cad_site_settings`, в паспорте —
`contour.cad.situation` и `coordinate_system.height_system` (только когда
заданы); на странице — `useSituation`, подложка `SituationCanvas`, группа
«Ситуация» в «Виде». Базовый слой холста окна — `<canvas>` (`CanvasHitIndex`).
Подробности — `Docs/CAD_IMPORT.md`; справка «?» окна обновляется в каждом PR
задачи.

## Темп отбойки (оптимизатор, часть 2)

Темп мс/м (задержка на метр между соседними скважинами, треугольники Делоне
по устьям) — `design/relief.py`: `relief_triangles`, `relief_stats`,
`burden_relief`. Приходит в ответе `POST /design/analyze` как `relief`; на
фронте — слой «Темп отбойки» пресета «Тайминг» (`frontend/src/pages/design/relief.ts`)
и сводка в панели «Тайминг». Ровность для перебора (часть 4): главный
показатель — `outside_share` (доля площади вне ±25 % от медианы), второй —
`robust_spread` (межквартильный размах к медиане); `cv` — справочный.
Порядок оценки: `fast_share` (быстрее нижней границы, 3 мс/м — `RELIEF_MIN_MS_M`)
→ `converging_length_m` (стыки сходящихся фронтов) → `outside_share` →
`robust_spread`. Границы «Темп отбойки от/до» живут в справочнике пород
(`relief_min_ms_m`/`relief_max_ms_m`, `relief_bounds_for_rock`): имя породы
пустое — молча 3 мс/м; порода не найдена — 3 мс/м и предупреждение; справочник
не прочитан — 3 мс/м и предупреждение; верхняя не больше нижней — верхняя
отбрасывается с предупреждением. В сетку темпа входят скважины семейства
сетки, кроме стабилизации и сателлитов, и вид основной сетки
(`pattern_params.default_kind`); пределы — по фактической раскладке
(`relief_limits`): «щепки» (высота < 0,3·s, s — медиана расстояния до
ближайшей соседней) и рёбра длиннее 1,6·max(max(a, b), L) отбрасываются,
как и треугольники с центром вне контура блока. Стык — столкновение породы (долина
времени, вруб по центру), а не встреча фронтов инициирования.
Подробности — `Docs/BURDEN_RELIEF.md`.

## Первый ряд у откоса (часть 3)

Линия подошвы (от неё ЛСП) — `design/toe_line.py::toe_line`: по умолчанию у
всех блоков — по углу откоса блока от верхней бровки на высоту уступа у
скважины (сдвиг сшитых цепочек `free_faces` — `_free_chains`, а не отдельных
рёбер: иначе в изломе бровки концы торчат или рвутся;
`Hole.bench_height_m`; на плане — по высоте блока; угол
90° — не задан, берётся 75° от горизонтали, `effective_face_angle_deg`;
умолчание схемы `face_angle_deg = 90` не трогать); съёмка нижней бровки —
только при `contour.toe_source = "survey"` (ключ пишется только при выборе
съёмки; решение владельца 07.11.2026: нижнюю бровку часто не снять — горная
масса, снег). Выбор — «Съёмка» → «Бровки» → «Линия подошвы»; снятая бровка
при подошве по углу — серым пунктиром на плане (`toe_line.survey_polylines`).
Правило развала — только в режиме съёмки; объём блока — по-прежнему по
снятой нижней бровке. Подробности — `Docs/FRONT_ROWS_TILT.md`, «Откуда линия
подошвы».

Три схемы — `design/pattern.py`, ключ `pattern_params.front_rows_mode`: нет
ключа — вертикальный первый ряд (при `front_rows_tilt_count` > 0 — `taper`);
`pair` — к скважине ранга 1 с ЛСП > W + 3 % добавляется `face_toe` («Наклонная
у откоса», номер `<id>T`) на 1 м ближе к откосу (`_face_pairs`); `taper` — 1–2
ряда перехода (α₁, α₁/2), один угол на участок ряда, ранг по столбцу, шаг b
у подошвы, устья соседних рангов не ближе 1 м (`_taper_front_rows`,
`taper_tan_limit`), шахматке не применяется. Все сдвиги устьев — вдоль
линии столбца к откосу (столбцы на одной линии — обязательно); наклоны
перехода — тоже, наклон пары — к откосу (см. ниже). Угол — не
больше `front_rows_tilt_deg` (≤ 30°, умолчание 15°; у пары — см. ниже) и ЛСП не меньше
max(0,8·W, 1 м) — по построенной скважине (`_verified_angles`: у скачка
съёмка ↔ развал оценка не годится). `min_crest_offset_m` (умолчание 0,2 м) — отступ устья от
кромки. Пара: устье сначала сдвигается к кромке (от 1 м, наименьший сдвиг до
ЛСП ≤ W, упор — отступ от кромки и разрыв у подошвы с вертикальной b + 3 %);
наклон — только если и у упора ЛСП > W: азимут к ближайшей точке подошвы, не
дальше 15° от столбца, угол наименьший до ЛСП ≈ W, не больше 30°
(`_smallest_angles`); `front_rows_tilt_deg` = 0 (флажок «Разрешить наклон пары» снят) — без наклона; перебор пробует одну пару. «Глубина» (`depth_m`, `*_depth_m`) —
глубина вертикальной скважины, у наклонной длина = глубина / cos α. Пара закрывает только свою вертикальную, в темп отбойки не входит.
Проверки `validate`: `floor_burden_short`/`_excess`, `floor_beyond_toe`,
`floor_row_gap_excess` (у подошвы шаг + 3 %), `collar_too_close_to_crest`
(только при ключах отступа, схемы или `layout_anchor = "back"`). Члены сетки в этих проверках —
`models.in_main_grid`: семейство сетки и ряды решётки стеночного вида
(`default_kind` или строка `row_params`; по номеру ряда, а не по виду), без
отдельных стеночных рядов (−1…−n, −10). Ключи пишутся только когда заданы
(иначе сменится хэш утверждённых паспортов). Подробности и проверка на №66 —
`Docs/FRONT_ROWS_TILT.md`.

Шаблон «от тыла» (PR 2 из 3) — `design/back_layout.py`, ключ
`layout_anchor = "back"` (только square/rectangular; нет тыла — от бровки) и
`back_offset_m` (нет ключа — линия отрыва 20·d, d — диаметр скважины
`diameter_mm`, он уже с учётом разбуривания; решение владельца 07.11.2026): тыл — наиболее длинная несвободная
сторона (излом > 45° делит), азимут — хорда (`POST /design/back-azimuth`,
вкладка «Сетка» → «Опора сетки»); решётка одна, приконтурный ряд — узел в
пределах отступ ± 0,15·b от тыла (на дуге — лесенкой); «Отступ от контура»
(`edge_margin_m`) сжимает только боковые стороны (`back_boundary`), `row` — ряд решётки от откоса (передний — 0, остаток — на ряд впереди). Конец эшелона
(`back_grid`): ЛСП ≤ W + 3 % — ничего; наклон (`pattern.face_tilts`) — не
больше, чем позволяет разрыв у подошвы до предыдущей, и наименьший до ЛСП ≈ W; иначе остаток
(вертикальный, а если не помещается или его ЛСП > W + 3 % — с наименьшим наклоном), шаг ≥ 1 м и
продвижение по коридору ЛСП последней ≥ 0,4·min(a, b) + `SHADOW_ADVANCE_MARGIN_M`
(1,5 см; проверка «закрыт соседом» — `corridor_blockers` — сравнивает порог с
допуском `SHADOW_ADVANCE_TOLERANCE_M`, обе — `design/toe_line.py`); остаток,
на котором проверка видит разрыв, убирается. Остатка нет или и он > W + 3 % —
последняя сама к откосу до ЛСП ≈ W (`_end_moved`): наклон ≤ 30°, а при
выключенном наклоне или нехватке угла — сдвиг устья вдоль линии столбца (не
ближе отступа к бровке); разрыв у подошвы до неё — до b + 20 %
(`toe_line.END_GAP_TOLERANCE`; решение владельца 09.11.2026, остаток с
недобором — нет). В проверке концевая — последняя в своём коридоре (ЛСП
меряется у неё) у сетки, построенной от тыла (`toe_line._back_layout`: ключ,
квадратная/прямоугольная, тыл есть): сосед впереди в том же столбце — она,
допуск пары + 20 %; по шагу a и наискосок — + 3 %; ключей паспорта нет.
Сдвиг, давший рядом новый брак, откатывается. Схемы первого ряда в шаблоне не действуют. Блок 67 —
`tests/test_block67_back_layout.py`; подробности — `Docs/FRONT_ROWS_TILT.md`,
«Шаблон «от тыла»». Перебор (PR 3) пробует оба шаблона — см. «Перебор
раскладки».

## Монтаж „магистраль + цепочки“ (часть 4а)

Построитель — `design/trunk_network.py` (`plan_trunk_chains`,
`build_trunk_chains_network`), схема `trunk_chains`; вход — через
`build_template_network` и `POST /design/tie/generate` (там же `warnings`).
Контур не нужен: ось ряда — по устьям. Цепочка 42 мс — к ближайшему ряду
впереди со скважиной в 0,75·a по оси (через выключенную; a не определяется —
0,75·b, нет и b — без порога); на шахматке при
равном смещении нечётный ряд берёт левого, чётный — правого, занятый соседкой
предшественник уступает свободному, а если свободного в ряду нет — берётся
занятый со следующей ступенью (42 → 67 мс, у ДШ — следующее реле; следующей
нет — от соседки, взявшей его, наименьшей ступенью: ДШ 10, НСИ 17 мс), не ряд
дальше впереди; времена — рядами спереди назад, и скважина не позже любой
впереди в 0,75·a перепривязывается к самой поздней из них; голова — без предшественника во всех рядах впереди; вруб —
крайняя у фланга голова среди голов не глубже передней + 1,5·b; магистраль
25 мс — по всем головам от вруба к дальнему флангу, головы со стороны фланга
— в обратную сторону. Член столбцов — скважина ряда решётки при любом
виде (`models.is_lattice_hole`), отдельные стеночные ряды (−1…−n, −10) — нет;
стабилизация и сателлиты — только когда это вид основной сетки (`main_kind` =
`pattern_params.default_kind`, передаёт генерация связей). Ручные
скважины, стенки, вставки стабилизации и сателлиты — «прочие» (42 мс от ближайшей
привязанной; стенки — с предупреждением). Ступени — НСИ (у ДШ — реле ДШ, у
электронной — любые от 1 мс), мостов нет; электронный режим тайминга схема
не применяет (предупреждение).
Внутрискважинное замедление одно на блок: у СИНВ — наименьшее из
500/700/1000 мс, строго больше местного запаса — наибольшей разницы
поверхностных времён скважин в радиусе 30 м по устьям («горящий фронт»,
`BURNING_FRONT_RADIUS_M`, `params["burning_front_m"]` не больше 200 м), иначе 1000
и предупреждение; у ДШ и электронной — из поля (`downhole_delay_ms`, иначе
умолчание системы). Предупреждения построения на фронте
(`frontend/src/pages/design/tieWarnings.ts`) видны, пока в документе та же
сеть. Пара у откоса — копия входящей связи своей
вертикальной (срабатывают одновременно). Ось рядов дальше 45° от бровки —
предупреждение «Ряды идут поперёк бровки…» (`rows_across_crest`; азимут
бровки — `params["crest_azimuth_deg"]`, его считает `generate_tie` по
`contour` запроса; нет контура, угловой блок без преобладающего направления
бровки (сосредоточенность < 0,5) или ось рядов не задана самими рядами
(`TrunkPlan.rows_axis` = None) — проверки нет). `trunk_ms`/`chain_ms`/`cut_flank`
в `timing_params` — только у этой схемы. Подробности и сравнение на №66 —
`Docs/TRUNK_CHAINS.md`.

## Перебор раскладки (части 4б и 4в)

Пакет `design/layout_search/`: `space.py` — варианты (`Candidate`, этапы
`stage1`/`stage2`/`stage3`), `evaluate.py` — оценка одного варианта
(`SearchContext.from_design`, `evaluate`, `Evaluation.rank_key`), `search.py`
— `search_layout(ctx, budget_s=150)`. Этап 1 — азимут бровки ±10° шагом 2,5°,
сдвиги вдоль (`grid_shift_along_m`, пишется только когда не 0) и поперёк рядов
четвертями шага, фланг вруба; этап 2 — схема первого ряда для 20 лучших (в семена идут и отбракованные
только превышением ЛСП — `FRONT_ROWS_FIXABLE`);
этап 3 — подстройка вокруг трёх лучших (a и b — только ±3 %; у `variable` и
`domain_dependent` шаги не перебираются). Семена — лучшие с разными сетками.
Этапы 2–3 фланг семени не меняют. Шаблон «от тыла» (`is_back`,
`back_applicable`: square/rectangular, тыл и свободная поверхность) — второй

## Паспорт на бурение (TASK-015)

Формулы `drill-v1` — только `design/drilling_passport.py` (чистые функции):
s = roundup(max(2,0; Hs·(ctg γ − ctg α)), 0,1 м) — округление вверх до
0,1 м; c_min = max(s − e, 0) и W — для инженера, не печатаются. s считается
по проектной высоте уступа Hs (паспорт `bench_height_for_s_m` → объект
`design_bench_height_m` → H₁), W — по фактической высоте каждой скважины
первого ряда; H₁ > Hs + 0,5 — `bench_above_design`. W = H·ctg α + c − d, d —
смещение оси на подошве к бровке (`floor_point`, наклон в массив — минус;
нет бровки — как к откосу, `first_row_tilt_direction_unknown`); скважина

## Нумерация скважин

`design/numbering.py::number_by_position`, зовёт `pattern._finish_pattern`.
Основная сетка — по эшелонам (решение владельца 09.11.2026): эшелон — линия
скважин от бровки вглубь блока (`deep_dir` — продвижение рядов после
`pattern_origin`), эшелоны — с левого фланга, если смотреть с откоса вглубь,
внутри эшелона — от бровки: «1-01» — у бровки на левом фланге. Так у обоих
шаблонов (от бровки и «от тыла»). Эшелон — прямая полоса с допуском 5 см (на
шахматке — через ряд, решение владельца 09.11.2026); ряд вдоль изогнутой бровки
(`first_row_follow_face`) нумеруется по линии ближайшего столбца
(`pattern._face_row_numbering_xy`) — «01» своего эшелона. Стенки и вспомогательные виды (P, K, B, T, SAT, S, I) —
прежняя нумерация по рядам; пара у откоса — номер вертикальной с «T»; ручные
не меняются. Первое число id сетки — эшелон, не ряд: ряд в сечении —
технический `row` (`SectionView.sectionRowKey`).
