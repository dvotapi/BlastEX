# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## Язык общения

Всегда общайся с пользователем на русском языке.

## Справочники экономики (Cost V2)

Поля payload описываются только схемами в `cost/v2/schemas/`: единица
измерения — `x-unit`, ссылка на другой раздел — `x-ref`, короткая подпись
поля — `title`, пояснение — `description`. Новый раздел добавляется схемой,
записью в `SECTION_SCHEMAS` и в `REFERENCE_SECTION_DEFINITIONS`.

Интерфейс строит формы по каталогу схем и не хранит собственных знаний о
полях: не заводи разделоспецифичных компонентов (единственное исключение —
матрица условий бурения) и не показывай пользователю JSON — ни в поле ввода,
ни в подсказке.

## Модель себестоимости блока (TASK-007)

Нормы живут только в `cost/model/`, цены — только в справочниках. Новая
статья вида «цена × существующий драйвер» — это запись в `cost_rules`, а не
код; код нужен лишь для нового типа натуральной величины.

Отсутствующая запись справочника даёт предупреждение и нулевую строку, а не
исключение. Постоянные затраты юнита распределяются по плановому объёму
юнита, постоянные затраты техники — по её плановым сменам; оба плана —
параметры вкладки. Подробности — `Docs/COST_MODEL.md`.

## Модель ФОТ по объектам (TASK-010)

Формулы — `cost/model/payroll.py` (приведённые метры, эффективные смены,
сдельная премия, месячный ФОТ, доля в марже), чтение справочников —
`cost/model/payroll_inputs.py`, превью — `POST /economics/payroll/preview`
(`cost/model/payroll_preview.py`). Премия — только на среднем темпе вахты, не
посменно; НДФЛ в затраты компании не входит; взносы — из ставок организации,
календарь и МРОТ — из «Параметров ФОТ» года. Подробности — `Docs/PAYROLL_MODEL.md`.

## Модель подбора q (Kuz-Ram)

Лист «Расчёт» подбирает q по Каннингему: формулы —
`simulation/fragmentation/cunningham.py`, подбор — `Blast.py::optimize_blast`,
окно «Модель Kuz-Ram» — `frontend/src/pages/calc/kuzram/`.
Прогноз одной точки собирает `cunningham.predict_point` — единственное место,
где формулы складываются вместе. Движок «Проектирования»
(`simulation/fragmentation/engine.py`) зовёт её во всех трёх моделях через
`simulation/fragmentation/base.py::region_point`; прежние формулы —
`simulation/fragmentation/legacy/` под именами `*_legacy`. Настройки модели
«Проектирование» берёт из объекта работ
(`api/services/fragmentation_settings.py`). ML-калибровки кусковатости
хранят базу (модель и версию baseline) и накладываются только на прогноз
той же базы, а пространственная модель считает физику скважин формулами
своей базы (модель другой версии той же формулы — текущей версией, с
просьбой переобучить) — `intelligence/calibration/base.py`; подробности —
`Docs/KUZRAM_MODEL.md`.

## Импорт чертежа маркшейдера (TASK-013)

Окно «Импорт чертежа» (`frontend/src/pages/design/cadImport/`) читает DXF/DWG
целиком и раскладывает сущности по ролям. Чтение и роли —
`design/spatial/cad/`, хранение — таблицы `cad_*`, API — `/design/cad`
(не `/spatial`: это ML-роутер, на проде он выключен). `$INSUNITS` не
масштабирует чертёж: масштаб 0,001 только предлагается по размеру. Шаблон
«имя слоя → роль» хранится на объекте (`site_code`). Контур блока (PR 2) — `design/spatial/cad/` (`rings`,
`stitch`, `contour`, `two_contours`, shapely ≥ 2), предпросмотр —
`POST /design/cad/sources/{id}/contour`; в паспорте — `contour.cad`, ключ
пишется только когда поле есть (иначе сменится хэш утверждённых паспортов).
Кровля (PR 3) — `design/spatial/cad/surface*.py`: CDT через PythonCDT
(запасной путь scipy — `BLASTEX_SURFACE_BUILDER`), предпросмотр —
`POST /design/cad/sources/{id}/surface`. Длина скважины — одна формула
L = (S − Z)/cos α + Δ (`geometry.hole_depth_m`), пересчёт —
`design/hole_recompute.py` и `POST /design/holes/recompute`; `surfaces.top.cad`,
`Hole.manual` и `contour.cad.map_volume_m3` пишутся только когда заданы.
Ситуация и СК (PR 4) — `design/spatial/cad/situation.py`, `crs.py`,
`api/services/cad_situation_service.py`: серии источников по названию, вид
объектов слоя, СК объекта в `cad_site_settings`, в паспорте —
`contour.cad.situation` и `coordinate_system.height_system` (только когда
заданы); на странице — `useSituation`, подложка `SituationCanvas`, группа
«Ситуация» в «Виде». Базовый слой холста окна — `<canvas>` (`CanvasHitIndex`).
Подробности — `Docs/CAD_IMPORT.md`; справка «?» окна обновляется в каждом PR
задачи.

## Темп отбойки (оптимизатор, часть 2)

Темп мс/м (задержка на метр между соседними скважинами, треугольники Делоне
по устьям) — `design/relief.py`: `relief_triangles`, `relief_stats`,
`burden_relief`. Приходит в ответе `POST /design/analyze` как `relief`; на
фронте — слой «Темп отбойки» пресета «Тайминг» (`frontend/src/pages/design/relief.ts`)
и сводка в панели «Тайминг». Ровность для перебора (часть 4): главный
показатель — `outside_share` (доля площади вне ±25 % от медианы), второй —
`robust_spread` (межквартильный размах к медиане); `cv` — справочный.
Порядок оценки: `fast_share` (быстрее нижней границы, 3 мс/м — `RELIEF_MIN_MS_M`)
→ `converging_length_m` (стыки сходящихся фронтов) → `outside_share` →
`robust_spread`. Границы «Темп отбойки от/до» живут в справочнике пород
(`relief_min_ms_m`/`relief_max_ms_m`, `relief_bounds_for_rock`): имя породы
пустое — молча 3 мс/м; порода не найдена — 3 мс/м и предупреждение; справочник
не прочитан — 3 мс/м и предупреждение; верхняя не больше нижней — верхняя
отбрасывается с предупреждением. В сетку темпа входят скважины семейства
сетки, кроме стабилизации и сателлитов, и вид основной сетки
(`pattern_params.default_kind`); пределы — по фактической раскладке
(`relief_limits`): «щепки» (высота < 0,3·s, s — медиана расстояния до
ближайшей соседней) и рёбра длиннее 1,6·max(max(a, b), L) отбрасываются,
как и треугольники с центром вне контура блока. Стык — столкновение породы (долина
времени, вруб по центру), а не встреча фронтов инициирования.
Подробности — `Docs/BURDEN_RELIEF.md`.

## Первый ряд у откоса (часть 3)

Три схемы — `design/pattern.py`, ключ `pattern_params.front_rows_mode`: нет
ключа — вертикальный первый ряд (при `front_rows_tilt_count` > 0 — `taper`);
`pair` — к скважине ранга 1 с ЛСП > W + 3 % добавляется `face_toe` («Наклонная
у откоса», номер `<id>T`) на 1 м ближе к откосу (`_face_pairs`); `taper` — 1–2
ряда перехода (α₁, α₁/2), один угол на участок ряда, ранг по столбцу, шаг b
у подошвы, устья соседних рангов не ближе 1 м (`_taper_front_rows`,
`taper_tan_limit`), шахматке не применяется. Все сдвиги и наклоны — вдоль
линии столбца к откосу (столбцы на одной линии — обязательно). Угол — не
больше `front_rows_tilt_deg` (≤ 30°, умолчание 15°) и ЛСП не меньше
max(0,8·W, 1 м) — по построенной скважине (`_verified_angles`: у скачка
съёмка ↔ развал оценка не годится). `min_crest_offset_m` (умолчание 1 м) — отступ устья от
кромки. Пара закрывает только свою вертикальную, в темп отбойки не входит.
Проверки `validate`: `floor_burden_short`/`_excess`, `floor_beyond_toe`,
`floor_row_gap_excess` (у подошвы шаг + 3 %), `collar_too_close_to_crest`
(только при ключах отступа или схемы). Ключи пишутся только когда заданы
(иначе сменится хэш утверждённых паспортов). Подробности и проверка на №66 —
`Docs/FRONT_ROWS_TILT.md`.

## Монтаж „магистраль + цепочки“ (часть 4а)

Построитель — `design/trunk_network.py` (`plan_trunk_chains`,
`build_trunk_chains_network`), схема `trunk_chains`; вход — через
`build_template_network` и `POST /design/tie/generate` (там же `warnings`).
Контур не нужен: ось ряда — по устьям. Цепочка 42 мс — к ближайшему ряду
впереди со скважиной в 0,75·a по оси (через выключенную; a не определяется —
0,75·b, нет и b — без порога); на шахматке при
равном смещении нечётный ряд берёт левого, чётный — правого, занятый соседкой
предшественник уступает свободному, а если свободного в ряду нет — берётся
занятый со следующей ступенью (42 → 67 мс, у ДШ — следующее реле), не ряд
дальше впереди; голова — без предшественника во всех рядах впереди; вруб —
крайняя у фланга голова среди голов не глубже передней + 1,5·b; магистраль
25 мс — по всем головам от вруба к дальнему флангу, головы со стороны фланга
— в обратную сторону. Ручные
скважины, стенки, стабилизация, сателлиты — «прочие» (42 мс от ближайшей
привязанной; стенки — с предупреждением). Ступени — НСИ (у ДШ — реле ДШ, у
электронной — любые от 1 мс), мостов нет; электронный режим тайминга схема
не применяет (предупреждение).
Внутрискважинное замедление одно на блок: у СИНВ — наименьшее из
500/700/1000 мс, строго больше наибольшего поверхностного времени, иначе 1000
и предупреждение; у ДШ и электронной — из поля (`downhole_delay_ms`, иначе
умолчание системы). Предупреждения построения на фронте
(`frontend/src/pages/design/tieWarnings.ts`) видны, пока в документе та же
сеть. Пара у откоса — копия входящей связи своей
вертикальной (срабатывают одновременно). `trunk_ms`/`chain_ms`/`cut_flank`
в `timing_params` — только у этой схемы. Подробности и сравнение на №66 —
`Docs/TRUNK_CHAINS.md`.

## Перебор раскладки (части 4б и 4в)

Пакет `design/layout_search/`: `space.py` — варианты (`Candidate`, этапы
`stage1`/`stage2`/`stage3`), `evaluate.py` — оценка одного варианта
(`SearchContext.from_design`, `evaluate`, `Evaluation.rank_key`), `search.py`
— `search_layout(ctx, budget_s=150)`. Этап 1 — азимут бровки ±10° шагом 2,5°,
сдвиги вдоль (`grid_shift_along_m`, пишется только когда не 0) и поперёк рядов
четвертями шага, фланг вруба; этап 2 — схема первого ряда для 20 лучших;
этап 3 — подстройка вокруг трёх лучших (a и b — только ±3 %; у `variable` и
`domain_dependent` шаги не перебираются). Семена — лучшие с разными сетками.
Этапы 2–3 фланг семени не меняют. Монтаж — «магистраль + цепочки», система —
как в базовой сети; контурный ряд — если база монтирует контурную скважину
(`wired_wall_holes`) или `default_kind` = contour (пресплит и оконтуривание —
всегда); у ДШ и электронной замедление в скважине — из базовой сети
(`base_downhole_ms`). Отбраковка —
коды `validate` (`floor_beyond_toe`, `floor_row_gap_excess`,
`collar_too_close_to_crest`), но за один проход `floor_checks` плюс
`collar_crest_warnings(force=True)`, без полного `validate` (равенство кодов
при заданном отступе держит тест), на скважинах варианта с шагами a/b базы
(`with_base_steps`: разрыв у подошвы — от исходной сетки, как W₀); отступ
устья от кромки перебор проверяет всегда (без ключа — 1 м), `validate` —
только при ключах. Ранжирование:
отбраковка → ЛСП вне `[0,8·W₀; 1,03·W₀]` (W₀ — база) → `fast_share` → стыки →
`outside_share` → `robust_spread` (без темпа — `inf`); доли и разброс до
0,01, стыки до 0,5 м; окно 8 мс (разница ≤ 8 мс, как у МИС) и замедление
только показываются; бюджет, кончившийся в этапе 1, — предупреждение «Блок
большой». В `best` —
только прошедшие (отбракованные — лишь когда прошедших нет), с разными
сетками. Ручные скважины перебор не использует. Проверка на №66 — медленный
тест под `BLASTEX_SLOW=1`.

Фон и экран (4в): `design/layout_search/jobs.py` — реестр `LayoutSearchJobs`
в памяти процесса API, перебор в дочернем процессе (`spawn`), на весь сервер
один подбор (второй — 409), страховка `budget_s + 60` с → `failed` (без
карточек прошлого итога). Запуск — только для сохранённого паспорта
организации (иначе 404), в дочерний процесс — лишь поля перебора
(`LAYOUT_SEARCH_FIELDS` и контурные скважины, которые монтирует базовая
сеть, — `wired_wall_holes`); `design.design_id`, если задан, равен `design_id`
запроса (иначе 400); паспорт удалён во время подбора — итог не пишется. API —
`POST /design/layout-search`, `GET /design/layout-search/{design_id}`,
`POST …/{design_id}/stop`, без `require_human` (паспорт не меняется). Итог —
`data/teams/{team}/designs/layout_search/{design_id}.json` (свой каталог, не
суффикс к паспорту), с отпечатком входа, который считает фронт (контур,
поверхности, домены, `pattern_params`, порода, система инициирования и
связанные базовой сетью контурные скважины; пока пересчитывается — null) — по
нему «Устарел»; с границами темпа запуска и породой — статус сверяет их со
справочником (`bounds_changed`). Фронт —
`useLayoutSearch` (опрос раз в секунду), `LayoutSearchPanel` (карточки, вне
`fieldset` вкладки), `useLayoutSearchApply`: «Применить» — одно действие
`APPLY_LAYOUT` (скважины, сеть, `pattern_params`, один шаг отмены; отмена —
документ как был, формы берутся из него; параметры узнаются по значению),
«Коммутация» — «Магистраль +
цепочки» с флангом варианта. Подробности —
`Docs/LAYOUT_SEARCH.md`.

## Интерфейс

Streamlit удалён: UI — только `frontend/` (React + TypeScript). Расчётные
модули не знают об интерфейсе; всё, что нужно фронту, проходит через
`api/`.

Справочники Cost V1 (породы, ВМ, станки, объекты, номенклатура, постоянные
расходы, должности) читаются из опубликованной ревизии V2 через
`cost/v2/legacy_adapter.py`; файловых справочников нет. Каталог `data/teams`
хранит только паспорта проектирования и артефакты ML.
