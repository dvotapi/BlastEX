# Темп отбойки (мс/м)

Темп отбойки показывает, сколько миллисекунд проходит между срабатыванием
соседних скважин на каждый метр расстояния между ними. Ровный темп по блоку
означает, что порода отрывается равномерно, без «зажатых» и «пустых» участков.
Это первая метрика оптимизатора раскладки блока: часть 4 (перебор схем)
будет сравнивать варианты именно по ней.

## Определение

Определение взято из модуля «Initiation analysis» Datamine DataBlast Pro
(relief — задержка в мс на метр кажущегося сопротивления, считается по
треугольникам между скважинами; цель — постоянный темп):
https://docs.dataminesoftware.com/DataBlast/Pro/2.14/H-Initiation-Module/Initiation-Analysis.htm

Формула ShotPlus не опубликована, поэтому мы не копируем её, а берём
определение Datamine.

Решение: в расчёт берётся точка устья скважины (как и в изолиниях тайминга).
Datamine при показе траекторий скважин использует точку забоя; если для
наклонных скважин (1–2 ряда, часть 3) понадобится забой, это переключается
по запросу владельца.

## Как считается

Код — `design/relief.py`.

1. Берутся устья включённых скважин сетки, у которых есть время срабатывания.
2. По ним строится триангуляция Делоне.
3. Рёбра длиннее `RELIEF_EDGE_FACTOR · max(a, b)` отбрасываются
   (`RELIEF_EDGE_FACTOR = 1,6`; a и b — шаг между скважинами в ряду (a)
   и между рядами (b)). Так треугольники не «перекидываются» через
   вогнутость контура и пустоты, где скважин нет.
4. По трём временам треугольника строится плоскость t = αx + βy + γ.
   Темп треугольника — длина градиента, |∇t| = √(α² + β²), мс/м. Это
   скорость нарастания времени в направлении, где оно растёт быстрее всего,
   то есть темп по кратчайшему пути между «ранней» и «поздней» сторонами.
5. Вырожденные треугольники (площадь меньше 10⁻⁶ м²) пропускаются.

Если скважин меньше трёх, они лежат на одной прямой или все рёбра
отбракованы, темпа нет (`relief = null`).

## Показатели ровности

Все показатели взвешены по площади треугольников: мелкий треугольник у
края не должен весить как крупный в центре.

- **Медиана** (`median_ms_m`) — типичный темп блока.
- **Среднее, минимум, максимум** — `mean_ms_m`, `min_ms_m`, `max_ms_m`.
- **Доля вне коридора** (`outside_share`) — **главный показатель ровности**
  (решение владельца 21.10.2026): доля площади блока, где темп отличается от
  медианы больше чем на 25 % (`RELIEF_CORRIDOR = 0,25`). Ограничена 0…1,
  совпадает с картой: это площадь всех зон, кроме «ровно» и умеренных.
- **Устойчивый разброс** (`robust_spread`) — второй показатель: межквартильный
  размах по площади к медиане, (P75 − P25) / медиана. Показывает, насколько
  неровен основной массив треугольников; единичные выбросы на малой площади
  его не сдвигают. При медиане 0 не определён. Неровность на хвостах меньше
  четверти площади с каждой стороны он не видит — её ловит `outside_share`,
  поэтому тот и главный.
- **Быстрее нижней границы** (`fast_share`) и **медленнее верхней**
  (`slow_share`) — доли площади за границами рабочего диапазона, см. ниже.
- **Стыки фронтов** (`converging_length_m`) — суммарная длина, м, см. ниже.
- **`cv`** (σ / среднее) — справочный, в панели не показывается: несколько
  треугольников с очень большим темпом поднимают его сильно, поэтому порядок
  вариантов по `cv` задавала бы длина хвоста в одном месте, а не ровность блока.

Порядок оценки вариантов в переборе (часть 4), без округления (`ReliefStats`):
`fast_share` → `converging_length_m` → `outside_share` → `robust_spread`.
Сначала отсекается зажатая порода, затем стыки фронтов, затем неровность.
Вариант с `robust_spread = None` (медиана 0 — больше половины площади
срабатывает одновременно) идёт последним.

Если медиана равна 0 (больше половины площади срабатывает одновременно),
коридор не определён: «вне коридора» считается всё, где темп больше нуля.

## Рабочий диапазон и нижняя граница

Нижняя граница по умолчанию — 3 мс/м (`RELIEF_MIN_MS_M`). Смысл: если задержка
на метр слишком мала, соседние скважины срабатывают почти одновременно, порода
оказывается зажатой, и дробление ухудшается; в литературе ниже примерно
1–3 мс/м качество дробления падает. Участки быстрее границы — `fast_share`;
на плане они заштрихованы тёмно-синим.

Верхней границы по умолчанию нет: стандарт объекта (НСИ 25 мс / 42 мс) даёт
около 12–13 мс/м, и общего значения «слишком медленно» нет. Верхняя граница
включается, только если задана для породы; тогда в панели появляется строка
«Медленнее … мс/м» (`slow_share`).

Где задаётся: справочник пород, поля «Темп отбойки от» и «до» (мс/м) —
`relief_min_ms_m` / `relief_max_ms_m` (`cost/v2/schemas/misc.py`). Маршрут
анализа находит породу по `design.rock_name` (без учёта регистра и пробелов по
краям, `api/services/design_service.py::relief_bounds_for_rock`):

- имя породы пустое — молча 3 мс/м, справочник не читается;
- имя задано, но такой породы в справочнике нет — 3 мс/м и предупреждение в
  тайминге «Порода «…» не найдена в справочнике…»;
- справочник не прочитан (сбой хранилища) — 3 мс/м и предупреждение
  «Диапазон темпа для породы не прочитан…».

Собственные цифры из результатов взрывов (по какому темпу порода дробилась
хорошо) — отдельная задача: их надо собрать по факту и внести в справочник.

## Сходящиеся фронты

Здесь важно не путать два направления:

- **Фронт инициирования** — порядок, в котором зажигаются скважины: идёт от
  ранних к поздним, по росту времени t.
- **Движение породы** — куда сдвигается порода: к уже сработавшим скважинам,
  то есть навстречу фронту инициирования, m = −∇t / |∇t|.

Стык — общее ребро двух соседних треугольников, к которому порода движется с
обеих сторон: массивы сталкиваются. По времени это «долина»: ребро сработало
раньше обеих сторон. Для нормали n ребра (от первого треугольника ко второму)
стык есть, когда обе стороны подходят к ребру под углом больше 10°
(`CONVERGING_MIN_APPROACH_DEG`): m₁·n > sin 10°, m₂·n < −sin 10°. Треугольники
с нулевым темпом не учитываются. Длина стыков — `converging_length_m`; на плане
это красные линии 3 px.

Вруб по центру блока всегда даёт стык: линия вруба срабатывает первой, обе
половины движутся к ней и сталкиваются. Вруб с фланга стыка не даёт — порода
всего блока движется в одну сторону.

Встреча фронтов инициирования — «хребет» по времени: фланги зажигаются
первыми, середина последней (так «Трапецеидальная» ведёт себя на
прямоугольнике). Порода по обе стороны такого ребра расходится, и стыком это
не считается.

Стыки — минус при оценке схемы, а не запрет: перебор их штрафует, но схему не
отбрасывает.

Решение владельца 21.10.2026: минусом считается именно столкновение породы (как считает код); встреча фронтов инициирования минусом не считается.

## Где это видно

- API: `POST /design/analyze` возвращает поле `relief`
  (`api/schemas/design.py`, `BurdenReliefSchema`): список треугольников и
  сводку `stats`. Числа округляются в `to_dict`, расчёт идёт без округления;
  флаг треугольника `fast` (быстрее нижней границы) ставится по точному темпу,
  как `fast_share`, и по нему фронт штрихует план.
- Фронт: `frontend/src/pages/design/relief.ts` — зоны по отклонению от
  медианы: ±10 % — «ровно», ±25 % — умеренное отклонение, дальше — «заметно»
  и «намного» быстрее или медленнее. Слой «Темп отбойки» входит в пресет
  «Тайминг»; сводка — в панели «Тайминг»: «Быстрее 3 мс/м», «Медленнее … мс/м» (только
  при верхней границе), «Стыки фронтов», «Вне коридора ±25 %», «Устойчивый
  разброс». Быстрые треугольники заштрихованы тёмно-синим, стыки — красные линии.
- Особые случаи сводки: максимум 0 — «Все скважины срабатывают
  одновременно»; медиана 0 при максимуме больше 0 — «Больше половины
  площади срабатывает одновременно».

## Блок №66

Проверка на тестовом стенде: чертёж `tests/fixtures/cad/block66.dxf`,
импортирован через «Импорт чертежа», блок построен по контуру «блок 66 вар 2».
Прямоугольная сетка 4,41 × 3,53 м, азимут рядов 0, 157 скважин, НСИ 25 мс,
замедление в скважине 500 мс.

| Схема | Медиана, мс/м | Вне коридора ±25 % | Устойчивый разброс | `cv` (справочно) |
|---|---|---|---|---|
| «Порядная» | 7,1 | 0 % | 0 % | 0 % |
| «Клиновая» | 5,7 | 5 % площади | 0 % | 55 % |

- «Порядная»: весь ряд срабатывает одновременно, ряды идут через 25 мс, поэтому
  темп везде равен 25 / 3,53 м = 7,1 мс/м. Карта однотонная.
- «Клиновая»: на прямой части карта зелёная («ровно»), а у мыса (юго-восток),
  где диагонали клина встречаются с развёрнутой бровкой, появляется красная
  зона «намного медленнее». При этом `cv` = 55 %, хотя вне коридора всего 5 % площади, а
  устойчивый разброс 0 %: основной массив ровный, `cv` раздувают несколько
  треугольников у мыса. Этот пример и привёл к выбору `outside_share` главным
  показателем.
- Оговорка к «Клиновой»: медиана 5,7 ≈ 25 / 4,41 м — на №66 схема по факту
  поджигает поперечные столбцы по очереди, а не диагональ. Идеальный клин на
  этой сетке дал бы √((25/4,41)² + (25/3,53)²) ≈ 9,1 мс/м. Это поведение
  генератора тайминга на этом блоке (проверить отдельно), а не метрики темпа;
  красная зона у мыса от этого не зависит.

Часть 2b, тот же блок, породы в справочнике нет (нижняя граница 3 мс/м):

| Схема | Медиана, мс/м | Быстрее 3 мс/м | Стыки фронтов | Вне коридора | Устойчивый разброс |
|---|---|---|---|---|---|
| «Порядная» | 7,1 | 0 % | нет | 0 % | 0 % |
| «Клиновая» | 5,7 | 0 % | нет | 5 % | 0 % |
| «Диагональная V» | 15,3 | 0 % | 32,8 м | 45 % | 63 % |
| «Трапецеидальная» | 5,7 | 0 % | 5,7 м | 45 % | 169 % |

- У «Диагональной V» стык идёт поперёк блока по линии вруба: линия вруба
  срабатывает первой, порода обеих половин движется к ней и сталкивается. Это согласуется с предпочтением владельца —
  вруб с фланга, а не по центру.
- Красная зона у мыса «Клиновой» — медленная зона, а не стык.
- У «Трапецеидальной» 5,7 м — одно диагональное ребро у мыса: там неровный
  контур дал местную «долину» времени. Сама встреча фронтов инициирования в
  середине блока (фланги раньше, центр позже) стыком не считается — порода там
  расходится; на прямоугольнике та же схема даёт 0 м.
