# Темп отбойки (мс/м)

Темп отбойки показывает, сколько миллисекунд проходит между срабатыванием
соседних скважин на каждый метр расстояния между ними. Ровный темп по блоку
означает, что порода отрывается равномерно, без «зажатых» и «пустых» участков.
Это первая метрика оптимизатора раскладки блока: часть 4 (перебор схем)
будет сравнивать варианты именно по ней.

## Определение

Определение взято из модуля «Initiation analysis» Datamine DataBlast Pro
(relief — задержка в мс на метр кажущегося сопротивления, считается по
треугольникам между скважинами; цель — постоянный темп):
https://docs.dataminesoftware.com/DataBlast/Pro/2.14/H-Initiation-Module/Initiation-Analysis.htm

Формула ShotPlus не опубликована, поэтому мы не копируем её, а берём
определение Datamine.

Решение: в расчёт берётся точка устья скважины (как и в изолиниях тайминга).
Datamine при показе траекторий скважин использует точку забоя; если для
наклонных скважин (1–2 ряда, часть 3) понадобится забой, это переключается
по запросу владельца.

## Как считается

Код — `design/relief.py`.

1. Берутся устья включённых скважин сетки, у которых есть время срабатывания.
2. По ним строится триангуляция Делоне.
3. Рёбра длиннее `RELIEF_EDGE_FACTOR · max(a, b)` отбрасываются
   (`RELIEF_EDGE_FACTOR = 1,6`; a и b — шаг между скважинами в ряду (a)
   и между рядами (b)). Так треугольники не «перекидываются» через
   вогнутость контура и пустоты, где скважин нет.
4. По трём временам треугольника строится плоскость t = αx + βy + γ.
   Темп треугольника — длина градиента, |∇t| = √(α² + β²), мс/м. Это
   скорость нарастания времени в направлении, где оно растёт быстрее всего,
   то есть темп по кратчайшему пути между «ранней» и «поздней» сторонами.
5. Вырожденные треугольники (площадь меньше 10⁻⁶ м²) пропускаются.

Если скважин меньше трёх, они лежат на одной прямой или все рёбра
отбракованы, темпа нет (`relief = null`).

## Показатели ровности

Все показатели взвешены по площади треугольников: мелкий треугольник у
края не должен весить как крупный в центре.

- **Медиана** (`median_ms_m`) — типичный темп блока.
- **Среднее, минимум, максимум** — `mean_ms_m`, `min_ms_m`, `max_ms_m`.
- **Разброс `cv`** — стандартное отклонение, делённое на среднее. 0 означает
  идеально ровный темп. Чувствителен к выбросам: несколько треугольников с
  очень большим значением поднимают `cv` сильно.
- **Доля вне коридора** (`outside_share`) — доля площади блока, где темп
  отличается от медианы больше чем на 25 % (`RELIEF_CORRIDOR = 0,25`).
  Показывает, насколько большая часть блока затронута отклонениями.

Читать вместе: высокий `cv` при малой доле вне коридора — несколько
треугольников с очень большим темпом на небольшой площади; высокий `cv` при
большой доле — неровный темп по всему блоку. Оптимизатор (часть 4) должен
использовать оба показателя: `ReliefStats.cv` и `ReliefStats.outside_share`.

Если медиана равна 0 (больше половины площади срабатывает одновременно),
коридор не определён: «вне коридора» считается всё, где темп больше нуля.

## Где это видно

- API: `POST /design/analyze` возвращает поле `relief`
  (`api/schemas/design.py`, `BurdenReliefSchema`): список треугольников и
  сводку `stats`. Числа округляются в `to_dict`, расчёт идёт без округления.
- Фронт: `frontend/src/pages/design/relief.ts` — зоны по отклонению от
  медианы: ±10 % — «ровно», ±25 % — умеренное отклонение, дальше — «заметно»
  и «намного» быстрее или медленнее. Слой «Темп отбойки» входит в пресет
  «Тайминг»; сводка (медиана, разброс, доля вне коридора) — в панели
  «Тайминг».
- Особые случаи сводки: максимум 0 — «Все скважины срабатывают
  одновременно»; медиана 0 при максимуме больше 0 — «Больше половины
  площади срабатывает одновременно».

## Блок №66

Проверка на тестовом стенде: чертёж `tests/fixtures/cad/block66.dxf`,
импортирован через «Импорт чертежа», блок построен по контуру «блок 66 вар 2».
Прямоугольная сетка 4,41 × 3,53 м, азимут рядов 0, 157 скважин, НСИ 25 мс,
замедление в скважине 500 мс.

| Схема | Медиана, мс/м | Разброс `cv` | Вне коридора ±25 % |
|---|---|---|---|
| «Порядная» | 7,1 | 0 % | 0 % |
| «Клиновая» | 5,7 | 55 % | 5 % площади |

- «Порядная»: весь ряд срабатывает одновременно, ряды идут через 25 мс, поэтому
  темп везде равен 25 / 3,53 м = 7,1 мс/м. Карта однотонная.
- «Клиновая»: на прямой части карта зелёная («ровно»), а у мыса (юго-восток),
  где диагонали клина встречаются с развёрнутой бровкой, появляется красная
  зона «намного медленнее». Высокий `cv` при доле вне коридора всего 5 %
  говорит о нескольких треугольниках с очень большим значением: `cv`
  чувствителен к выбросам, а доля показывает, сколько площади реально
  затронуто. Поэтому перебор схем должен смотреть на оба показателя.
- Оговорка к «Клиновой»: медиана 5,7 ≈ 25 / 4,41 м — на №66 схема по факту
  поджигает поперечные столбцы по очереди, а не диагональ. Идеальный клин на
  этой сетке дал бы √((25/4,41)² + (25/3,53)²) ≈ 9,1 мс/м. Это поведение
  генератора тайминга на этом блоке (проверить отдельно), а не метрики темпа;
  красная зона у мыса от этого не зависит.
