# Модель себестоимости блока (`cost/model/`)

Слой норм между техническим расчётом БВР и экономикой Cost V2. Принцип
один: **нормы — в коде, цены — в справочниках**. Код считает натуральные
величины по инженерным формулам, справочники умножают их на ставки,
надбавки применяются отдельным шагом.

## Граница «норма / цена»

| Что | Где живёт | Пример |
| --- | --- | --- |
| Нелинейная формула, дающая натуральную величину | `cost/model/` | смены станка = погонаж / коммерческую скорость |
| Параметр формулы | справочник | техническая скорость 12 м/ч, ресурс коронки 700 м |
| Цена за единицу драйвера | `cost_rules`, `material_prices`, `labor_rates`, `subcontract_rates` | 46 ₽/кг гранулита |
| Ставки и надбавки организации | `organization_rates` | взносы 30 %, ОХР 10 %, НДС 20 % |
| Параметр моделирования | вкладка «Экономика» | плановый объём юнита, смены станка, состав бригады |

Новая статья вида «цена × существующий драйвер» — это запись в
`cost_rules`, а не код. Код нужен только для **нового типа натуральной
величины**.

## Что откуда берётся

```
технический паспорт (physical + lineage)
        ↓
cost/model: drilling → logistics → labor → equipment → cost_rules → unit
        ↓
строки CostLine по слоям variable → project_direct → production → full
        ↓
markup: ОХР → рентабельность → НДС
        ↓
четыре цены м³: marginal, full, with_margin, with_vat
```

Порядок модулей важен: смены станка и СЗМ выводятся первыми, потому что от
них зависят человеко-смены бригады и затраты техники.

## Натуральные величины

| Величина | Формула | Модуль |
| --- | --- | --- |
| `v_commercial_m_per_shift` | `tech_speed × (shift_hours − unproductive_h)` | `drilling` |
| `rig_shifts` | `drilling_m / v_commercial` | `drilling` |
| `rig_maintenance_shifts` | `rig_shifts × maintenance_ratio` | `drilling` |
| `rig_plan_metres` | `rig_plan_shifts × v_commercial` | `drilling` |
| `szm_trips`, `szm_shifts` | `⌈bulk_kg / грузоподъёмность⌉`, один рейс — одна смена | `logistics` |
| `delivery_trips`, `delivery_shifts` | то же по патронам | `logistics` |
| `vm_tkm` | `cartridge_kg / 1000 × расстояние от склада` | `logistics` |
| `component_tkm` | `bulk_kg / 1000 × расстояние от базы` | `logistics` |
| `mobilization_trip_km` | `плечо × 2 / блоков на мобилизацию` | `logistics` |
| `crew_shifts.<должность>` | ручная поправка → смены техники → `норм_смен / норм_операций` | `labor` |
| `crew_headcount.<должность>` | `⌈плановые смены техники / норм_смен человека⌉` | `labor` |
| `warehouse_area_m2` | `⌈max(потребность месяца / ёмкость на м²)⌉` | `unit` |
| `unit_allocation_share` | `объём блока / плановый объём юнита` | `unit` |

У каждой величины есть `lineage` — строка, объясняющая, откуда она взялась:
именно её видит пользователь рядом с числом.

## Слои себестоимости

- `variable` — растёт вместе с объёмом: ВМ, оснастка, ДТ, запчасти.
- `project_direct` — прямые затраты блока: ФОТ со взносами, амортизация и
  ТОиР техники по сменам, мобилизация.
- `production` — постоянные затраты юнита, распределённые по плановому
  объёму: косвенный персонал, база, аренда склада ВМ.
- `full` — то, что на блок не распределяется: например, постоянные затраты
  собственного станка при бурении на субподряде.

Итоги накопительные: `full` включает все предыдущие слои. Маржинальная цена
считается по `project_direct`, полная — по `full`.

## Распределение постоянных затрат

База — **плановый объём юнита**, параметр вкладки, а не справочник. Только
он показывает, как доля постоянных затрат в цене м³ падает с ростом
загрузки: при плане 400 000 м³ вместо 600 000 полная цена растёт, а
маржинальная не меняется.

Постоянные затраты техники распределяются по её **плановым сменам**: при 25
сменах станка вместо 40 постоянная часть метра растёт на 60 %, а численность
экипажа падает с трёх до двух.

## Склад ВМ

Аренда склада — не константа на блок, а ресурсный пул с ёмкостью:
`resource_kind = STORAGE_AREA`, `consumption_norms` вида
`{"driver": "downhole_nsi", "units_per_capacity": 300}`. Требуемая площадь
считается по месячному плану юнита; превышение базовой ёмкости добавляет
ступени аренды и предупреждение с требуемой площадью.

## Отсутствующие данные

Незаполненная запись справочника — не исключение, а предупреждение и нулевая
строка. Список предупреждений возвращается вместе с результатом и
показывается на вкладке: сметчик должен увидеть незаполненное место, а не
ошибку 500.

## Хранение и сравнение

Каждый прогон сохраняется в `blastex.economics_runs` целиком: паспорт,
пакет, ревизия справочников, параметры и результат. Сравнение сценариев идёт
между снимками, поэтому старый расчёт воспроизводим спустя месяцы, даже если
справочники изменились.
