# Модель Kuz-Ram для подбора удельного расхода

Лист «Расчёт» подбирает для каждой коронки наименьший удельный расход q
(кг/м³), при котором доля кусков крупнее кондиционного (негабарит) не
превышает допустимую. Прогноз дробления — модель Kuz-Ram по Каннингему:
C. V. B. Cunningham, «The Kuz-Ram fragmentation model — 20 years on»,
EFEE 2005.

## Какие уравнения статьи использованы

Код использует не весь набор формул статьи, а конкретный выбор:

- **A** (фактор породы) — уравнения (4)–(7): A = 0,06·(RMD + RDI + HF)·C(A).
- **x50** (средний кусок) — уравнение (1), без поправки на замедление A_T:
  данных о точности замедления в модели нет. Сила ВВ — как в статье,
  (115/RWS)^e, где RWS — массовая сила относительно ANFO, % (115 — тротил в
  той же шкале).
- **n** (индекс равномерности) — уравнение (3), вариант 1987 года (в коде —
  `n = (2,2 − 14·W/d) · √((1 + a/W)/2) · (1 − σ/W) · 1,1^0,1 · (L/H) · C(n)`,
  см. раздел «Дробление» ниже), **а не** уравнение (14) редакции 2005 года
  (n = n_s·√(2 − 30·B/d)·√((1 + S/B)/2)·(1 − W/B)·(L/H)^0,3·C(n), где W у
  Каннингема в этом уравнении — отклонение бурения, а не ЛНС).

Почему уравнение (3), а не (14) — решение владельца от 21.09.2026: на
габбро-диабазе (коронка 152 мм) уравнение (3) давало q ≈ 1,26 кг/м³, близко к
практике объекта; уравнение (14) на тех же входных даёт около 1,6–2,0 кг/м³.
После перевода силы ВВ на шкалу ANFO (решение владельца от 02.10.2026, версия
`kuzram-cunningham-1.1`) тот же пример даёт q = 1,33 кг/м³.
**Менять формулу n на (14) без отдельного согласования с владельцем нельзя**:
подбор q сдвинется на всех объектах, а не только на новых.

Поле разбора `burden_to_diameter` (B/d — ЛНС к диаметру скважины, обе
величины в метрах) — справочное: статья рекомендует B/d в диапазоне 25–35, но
подбор q это поле не проверяет и не ограничивает.

Код: `simulation/fragmentation/cunningham.py` (формулы) и
`Blast.py::BlastEngine.optimize_blast` (подбор). Версия модели —
`kuzram-cunningham-1.1`. Контрольный пример с ручным A = 8
(`tests/test_kuzram_control_example.py`) сверяет x50, n и негабарит с ручным
расчётом по статье с допуском 0,5 %.

## Геометрия скважины

```
d  = коронка/1000 · коэф. разбуривания              [м]
L  = 0,8 · (H + перебур)                             [м] длина заряда
Q  = π·d²/4 · ρВВ·1000 · L                           [кг]
V  = Q / q;  W = √(V / (a/W · H));  a = a/W · W;  b = W
RWS = 100 · теплота взрыва / 3,8                     сила ВВ к ANFO, %
```

## Дробление

```
RDI = 25·ρ − 50                  HF = UCS/5
A   = 0,06·(RMD + RDI + HF)·C(A)
x50 = A · q^−0,8 · Q^(1/6) · (115/RWS)^e · 10        [мм], e = 19/20 (или 19/30)
n   = (2,2 − 14·W/d_мм) · √((1 + a/W)/2) · (1 − σ/W) · 1,1^0,1 · min(1, L/H) · C(n)
xc  = x50 / (ln 2)^(1/n)
негабарит = exp(−(кусок/xc)^n) · 100 %
```

RMD — описание массива: 50 — монолитный, 10 — рыхлый. Для трещиноватого
массива вместо RMD берётся JF = JCF·JPS + JPA: шаг трещин s = 1/трещиноватость,
приведённая сетка P = √(a·b); JPS = 10 при s < 0,1 м, 20 при s < 0,3 м,
80 при s < 0,95·P, иначе 50. HF = UCS/5, потому что модуля упругости в
данных нет. n ниже 0,1 принимается равным 0,1.

Диаметр скважины в формуле n — в миллиметрах, от 20 до 2000 мм; другое
значение, NaN или бесконечность формула отвергает с ошибкой. Сама формула к
единицам безразлична: диаметр в метрах (0,1–0,3) молча уводил n в нижнюю
границу (закрытый PR #82), поэтому проверка стоит в формуле, а не у
вызывающих. API проверяет раньше, на входе: коронка — от 20 до 1000 мм, иначе
422 с указанием поля (`crown_diameters_mm[i]` или `facts[i].crown_mm`). С
коэффициентом разбуривания 1–1,5 такая коронка всегда даёт скважину в
границах формулы.

## Подбор q

q перебирается от 0,10 до верхней границы (по умолчанию 2,0) с шагом 0,01;
берётся первое значение, при котором негабарит не больше допустимого. Если
такого нет, возвращается расчёт на верхней границе с признаком «порог не
достигнут».

## Настройки

| Настройка | Умолчание | Границы |
|---|---|---|
| Способ A | монолитный массив (RMD 50) | RMD 10, JF, вручную (0,5–30) |
| C(A) | 1,0 | 0,1–10 |
| Показатель при силе ВВ | 19/20 | 19/30 |
| σ, м | 0 | 0–2 |
| C(n) | 1,0 | 0,5–2 |
| Верхняя граница q, кг/м³ | 2,0 | 0,5–5 |

Без достоверных данных о трещиноватости и ориентации трещин оставляйте
монолитный массив и уточняйте C(A) по фактическим взрывам:
`POST /api/v1/blast/kuzram/calibrate` ищет C(A), при котором модель при
фактическом q даёт фактический негабарит (бисекция по ln C(A) на 0,1–10),
и усредняет решённые строки геометрически.

## Что считалось раньше

До сентября 2026 года подбор использовал A = 0,12·(UCS/20 + 2,5ρ + 7),
показатель 19/30, силу ВВ к тротилу (теплота / 4,184) и индекс n с диаметром
в метрах — из-за этого n всегда упирался в 0,8. Ошибки почти компенсировали
друг друга: для монолитного массива прежний и новый q близки (габбро-диабаз,
152 мм: 1,34 и 1,33 кг/м³).

До 02.10.2026 и Kuz-Ram по Каннингему брал силу ВВ к тротилу, RE^(−e) с
RE = теплота / 4,184 (версия `kuzram-cunningham-1.0`, модели движка 2.0.0).
Это занижало x50 примерно на 4 % против статьи: для эмульсии 2,99 МДж/кг
множитель 1,376 вместо 1,434. Тротиловую RE теперь показывает только расчёт
«до исправления» (поле `re_weight`); Каннингем отдаёт `rws_anfo_pct`. Прежний расчёт сохранён как
`BlastEngine.optimize_blast_legacy` и отдаётся в блоке `legacy` ответа
`/blast/optimize` на переходный период.

Прогноз дробления на вкладке «Проектирование» и в отчётах считает движок
`simulation/fragmentation/` на той же `predict_point`, а прежние формулы
лежат в `simulation/fragmentation/legacy/`. Базис ML-калибровки до PR 3
остаётся на старой модели `kuzram_legacy`. Подробности — в разделе
«Проектирование: движок кусковатости» ниже.

## Окно на листе «Расчёт»

Кнопка «Модель Kuz-Ram» в панели «Варианты сетки» открывает окно
(`frontend/src/pages/calc/kuzram/`): настройки, сравнение с расчётом «до
исправления», график q(d), разбор расчёта, фактические взрывы с подбором C(A)
и справка «Как пользоваться».

- Настройки и фактические взрывы хранятся за объектом работ — блок `kuzram` в
  настройках листа (`calc-inputs`, `version` 1). Без блока — умолчания; числа
  при чтении приводятся к границам. Перед `/blast/optimize` и
  `/blast/kuzram/calibrate` фронт отрезает `facts` (схема настроек —
  `extra=forbid`), в калибровку идут только полные строки в границах.
- Правка настроек перезапускает подбор (пауза 300 мс), правка фактов — нет.
- Умолчания и границы фронт берёт из `kuzramContract.json`; совпадение с
  `cunningham.py` и схемами API проверяет `tests/test_kuzram_frontend_contract.py`.
- Цифры примеров справки — `helpExamples.json`, их пересчитывает моделью
  `tests/test_kuzram_help_examples.py`.
- W/d (B/d у Каннингема) выше 35 — предупреждение в окне; подбор q не
  ограничивается. Ниже 25 не предупреждаем: для крепких пород это обычная
  сетка (решение владельца от 21.09.2026).
- JPA по Каннингему 2005, §4.1.1.3: 20 — падение трещин в сторону откоса, 30 —
  простирание поперёк откоса, 40 — падение в массив («out of face» —
  плоскость трещины, продолженная из откоса, уходит вверх). Формулировки ждут
  подтверждения технолога.

## «Проектирование»: движок кусковатости

С версии моделей 2.0.0 (с 2.1.0 — сила ВВ к ANFO) «Проектирование», паспорт БВР, сценарии, поиск Парето
и рекомендации считают кусковатость той же функцией `predict_point`, что и
лист «Расчёт». Входные величины региона влияния переводит в её аргументы
`simulation/fragmentation/base.py::region_point`:

- диаметр — диаметр скважины × коэффициент разбуривания, мм (как в
  `Blast.py::_charge`);
- длина заряда — сумма длин взрывчатых дек, без дек — скважина минус забойка;
  высота уступа — по оси скважины без перебура;
- сила ВВ — RWS = 100 · теплота взрыва / 3,8 (к ANFO, %), теплота смеси ВВ —
  средняя по массе.

Три модели различаются только кривой: `kuznetsov` — Розин — Раммлер с n = 1 (если калибровка не задаёт
`uniformity_n`),
`kuzram` — с n по Каннингему, `swebrec` — функция Swebrec поверх того же x50.
Прежние формулы (A по Лилли, 19/30, n ≥ 0,8) доступны как `*_legacy`, версия
1.0.0; сохранённые прогнозы не пересчитываются. Сценарий хранит версию
модели, посчитавшей его x50 (`fragmentation_model_version`); сценарий другой
версии — а без версии он сохранён на 2.0.0 — сравнение помечает
предупреждением «посчитан прежней версией модели».

**Настройки модели.** Отдельных настроек в «Проектировании» нет: сервер берёт
блок `kuzram` черновика листа «Расчёт» (`calc_object_inputs`) для объекта
работ из запроса, без него — для активного объекта организации, а если блока
нет — умолчания. Источник пишется в ответ и в `provenance.settings` прогноза.

**Неполный паспорт.** Скважина с нулевой массой заряда, силой ВВ или сеткой
пропускается с предупреждением; нулевая длина заряда или высота уступа —
множитель L/H = 1 и предупреждение.

**ML.** До PR 3 калибровки и пространственные признаки считают базу старой
моделью `kuzram_legacy`, а поправки калибровок к новым моделям в сценариях не
применяются.
