# Наряд-путёвка BlastEX ↔ MagEX (TASK-018, PR 7)

Источник истины по обмену — контракт MagEX `MagEX/Docs/contracts/blastex/README.md`
(версия 1). Его фикстуры и 19 векторов скопированы в `tests/fixtures/magex/`.
План и решения владельца — `Docs/plans/2026-11-12-task-018-pr7.md`.

## Кто что пишет

- **BlastEX** пишет выписанную часть — версиями: кто, куда, какие ВМ и сколько
  («Выписано» = по проекту + запас).
- **MagEX** пишет исполнение: резерв, выдачу, возврат, расход, закрытие. BlastEX
  его читает и показывает, но не правит.

## Включение

Флаг `BLASTEX_MAGEX_INTEGRATION_ENABLED` по умолчанию **выключен**. Без флага
слой «Наряд-путёвка» работает как до PR 7, и выпущенные ревизии печатаются
байт-в-байт как раньше.

| Переменная | Что |
|---|---|
| `BLASTEX_MAGEX_INTEGRATION_ENABLED` | флаг |
| `MAGEX_API_URL` | адрес MagEX до `/api/v1` включительно |
| `MAGEX_ORGANIZATIONS` | JSON `{"<организация BlastEX>": "<UUID организации MagEX>"}` |
| `BLASTEX_SIGNING_KEY`, `BLASTEX_SIGNING_KID` | закрытый ключ ES256 (PEM, P-256) и его `kid`; в одну строку — с `\n` |
| `BLASTEX_JWKS_EXTRA` | открытые ключи, которые публикуются, но не подписывают: следующий и прежние, `{"keys": [...]}` без `d` |
| `BLASTEX_ALLOW_TEST_KEY` | `true` — разрешить тестовый ключ MagEX (только тесты и локальный стенд) |
| `MAGEX_NARYAD_JWS_MAX_LENGTH` | предел длины строки, 500…2 953, по умолчанию 2 000 (как `VM_NARYAD_JWS_MAX_LENGTH` у MagEX) |

Если флаг включён, а адреса, ключа или организации нет, наряд работает
«вне учёта MagEX»: выпускается как раньше, на печати стоит пометка «вне учёта
MagEX». Ошибку в ключе или в наборе API проверяет при старте и тогда не
запускается. Ошибкой считаются: ключ не P-256, `d` в `BLASTEX_JWKS_EXTRA`,
повтор `kid`, тестовый ключ без разрешения.

## Первая выкладка

1. На VPS BlastEX создать ключ:
   ```bash
   python scripts/magex_signing_key.py --kid blastex-2026-11 --out /secure/blastex-signing.pem
   ```
2. Задать в окружении API `BLASTEX_SIGNING_KEY` (содержимое PEM) и
   `BLASTEX_SIGNING_KID`, перезапустить. Ключ опубликован по
   `https://<BlastEX>/.well-known/jwks.json`: Caddy передаёт этот путь в API.
3. В MagEX задать `VM_BLASTEX_JWKS_URL=https://<BlastEX>/.well-known/jwks.json` и
   перезапустить. После этого `/integrations/blastex/*` без токена отвечают
   `401`, а не `503`.
4. Не раньше чем через 330 с задать в BlastEX `MAGEX_API_URL`,
   `MAGEX_ORGANIZATIONS`, `BLASTEX_MAGEX_INTEGRATION_ENABLED=1` и перезапустить.

## Ротация ключа

1. Создать новый ключ (п. 1 выше). Его открытый JWK, который печатает скрипт,
   добавить в `BLASTEX_JWKS_EXTRA` и перезапустить.
2. **Не раньше чем через 330 с** — это кэш MagEX 300 с плюс пауза 30 с — новый
   ключ поставить в `BLASTEX_SIGNING_KEY/KID`, а открытую часть прежнего — в
   `BLASTEX_JWKS_EXTRA`.
3. Прежний ключ убрать, когда в `GET /api/v1/design/mass-blast-projects/magex/keys-in-use`
   его `kid` больше нет: наряд-путёвки с его QR закрыты и в очереди нет версий с его подписью.

## Справочники

- **Материалы** — «Позиция MagEX» (`magex_material_id`): выбирается из
  номенклатуры MagEX (`x-options: magex.materials`). Строка наряда без
  сопоставления не даёт разрешить наряд (`magex_material_unmapped`).
- **Проект МВ: реквизиты объекта:**
  - «Склад MagEX» (`magex_warehouse_id`);
  - «Разрешение на ВР: № / дата»;
  - «Спецавтомобиль: марка / гос. номер».
- **Взрывники** (`blasters`, раздел за флагом) — ФИО, индивидуальный индекс,
  № единой книжки, сотрудник SafetyMAIN. `blaster.ref` берётся из сотрудника
  SafetyMAIN; если его нет — это UUID v5 от организации и индекса. Взрывник
  наряда — выбранный в наряде, иначе найденный по ФИО взрывника из персонала
  проекта.

  Если в справочнике взрывников MagEX индекс уже связан с сотрудником,
  `blaster.ref` должен совпадать с ним. Иначе MagEX отвечает `409
  BLASTER_INDEX_CONFLICT` (кода нет в README контракта, он из MagEX PR 11),
  а окно подсказывает указать у взрывника того же «Сотрудника SafetyMAIN».

## Разрешение

«Разрешить» (`POST …/layers/{id}/magex/approve`) — выписка уходит в MagEX
очередной версией:

1. BlastEX собирает содержимое (`design/magex/naryad_payload.py`).
2. Подписывает строку JWS (`design/magex/jws.py`): raw DEFLATE до подписи,
   R‖S, `typ` = `naryad-v1`.
3. Выпускает ревизию слоя со снимком `magex`: строка, версия, склад, позиции.
4. Отправляет `PUT /naryads/{id}`.

| Ответ | Что делает BlastEX |
|---|---|
| `200` | версия `ACCEPTED`, наряд разрешён, печать открыта |
| `409`, `422`, `404`, `401`, `403` | версия `REJECTED`, ревизия убирается; в окне — нехватка, занятый номер, запреты или ошибки по полям |
| `503`, сеть, `5xx` | версия `PENDING`, ревизия остаётся, печать закрыта до приёма |

Версии в состоянии `PENDING` повторяет фоновая задача процесса API — раз в
30 с, с отступом 30 с … 60 мин. Уходит та же строка. «Повторить сейчас»
отправляет её сразу.

Если выписка не изменилась, новая версия не заводится: уходит принятая строка,
и MagEX отвечает `200` «без изменений». После выдачи ВМ склад, взрывник, дату
выписки, состав и количества менять нельзя: нужна новая наряд-путёвка.

Если выписка не изменилась, но изменилось то, что не подписывается (исполнение после взрыва,
подписи), «Разрешить» выпускает новую ревизию для печати с той же строкой и QR — архивную копию
с графами после взрыва. Округление кг до целых патронов (штучная позиция MagEX) ложится в запас:
«Выписано» в печати — как в выписке; окно сообщает об округлении.

Отменить наряд до выдачи — `POST …/magex/cancel` с причиной. После выдачи
наряд закрывается на складе.

## Печать

QR — та же строка JWS, что ушла в `PUT`. Он стоит справа вверху формы 4,
размер 40 × 40 мм без масштабирования, уровень коррекции L. QR не сжимается вместе с формой:
при большом числе блоков и позиций сжимается только часть формы ниже шапки. Под QR — «№ /
версия / склад». Если строка длиннее предела, сначала сокращаются названия
блоков; не помогло — выписка не отправляется.

Печатается только последняя принятая версия, и только пока наряд не отменён.

## Исполнение

`GET /naryads/{id}` вызывается при «Разрешить», «Обновить» и отмене; последний
ответ хранится. Выдано, возвращено и израсходовано по строкам наряда, а также
разд. 1 по блокам (`block_results`) берутся из MagEX — они главнее ручного
ввода и факта. Расхождение с фактом заряжания даёт предупреждение. Акт приёмки
берёт фактический расход ВВ из MagEX, если расход внесён.
