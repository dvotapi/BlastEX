## Раскладка

- Шапка: логотип COMPLEX, справа серым «Проект массового взрыва № … · блок № … · гор. …», жирно — название листа, красная линия. На продолжениях техрасчёта и таблицы шапки нет (как в эталоне).
- Таблица параметров: книжный A4, 63 скважины на первой странице и 73 на следующих; заголовок таблицы — на каждой странице; № первого ряда — красным; диаметр, перебур, забойка и ПД — «общей записью»; графы Ф — белые клетки; итог — строкой под последней скважиной (не помещается — на следующей странице).
- Титул — по координатам эталона; техрасчёт — разд. 13 с новой страницы.
- Талон-допуск — два экземпляра на листе, линия отреза ровно посередине высоты A4.

## Двусторонняя печать

Комплект (`00_Комплект.pdf` и «проект» `project.pdf`): каждый документ начинается с лицевой; после документа с нечётным числом страниц — пустой оборот «Страница оставлена пустой» с подвалом документа. Проект — сквозная «Стр. N из M» с учётом пустых; документы дня взрыва — у каждого своя, пустой оборот — без номера. Отдельно скачанный документ — без пустых оборотов, своя нумерация.

- **Масштаб и поворот** (TASK §4): крупнейший масштаб ряда, при котором блок помещается «север вверх»; если для этого нужен масштаб мельче 1:500 — поворот с шагом 1° в 1:500 (первым рядом вниз), не помещается — следующий масштаб. Один вид на Г.1, Г.3, Г.4 блока.
- **Печать 100 %**: PDF с графикой просит просмотрщик печатать в фактическом размере (`/PrintScaling /None`), у линейки — напоминание.
- **Точки Г.5** — `payload.layout_points` проекта v2: `{kind: guard_post|blast_station|shelter|gather, ref, x, y, label}` в СК объекта; пост — по коду. Без точки — предупреждение `layout_point_missing`, пост ближе зоны для людей — `guard_post_inside_zone`, станция или укрытие в зоне — `station_inside_zone` (предупреждения), неизвестный пост — ошибка `layout_point_unknown_post`.
- Несколько блоков: Г.1–Г.4 — лист на блок, Г.5 — один. Лист «Перечень графических материалов» формы не печатается: его роль у «Состава проекта».

## Факт (PR 5)

Факт бурения, заряжания и взрывания пишется в проект блока (`as_drilled`, `as_charged`, `as_fired`); в документы он попадает только через **слой «Факт»** (`EXECUTION`, решение владельца В1 12.11.2026). Подписанная ревизия проекта не меняется: «перевыпуск таблицы ревизией `executed`» — ревизия этого слоя.

- **Слой «Факт»** — один на проект, открывается после `approved` (факт бурения нужен до заряжания, п. 412), перевыпускается после заряжания и взрыва. Перенос (`seed.blocks_fact`): строки Р ревизии проекта с графами Ф (`design/mass_blast_fact.py`), фактический расход ВМ, точки Г.1 по съёмке и геометрия плана Г.1 ревизии, отпечаток факта блока `execution_sha256`. Проект блока, изменённый после выпуска ревизии проекта МВ (`designed_sha256`), — ошибка. Ручной ввод: дата и время взрыва по факту, скважины-отказы (`misfired_holes` — «отказ» в примечании), примечания по факту; в проекте из нескольких блоков с одинаковыми номерами — «блок:номер» (иначе `fact_hole_ambiguous`). Факт в проекте блока записан после переноса — `fact_changed`, выпуск — после повторного переноса.
- **Графы Ф** — теми же функциями, что Р, на копии проекта с фактической геометрией (факт, где есть, иначе проект): глубина — длина по оси; перебур Δ_ф = L_ф − (Z_уст.ф − Z_подошвы)/cos α_ф при проектной подошве; ЛСПП (только первый ряд Р), a, b — у скважин с фактом бурения; масса — как записано, до 1 кг; забойка — над верхним зарядом. Итог Ф графы — когда факт есть у всех скважин. Нет факта — белая клетка. Копия проекта в факте — предупреждение `fact_copied_from_design`.
- **Документ 11**: исполнительные таблицы (шапка «(ФАКТ)», «взрыв по факту», под таблицей — «бурение N из M, заряжание N из M, отказов K») и Г.1 по съёмке (скважины по фактическим устьям; без съёмки — пустым серым кружком по проекту; смещение устья > 0,5 м — № красным и перечнем); одна нумерация на обе части (`numbering="group:EXECUTION"`). В PACKAGE — `11_Таблица_параметров_(исполнительная).pdf` после акта приёмки.
- **Наряд-путёвка после взрыва** (только у проекта `executed`/`closed`): ручной ввод `issued`, `consumed`, `returned` по ключу строки ВМ. Израсходовано — из последней выпущенной ревизии «Факта» (ВВ, ПД, НСИ скважинные; инициатор с маркой из `as_fired` главнее проектной сети), поверхностные и стартеры — вручную; возвращено = выдано − израсходовано (ручное главнее; отрицательный остаток не печатается); у ВВ, изготавливаемых на месте, — «—». Разд. 1: заряжено, взорвано (= заряжено − отказы), отказы, отклонение. Сверка баланса — предупреждения `naryad_balance_mismatch`, `naryad_vv_site_balance`, на печать не идут (графа «Контроль» — MagEX, PR 7).
- **Талон-допуск**: `fired_date`, `fired_time` — фактическое время взрыва; «не ранее» = факт + 30 мин (через полночь — с датой); без факта — проектное + 30 мин со звёздочкой «по проектному времени взрыва».
- **Акт приёмки**: «Параметры взрывных работ (по факту)» — сетка по факту, удельный расход = израсходовано ВВ / объём «к оплате» (не введён — к объёму по контуру, с пометкой), «Израсходовано ВВ, кг»; дата взрыва в тексте — по факту. Нет выпущенного «Факта» — «(по проекту)» и предупреждение `execution_missing`.
- Акт приёмки и наряд берут факт из последней выпущенной ревизии «Факта» на той же ревизии проекта (`seed.fact.execution_revision_id`); вышла новая — `fact_layer_stale`, перенос — `refresh`.
- Ревизии слоёв, выпущенные до PR 5, печатаются байт-в-байт как раньше (новые ключи `view` у них отсутствуют).

Маршруты окна (за флагом): `POST /new`, `GET /{id}/hints`, `GET /{id}/layers/available`, `GET /{id}/notification-addressees`.
