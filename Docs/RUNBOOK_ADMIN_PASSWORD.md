# Runbook: смена логина и пароля администратора

В интерфейсе BlastEX смены пароля нет. Учётные записи задаются только
конфигурацией, и в ней хранится не пароль, а его хеш.

## Как устроены учётные записи

- Пользователи описаны JSON-массивом в переменной `BLASTEX_USERS_JSON`.
  Если переменная не задана, API читает TOML-файл из `BLASTEX_USERS_FILE`,
  а без неё — `.streamlit/secrets.toml` (`cost/auth.py`).
- Логин — поле `email` (регистр не важен), пароль — поле `password_hash`
  (PBKDF2-SHA256, 600 000 итераций).
- Роли: `admin`, `reference_editor`, `user`. Запись с другой ролью,
  пустым `email` или пустым `password_hash` молча пропускается.
- На проде контейнер `blastex-api` получает переменные из файла `.env`,
  который лежит рядом с `docker-compose.production.yml`.

## Шаг 1. Получить хеш нового пароля

В корне репозитория (локально или на VPS):

```bash
python3 scripts/hash_password.py
```

Скрипт дважды спросит пароль (ввод не отображается) и выведет строку вида
`pbkdf2_sha256$600000$<соль>$<хеш>`. Скопируйте её целиком. Каждый запуск
даёт новую соль, поэтому хеш каждый раз разный — это нормально.

## Шаг 2а. Прод (VPS)

1. Зайдите на сервер по SSH и перейдите в каталог проекта, где лежат
   `docker-compose.production.yml` и `.env`.
2. Сделайте резервную копию **вне каталога проекта** — в `.env` пароли
   к базе, ключи и секрет сессий, и копии не место в рабочем дереве Git
   и в контексте сборки Docker:

   ```bash
   install -m 700 -d ~/blastex-env-backups
   cp -p .env ~/blastex-env-backups/.env.bak-$(date +%F)
   chmod 600 ~/blastex-env-backups/.env.bak-*
   ```

3. Откройте `.env`, найдите строку `BLASTEX_USERS_JSON=` и у нужного
   администратора замените `password_hash` (и `email`, если меняется логин):

   ```
   BLASTEX_USERS_JSON='[{"email":"admin@company.ru","password_hash":"pbkdf2_sha256$600000$...$...","role":"admin","display_name":"Администратор","organization_id":"default","organization_name":"Моя компания","active":true}]'
   ```

   - Значение берите **в одинарные кавычки**. В хеше есть символы `$`;
     без одинарных кавычек Docker Compose примет их за переменные,
     хеш испортится и войти будет нельзя.
   - JSON пишется одной строкой.
   - Остальные записи массива не трогайте: удалённый пользователь
     перестанет входить.

4. Пересоздайте контейнер API:

   ```bash
   docker compose -f docker-compose.production.yml up -d api
   ```

   `docker compose restart` не подходит — он не перечитывает `.env`.
   Пересобирать образ и ждать деплой не нужно.

5. Проверьте, что API видит пользователя:

   ```bash
   docker compose -f docker-compose.production.yml exec api python -c "from cost.auth import configured_users; print([(u.email, u.role, u.active) for u in configured_users()])"
   ```

   В списке должен быть нужный email с ролью `admin`.

6. Войдите в интерфейс с новым паролем.

## Шаг 2б. Локальный стенд

1. Откройте `.streamlit/secrets.toml` (файл в `.gitignore`).
2. В блоке `[[blastex.users]]` замените `password_hash`, при необходимости
   и `email`. В TOML значение пишется в двойных кавычках, `$` экранировать
   не нужно:

   ```toml
   password_hash = "pbkdf2_sha256$600000$...$..."
   ```

3. Перезапустите API. Если в окружении задан `BLASTEX_USERS_JSON`, файл
   игнорируется — правьте переменную.

## Диагностика

| Симптом | Причина |
|---|---|
| Пользователь в списке есть, но вход не проходит | Хеш испорчен: `$` съеден интерполяцией (нет одинарных кавычек) или строка скопирована не целиком |
| Список пользователей пустой | Ошибка в JSON — API отбрасывает конфигурацию целиком |
| Нужного пользователя нет в списке | `role` не из допустимых, либо пустой `email` или `password_hash` |
| Изменения не применились | Выполнен `restart` вместо `up -d` |

Откат: `cp -p ~/blastex-env-backups/.env.bak-<дата> .env`, затем снова
`docker compose -f docker-compose.production.yml up -d api`.

## Безопасность

- Сессия — подписанный токен со сроком действия (`api/security.py`), он не
  зависит от пароля. После смены пароля уже вошедшие браузеры остаются
  в системе до истечения сессии. Чтобы завершить все сессии сразу, смените
  `BLASTEX_SESSION_SECRET` в том же `.env` и выполните `up -d api`.
- Старые переменные `BLASTEX_ADMIN_EMAIL` / `BLASTEX_ADMIN_PASSWORD`
  действуют, только когда список пользователей пуст. Если они остались
  в `.env`, удалите их: там пароль в открытом виде.
- Не пересылайте хеш и `.env` в чаты: хеш не раскрывает пароль напрямую,
  но позволяет подбирать его офлайн.
