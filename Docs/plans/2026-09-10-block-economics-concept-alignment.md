# Экономика блока: приведение вкладки к дизайн-концепту

## Контекст

Вкладка «Экономика блока» (PR #70, слит 2026-09-10, коммит `62da15e`) работает
на проде и считает смету, но выглядит иначе, чем визуальный концепт владельца
`Docs/design/economics_block_concept.png`: другая компоновка (шапка в три
этажа вместо одной строки, полоса паспорта вместо карточки показателей,
разделы без карточек), шрифты на 1–3 px мельче, редакторы величин свалены в
32-пиксельную колонку действий и наезжают на суммы.

Проверка прода 2026-09-10 нашла 11 дефектов, часть из которых блокирует
работу: страница падает целиком при открытии сохранённого прогона, выпадающие
списки справочников не видны из-за обрезки, липкая шапка колонок закрывает
строки. Владелец решил чинить все 11 в этой же работе.

Цель: вкладка визуально и по компоновке совпадает с концептом, все найденные
дефекты закрыты, расчёт и API не меняются.

## Что уже решено с владельцем

1. **Меняем только страницу экономики.** Пункты бокового меню, набор страниц и
   верхняя панель для других страниц не трогаются.
2. **Верхняя панель на этой странице:** селекторы объекта и паспорта слева,
   затем логотип «Комплексные Решения», затем круглая иконка «?» (справка),
   затем «Выйти». Заголовок страницы из панели уходит — он живёт на странице,
   как в концепте.
3. **Названия в строках сметы — обычный текст.** Клик по названию открывает
   список справочника с поиском; рамки поля нет, при наведении и фокусе видна
   стрелка и подчёркивание. Роль `combobox` и клавиатура сохраняются.
4. **Вторичные величины** («смены на блок» у должности, «плановые смены в
   месяц» у техники, «плановые смены станка») уходят из колонки действий в
   серую подпись под названием, правятся из меню строки «⋯».
5. **Чиним все 11 дефектов проверки прода.**

## Ограничения

- Бэкенд, схемы API и модель себестоимости (`cost/`, `api/`) не меняются.
- Все изменения — в `frontend/src/pages/economics/**`, `frontend/src/styles/economics.css`,
  плюс две строки вне страницы: класс страницы в `frontend/src/app/AppShell.tsx`
  и мета-тег `viewport` в `frontend/index.html`.
- Роли и подписи для доступности (`aria-label`) сохраняются везде, кроме одной
  осознанной замены, указанной ниже, — чтобы не переписывать тесты без нужды.
- `npm --prefix frontend test` и `npx tsc -b` зелёные после каждой задачи.

## Фаза 0. Дефекты, которые мешают работать

### 0.1. Падение страницы на сохранённых прогонах

`draftFromRun` в [scenario.ts:56](frontend/src/pages/economics/scenario.ts:56)
подставляет значения только для двух полей субподряда. Прогоны, сохранённые до
PR #69/#70, не содержат `services`, `machine_plan_shifts`, `emulsion_truck_code`;
`ServicesPanel` падает на `services.length`, React размонтирует всё дерево, в
консоли `TypeError: Cannot read properties of undefined (reading 'length')`.

- `draftFromRun` принимает вторым аргументом `defaults: ModelDefaults` и
  собирает параметры как `{ ...defaults.parameters, ...rawParameters }` с
  явным приведением `undefined → null` для необязательных полей. Комментарий
  про субподряд обобщить.
- `ServicesPanel` и `ServicesSection` защитить `services ?? []`.
- Новый `EconomicsErrorBoundary` (классовый компонент, `componentDidCatch`)
  оборачивает содержимое страницы: показывает карточку «Не удалось показать
  смету» с текстом ошибки и кнопкой «Перезагрузить». В проекте error boundary
  ещё нет — это первый.
- Тест: `scenario.test.ts` — прогон без `services`/`machine_plan_shifts` даёт
  черновик с непустыми значениями по умолчанию.

### 0.2. Выпадающие списки не видны

`.catalog-select-popover` — `position:absolute` внутри ячейки названия с
`overflow:hidden` ([economics.css:41](frontend/src/styles/economics.css:41)),
выше по дереву режут ещё `.estimate-table` и `.table-scroll`. Тем же дефектом
болеет `.row-menu-list`.

- Новый хук `estimate/useAnchoredPosition.ts`: по `ref` кнопки и признаку
  открытия считает `top/left/minWidth` из `getBoundingClientRect()`,
  переворачивает вверх при нехватке места снизу, прижимает к краям окна.
  Пересчёт на `scroll` с `capture: true` (ловит прокрутку любого предка) и на
  `resize`. В jsdom прямоугольник нулевой — возвращать нули и пропускать
  переворот, ничего не бросая.
- `CatalogSelect` и `RowMenu` рисуют поповер через `createPortal` в
  `document.body` с `position: fixed` и координатами из хука, `z-index: 50`.
- Обработчик клика вне должен проверять оба узла — контейнер кнопки и сам
  поповер, иначе клик по пункту закроет список раньше выбора.
- Клавиатура не меняется: события всплывают по дереву React, `onKeyDown` на
  корне портала продолжает ловить нажатия в поле поиска.
- Тесты: список открывается внутри предка с `overflow:hidden` и не является
  его потомком в DOM; клик по `document.body` закрывает; существующие три
  теста `CatalogSelect.test.tsx` проходят без правок.

### 0.3. Липкая шапка колонок закрывает строки

`.estimate-head` липнет к ближайшему предку с прокруткой, а это
`.estimate-table` с `overflow:hidden` — шапка застывает на `167px` внутри
таблицы и закрывает строку раздела.

- Между `.estimate-head` и документом не должно остаться ни одного предка с
  `overflow != visible`: `.table-scroll` вокруг сметы убрать, `.estimate-table`
  сделать `overflow: visible`. Скругление углов перенести на саму шапку
  (`border-radius: 14px 14px 0 0`) и на последнюю секцию.
- `top: 0` вместо `var(--passport-strip-h)`: карточка показателей больше не
  липкая.
- Горизонтальная прокрутка узкой таблицы включается только в медиазапросе
  ниже `1050px`, где липкая шапка не нужна.

### 0.4. Наложение редакторов на суммы

Побочный эффект того, что у классов `drilling-volume`, `drilling-rate`,
`drilling-plan-shifts`, `drilling-links`, `drilling-executor`,
`equipment-role-shifts`, `equipment-role-note`, `subcontract-drilling-name`,
`drilling-rate-manual`, `explosives-manual-qty`, `link-button`,
`drilling-drawer` нет ни одного правила в CSS. Закрывается фазами 3–5 (эти
классы исчезают или получают правила) и защитным тестом из фазы 7.

  после `titleSlot`, то есть между селекторами и слотом справа, ровно как
  просил владелец.
- `EconomicsHelp` портирует кнопку не в `titleSlot`, а в `topbarSlot`, и
  становится круглой иконкой «?» (`aria-label="Справка"`, 32×32, рамка,

- Новый компонент `TopbarSelectors.tsx` в папке экономики: рисует три блока и
  портирует их в `titleSlot`. Если слота нет (тесты компонентов без `AppShell`)
  — рисует их на месте, как это уже делает `EconomicsHelp`.

`.economics-card` оборачивает `EconomicsTabs` + панель инструментов + активную

## Фаза 3. Примитивы таблицы

### 3.1. `EstimateLine` — новый набор свойств

Свойство `actions` **удаляется** — это и есть механизм миграции: каждый
непереписанный вызов станет ошибкой типов.

```ts
type RowMenuItem = { label: string; onSelect: () => void; danger?: boolean;
                     expanded?: boolean; controls?: string };

type EstimateLineCaption = { label: string; value: string; origin?: ValueOrigin;
                             originLabel?: string; originTitle?: string };

type EstimateLineProps = {
  number: string;
  name: ReactNode;
  captions?: EstimateLineCaption[];   // серая строка под названием, пункты через «·»
  origin: ValueOrigin;
  originLabel?: string;
  quantity: number | null;
  quantityEditor?: ReactNode;         // компактный ввод прямо в колонке «Кол-во»
  unit: string;
  price: number | null;
  amount: number | null;              // null — сумма живёт в другом разделе, «—»
  volume: number | null;
  share: number | null;               // null — пустая ячейка «%»
  menuItems?: RowMenuItem[];          // раздел больше не рендерит RowMenu сам
  menuLabel?: string;
  editor?: ReactNode;                 // панель под строкой
  editorMenuLabel?: string;           // подпись пункта, открывающего панель
  formula?: string;
};
```

**Одно меню на строку.** Сегодня строки материалов рисуют два соседних «⋯»:
один от раздела, второй от самой строки для формулы. Пункты склеиваются в один
список в порядке: пункт редактора, пункты раздела, «Формула», опасные пункты
(«Убрать») последними.

**Панель под строкой.** Одно состояние `panel: "editor" | "formula" | null`,
один узел `.estimate-line-panel` на месте сегодняшнего `<details>` формулы.
Пункт меню получает `aria-expanded`/`aria-controls`, панель —
`role="group"` с подписью и атрибут `hidden` в закрытом виде. При открытии
фокус уходит на первый элемент внутри, `Escape` закрывает и возвращает фокус
на «⋯». Клик вне не закрывает: это поверхность правки, а не всплывашка.

При заданном `quantityEditor` согласование колонок «Кол-во» и «Цена»
(`reconcilingColumns` в [format.ts:42](frontend/src/pages/economics/format.ts:42))
пропускается — иначе цена дёргается, пока пользователь печатает.

### 3.2. `CatalogSelect` — текст вместо поля

Новое свойство `variant?: "ghost" | "field"`, по умолчанию `"ghost"`: без
рамки и фона, шрифт наследуется от строки, стрелка `▾` прозрачна и проявляется
при наведении и фокусе, подчёркивание пунктиром на `:hover`/`:focus-visible`.
`variant="field"` — сегодняшний вид с рамкой, остаётся только в карточке
бурения. Роль `combobox` и `aria-label` не меняются, поэтому запросы тестов
`getByRole("combobox", { name })` продолжают работать.

### 3.3. `RowMenu`

Тип пункта выносится в общий, добавляются `aria-expanded`/`aria-controls` у
пунктов-раскрывашек, список рисуется через портал (см. 0.2), пустой список
по-прежнему не рисует кнопку.

### 3.4. Сетка колонок

`44px | minmax(0,1fr) | 104px | 104px | 56px | 104px | 128px | 84px | 68px | 36px`,
подписи шапки как в концепте: «Статья / Номенклатура», «Цена, ₽», «Сумма, ₽».
Номер раздела переезжает в колонку «№», каретка и название — в колонку статьи
(сегодня кнопка раздела занимает обе колонки сразу).

## Фаза 4. Разделы сметы

| Раздел | Что меняется |
| --- | --- |
| **Взрывчатые материалы** | Название — текстовый комбобокс. Количество электродетонаторов из колонки действий → `quantityEditor`. Дублирующий бейдж «Ручной» убрать: происхождение уже приходит от модели. «Убрать» → `menuItems`. |
| **Персонал** | Численность → `quantityEditor` с прежней подписью `Численность: …`. «Смены на блок» → подпись под названием + панель редактора с прежней подписью `Смен на блок: …`, пункт меню «Смены на блок». «Сбросить к нормативу» и «Убрать» → `menuItems`. Строкам взносов и резерва добавить `formula`. |
| **Техника и оборудование** | «Смены на блок» и «Плановые смены в месяц» → две подписи под названием с бейджами; поле ввода — в панели редактора с прежней подписью `Плановые смены: …`. |
| **Бурение** | Фаза 5. |
| **ГСМ, Постоянные расходы** | Структурно не меняются, получают склеенное меню. Пустое состояние обернуть в `.estimate-section-empty`, чтобы оно не было прямым не-сеточным потомком тела раздела. |
| **Производственные услуги** | Панель ручных услуг оборачивается в `.estimate-section-footer`. |

Строка станка в «Технике» сейчас показывает 309 095 ₽ и 11 %, которых нет в
итоге раздела: статьи владения станком имеют `section = "DRILLING"` и попадают
в раздел «Бурение». Строка становится ссылочной: `amount = null`,
`share = null` → «—» в суммах и пустой процент, а третья подпись под названием
читает «Затраты станка: 309 095 ₽ — в разделе „Бурение“» и по клику
разворачивает раздел «Бурение» тем же путём, каким это делает клик по кольцу.
После этого итог раздела сходится с суммой видимых строк, а колонка процентов
перестаёт дважды считать одни и те же деньги.

Кнопки «+ Добавить материал / должность / технику» переезжают в
`.estimate-section-footer` — сегодня это прямые потомки тела раздела мимо сетки.

## Фаза 5. Карточка бурения

Новый общий компонент `drilling/DrillingCard.tsx` — светлая карточка внутри
тела раздела, три колонки:

1. «Исполнение» (переключатель, приезжает пропом из `DrillingSection`) и
   «Буровая установка» — комбобокс `variant="field"`.
2. Величины: «Объём бурения» с плашкой «Из паспорта», «Стоимость 1 п.м.» с
   плашкой «Из расчёта бурения», редактируемые «Плановые смены станка».
3. «Сумма» — крупное число 22 px, под ним ₽/м³, ниже кнопка
   «Открыть расчёт бурения →».

Ведущая строка сметы у бурения исчезает, подстроки (ДТ, запчасти,
амортизация) идут после карточки обычными строками с номерами `2.1`, `2.2`.
Ссылка «Перейти к расчёту бурения (Бурение) →» переезжает в подвал раздела с
сохранением точной подписи — на неё опирается тест страницы.

Субподряд использует ту же карточку: подрядчик и тариф — два поля в первой
колонке, «Ставка, ₽/м» — редактируемая величина во второй. Разметку
`.drilling-rate-save-form` сохранить дословно: на неё опирается
`BlockEconomicsPage.test.tsx`.

Единственная осознанная смена подписи во всей работе: плашка стоимости метра
становится «Из расчёта бурения» вместо «Расчёт бурения»; соответствующее
утверждение в `DrillingSection.test.tsx` поправить, проверку `title` оставить.

`DrillingDrawer` получает стили, закрытие по `Escape` и перевод фокуса внутрь
при открытии (дефект 11 отчёта).

## Порядок работ

Каждая задача — отдельный коммит, тесты и `tsc -b` зелёные после каждой.

1. Дефекты 0.1 (падение, error boundary).
2. `useAnchoredPosition` + портал `CatalogSelect`.
3. Портал и типы `RowMenu`.
4. `EstimateLine`: `menuItems`, удаление `actions`, одно меню. После этой
   задачи `tsc -b` покажет все непереписанные вызовы разом.
5. `EstimateLine`: панель редактора, доступность, фокус.
6. `EstimateLine`: `captions`, `quantityEditor`, `amount`/`share` как `null`.
7. Разделы «Взрывчатые материалы» и «Персонал».
8. Раздел «Техника», ссылочная строка станка.
9. `DrillingCard`, свои силы, субподряд, ящик расчёта.
10. Верхняя панель: класс в `AppShell`, селекторы, круглая справка.
11. Шапка страницы, карточка показателей, карточка вкладок, снятие липкости.
12. Сайдбар.
13. Токены и полный проход по стилям, защитный тест классов.
14. Фаза 8 целиком.
