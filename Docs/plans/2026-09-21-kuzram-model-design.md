# Модель Kuz-Ram на листе «Расчёт»: исправленный подбор q, настройки и справка

Дата: 2026-09-21. Статус: дизайн утверждён в чате, спецификация на ревью.

## Зачем

Лист «Расчёт» («Подбор параметров БВР») подбирает для каждой коронки наименьший
удельный расход q, при котором негабарит не превышает допустимый. Проверка
формул по первоисточнику (C. V. B. Cunningham, «The Kuz-Ram fragmentation
model — 20 years on», EFEE 2005) показала четыре отклонения от модели Kuz-Ram:

| Что | В коде | У Каннингема |
|---|---|---|
| Диаметр в индексе n | метры — n всегда упирается в 0,8 | миллиметры |
| Фактор породы A | 0,12·(UCS/20 + 2,5ρ + 7) | 0,06·(RMD + RDI + HF) |
| Показатель силы ВВ | 19/30 (1983) | 19/20 (1987) |
| Индекс n | (1 + (a/W − 1)/2), без L/H | √((1 + a/W)/2)·L/H |

Две главные ошибки почти гасят друг друга: полная модель Kuz-Ram для
монолитного массива даёт q, близкий к нынешнему (габбро-диабаз, 152 мм:
1,26 против 1,34 кг/м³), и это подтверждено опытом владельца. Исправление
одних единиц диаметра (PR #82) даёт нереальные 0,37 кг/м³, поэтому PR #82
закрывается и заменяется этой работой.

Временный симулятор (https://claude.ai/artifact/YRWRbE1JRgbgWNU3AhoRyG)
понравился владельцу; его возможности переносятся в сервис.

## Решения владельца

1. Исправленная модель применяется **только к подбору q на листе «Расчёт»**.
   Вкладка «Проектирование», отчёты и ML-калибровка остаются на старом
   Kuz-Ram; их перевод — отдельная задача.
2. Настройки модели и фактические взрывы хранятся **за объектом работ**,
   вместе с остальными настройками листа.
3. В окне модели есть сравнение со старой моделью («До исправления») на
   переходный период.
4. Расчёт — **на сервере**; фронт формул не считает (правило CLAUDE.md:
   расчётные модули не знают об интерфейсе, всё проходит через `api/`).
5. Внутри окна — **справочный раздел** с подробным описанием работы и
   примерами.
6. Два PR: сервер, затем фронт; выкатка после слияния обоих.
7. W/d (B/d у Каннингема) — **предупреждать только выше 35**, подбор q не
   ограничивать (21.09.2026): для габбро-диабаза W/d = 20–23,5 на всех
   коронках, и предупреждение «ниже 25» горело бы всегда.

## Не входит

- Перевод `simulation/fragmentation/kuzram.py`, вкладки «Проектирование»,
  отчётов, `intelligence/` и переобучение моделей остатков негабарита.
- Хранение свойств массива в справочнике пород.
- Hardness factor через модуль упругости (HF = Y/3 при Y < 50 ГПа): модуля
  в данных нет, HF = UCS/5.
- Расширения Каннингема 2005: точность замедления, ограничения B/d и S/B,
  F(A) в n.
- Существующее расхождение валидации: порода с UCS = 0 из справочника даёт
  422 на `/blast/optimize` — поведение не меняется.

## Часть 1. Модель расчёта

### Где живёт

- `simulation/fragmentation/cunningham.py` — новый модуль с чистыми функциями
  Kuz-Ram по Каннингему: фактор A, x50, n, негабарит, подбор C(A). Без
  зависимостей от `api/`.
- `Blast.py`:
  - `BlastEngine.optimize_blast(diameter_mm, max_oversize_threshold, settings)`
    считает по новой модели;
  - `BlastEngine.optimize_blast_legacy(...)` — нынешний расчёт без
    изменений: перебор q от 0,30 до 1,50 с накоплением `q += 0.01`,
    округление негабарита до сотых перед сравнением с порогом, n ≥ 0,8.
    Нужен только для столбца «До исправления» и удаляется отдельным PR,
    когда владелец решит.
  - Мёртвый `calculate_for_diameter` (`target_q = 1.4`, из API не
    вызывается) удаляется.

### Настройки (`KuzRamSettings`, неизменяемый dataclass)

| Поле | Смысл | Умолчание | Допустимо |
|---|---|---|---|
| `rock_factor_method` | способ расчёта A | `rmd50` | `rmd50`, `rmd10`, `joint_factor`, `manual` |
| `rock_factor_manual` | A при ручном вводе | 6,0 | 0,5–30 |
| `joint_condition` | JCF: плотные / раскрытые / с заполнителем | 1 | 1; 1,5; 2 |
| `joint_angle` | JPA: ориентация трещин | 20 | 20; 30; 40 |
| `rock_factor_correction` | C(A) | 1,0 | 0,1–10 |
| `strength_exponent` | показатель при силе ВВ | `19/20` | `19/20`, `19/30` |
| `drill_deviation_m` | σ, отклонение бурения, м | 0 | 0–2 |
| `uniformity_correction` | C(n) | 1,0 | 0,5–2 |
| `q_max_kg_m3` | верхняя граница перебора q | 2,0 | 0,5–5 |

Намеренно не переносятся из симулятора «A как в коде» и «n как в коде»:
с исправленными единицами они дают нереальный q, а старое поведение видно
в столбце «До исправления».

Подписи JPA — по Каннингему 2005, §4.1.1.3 («out of face» — плоскость трещины,
продолженная из откоса, уходит вверх): 20 — «падение в сторону откоса»,
30 — «простирание поперёк откоса», 40 — «падение в массив». Первая
редакция спецификации давала их наоборот; владелец 21.09.2026 выбрал вариант
статьи. Формулировки — на подтверждение технологу.

### Формулы

Общее с нынешним расчётом (без изменений):

```
d  = коронка/1000 · коэф. разбуривания              [м]
L  = 0,8 · (H + перебур)                             [м] длина заряда
Q  = π·d²/4 · ρВВ·1000 · L                           [кг]
V  = Q / q;  W = √(V / (a/W · H));  a = a/W · W;  b = W
RE = теплота взрыва / 4,184                          (к тротилу)
```

Новая модель:

```
RDI = 25·ρ − 50                  HF = UCS/5
RMD = 50 (rmd50) | 10 (rmd10) | JF (joint_factor)
A   = 0,06·(RMD + RDI + HF)·C(A)        (manual: A = rock_factor_manual·C(A))
x50 = A · q^−0,8 · Q^(1/6) · RE^(−e) · 10   [мм], e = 19/20 или 19/30
n   = (2,2 − 14·W/d_мм) · √((1 + a/W)/2) · (1 − σ/W) · 1,1^0,1 · min(1, L/H) · C(n)
xc  = x50 / (ln 2)^(1/n)
негабарит = exp(−(кусок/xc)^n) · 100 %
```

Трещиноватость (Каннингем 2005): шаг трещин s = 1/трещиноватость,
P = √(a·b) = W·√(a/W); JPS = 10 при s < 0,1 м, 20 при s < 0,3 м, 80 при
s < 0,95·P, иначе 50; JF = JCF·JPS + JPA. При трещиноватости 0 — RMD 50,
в разборе пометка «массив без трещин».

n ниже 0,1 (нереальная геометрия или σ ≥ W) принимается равным 0,1, в разборе
видно «сырое → принятое».

### Подбор q

q = i/100 для i от 10 до round(q_max·100): первое q, при котором негабарит
(без округления) не превышает порог. Если такого нет — результат при q_max
и `reached = false`. Нижняя граница 0,10 вместо 0,30: на известняке и
песчанике правильный q бывает ниже 0,30.

### Результат по коронке

q, W, a, b, x50, n, негабарит, `reached` и `details` для разбора:
d, L, Q, V, A и его состав (RMD или JF с s, P, JPS; RDI; HF; C(A)), RE и
показатель, n сырое и принятое, L/H, xc. Версия модели —
`kuzram-cunningham-1.0`.

## Часть 2. API и хранение

### `POST /api/v1/blast/optimize` (обратно совместим)

- Запрос: необязательный `kuzram: KuzRamSettingsSchema`; без него —
  умолчания. Pydantic проверяет границы из таблицы; нарушение — 422 с русским
  текстом.
- Вариант (`BlastOptimizeVariant`): прежние поля теперь из новой модели;
  плюс `reached: bool`, `details: FragmentationDetailsSchema`,
  `legacy: LegacyVariantSchema` — q, W, a, b, x50, n, негабарит, `reached`
  и `details` старой модели. `target_q_kg_m3` сохраняется для совместимости
  (`null`, если порог не достигнут).
- Ответ: плюс `model_version` и `kuzram` — фактически применённые настройки.

### `POST /api/v1/blast/kuzram/calibrate`

- Запрос: `rock`, `explosive`, `target`, `kuzram` и `facts` (1–50 строк:
  `crown_mm` > 0, `q_kg_m3` > 0, 0 < `oversize_pct` < 100). Порог негабарита
  не нужен: q взят из факта, а не подбирается.
- Ответ по каждой строке: `legacy_oversize_pct` и `model_oversize_pct` —
  негабарит обеих моделей при фактическом q (новая — с текущим C(A));
  `rock_factor_correction` — C(A), при котором новая модель даёт
  фактический негабарит, или `null` и `note` («вне 0,1–10»).
- Итог: `rock_factor_correction` — среднее геометрическое по решённым
  строкам (или `null`), `used`, `skipped`.
- Решение — бисекция по ln C(A) на [0,1; 10], 80 итераций: это границы
  C(A) в настройках, найденное значение всегда можно сохранить. Ничего не
  сохраняет.

Оба запроса без привязки к организации, как нынешний `/blast/optimize`.

### Хранение за объектом работ

Необязательный блок `kuzram` в настройках листа (`calc-inputs`, JSONB
`blastex.calc_object_inputs.inputs`):

```json
"kuzram": {
  "rock_factor_method": "rmd50", "rock_factor_manual": 6,
  "joint_condition": 1, "joint_angle": 20, "rock_factor_correction": 1,
  "strength_exponent": "19/20", "drill_deviation_m": 0,
  "uniformity_correction": 1, "q_max_kg_m3": 2,
  "facts": [{ "crown_mm": 152, "q_kg_m3": 1.2, "oversize_pct": 6.5 }]
}
```

- `version` остаётся 1; блока нет — умолчания (прецедент
  `production_unit_code`). Значения при чтении приводятся к границам,
  неизвестные варианты — к умолчанию. Строки факта хранятся и незаполненными
  (значение `null`), не больше 50.
- Правка настроек модели увеличивает `optimizeGenerationRef` и перезапускает
  подбор; правка фактов подбор не трогает.
- Миграция не нужна; 50 строк фактов укладываются в лимит 32 КБ.

## Часть 3. Интерфейс

### Лист

- Надпись «Куз–Рам» в заголовке панели «Варианты сетки» становится кнопкой
  **«Модель Kuz-Ram»**; при отличии от умолчаний рядом краткая подпись
  («JF · C(A) 1,15»).
- В таблице вариантов у q значок «!» с подсказкой, если порог не достигнут.
- Справка «?» листа: обновлены определение q и описание модели, упомянута
  кнопка и раздел «Как пользоваться».

### Окно «Модель Kuz-Ram»

Нативный `<dialog>` + `showModal()`, как `CalcHelp`, шириной
min(1180px, 100vw − 32px), высотой до 90vh; на телефоне — одна колонка.
Две вкладки: **«Расчёт»** и **«Как пользоваться»**.

Вкладка «Расчёт»:

- Слева — настройки из таблицы части 1 и «Сбросить к умолчаниям»; поля JCF и
  JPA видны только при `joint_factor`, поле A — только при `manual`.
  Исходные данные (порода, ВВ, уступ, коронки) показываются строкой-сводкой
  и правятся только на листе.
- Справа:
  1. сводка по выбранной коронке: q и сетка «Kuz-Ram» и «До исправления»,
     негабарит, разница q в процентах;
  2. таблица по коронкам, выбор строки синхронизирован с листом;
  3. график q(d): две линии, полые точки при `reached = false`, ромбы факта,
     подсказка при наведении;
  4. разбор расчёта выбранной коронки для обеих моделей;
  5. фактические взрывы: таблица с правкой на месте, «Добавить взрыв»,
     «Подобрать C(A) по факту» — записывает C(A) в настройки объекта и
     сообщает, по скольким строкам посчитано.
- Правка применяется сразу; пока идёт пересчёт, прежние цифры приглушены и
  видно «Пересчёт…». Неверное значение подсвечивается с понятным текстом, в
  расчёт идёт последнее верное.

Вкладка «Как пользоваться» — справочный раздел:

1. **Что делает модель** — простыми словами: как подбирается q, что такое
   x50, n, негабарит, откуда формулы.
2. **Порядок работы** — исходные данные на листе → способ A → сравнение с
   «До исправления» → фактические взрывы → «Подобрать C(A)» → проверка сетки
   → «Перенести в проект» или «Сохранить паспорт».
3. **Настройки** — по каждой: что это, когда менять, умолчание, границы.
   Отдельно — как выбрать способ A: без достоверных данных о трещиноватости и
   ориентации трещин оставлять «монолитный массив (RMD 50)» и уточнять C(A)
   по факту; JF — только при надёжной документации трещин.
4. **Как читать результаты** — столбцы, значок «!», разбор расчёта, «сырое →
   принятое» у n.
5. **Примеры** с цифрами:
   - базовый расчёт: габбро-диабаз, ЭВЕРСИН Э-100, кусок 400 мм, 5 %,
     коронка 152 мм — q и сетка обеих моделей;
   - калибровка: три условных фактических взрыва (явно помечены как
     условные) → C(A) → как изменились q и сетка;
   - выбор способа A: те же данные при RMD 50, RMD 10 и JF — почему q так
     различается и почему без данных о трещинах лучше RMD 50 + C(A);
   - «порог не достигнут»: крупная коронка на низкой границе q — что делать
     (поднять границу, взять меньшую коронку, проверить порог).
6. **Формулы и источники** — раскрывающийся блок с формулами части 1 и
   ссылкой на Каннингема 2005.

Цифры примеров хранятся в `frontend/src/pages/calc/kuzram/helpExamples.json`
(входы и ожидаемые результаты); вкладка берёт их оттуда, а Python-тест
пересчитывает каждый пример моделью и сверяет с JSON. Модель изменится —
тест упадёт, справка не разойдётся с расчётом.

## Риски

- q оптимизатора нигде не сохраняется: после выкатки сетка на каждом
  объекте при открытии пересчитается по новой модели. Смягчение: столбец
  «До исправления», справка, сообщение команде при выкатке.
- До отдельной задачи прогноз дробления на «Проектировании» и в отчётах
  считается по старой модели и расходится с листом «Расчёт».
- Способ JF и RMD 10 дают сильно отличающийся q, а данных по трещинам нет:
  умолчание RMD 50, справка советует калибровать C(A) по факту.

## Критерии готовности

- Лист «Расчёт» подбирает q по новой модели; на примере габбро-диабаза,
  152 мм — 1,26 кг/м³, сетка 4,42 × 3,54 м.
- Окно «Модель Kuz-Ram» открывается с листа, настройки сохраняются за
  объектом и переживают перезагрузку.
- «До исправления» совпадает с нынешним `Blast.py`.
- Подбор C(A) по фактическим взрывам записывает поправку и пересчитывает
  варианты.
- Вкладка «Как пользоваться» содержит разделы и примеры, цифры примеров
  проверяются тестом.
- Все тесты зелёные; оба PR прошли `/code-review`.
