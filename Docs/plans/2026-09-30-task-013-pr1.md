# TASK-013 PR 1 — чтение чертежа и роли слоёв: план реализации

> **Для агентов-исполнителей:** обязательный навык — superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans. Шаги отмечаются чекбоксами (`- [ ]`).

**Цель:** DXF/DWG маркшейдера читается целиком: линии, точки, знаки и подписи. Каждой сущности назначается роль по шаблону объекта, по правилам или по Z. Источник и роли хранятся в PostgreSQL. Диалог «Импорт чертежа» заменяет «Бровки из чертежа»: в нём есть холст и шаг «Слои». Кнопка «Построить блок» до PR 2 работает по-старому.

**Архитектура:**
- Чистая логика живёт в новом пакете `design/spatial/cad/`: модель сущности, чтение DXF, единицы, отметки из подписей, авторазметка. Пакет не знает о БД и API.
- Хранилище — `design/spatial/cad/repository.py`. Это модели SQLAlchemy на общей `Base` из `cost/v2/db_repository.py` плюс реализации Postgres и InMemory, по образцу `design/mass_blast_repository.py`.
- Сервис `api/services/cad_service.py` связывает чтение, разметку и хранилище.
- Роутер `api/routers/cad.py` отвечает по префиксу `/design/cad`.
- Фронт: папка `frontend/src/pages/design/cadImport/` — диалог, холст на SVG с камерой из `lib/geometry2d.ts`, шаг «Слои» и справка.

**Стек:** Python 3.11, ezdxf ≥ 1.4, SQLAlchemy 2 и Alembic, FastAPI. React и TypeScript, vitest с @testing-library. Новых зависимостей нет.

**Спека:** `TASK-013 — Импорт маркшейдерского чертежа….md` (корень репозитория; в git его нет): §2 «Чтение чертежа», «Роли слоёв и шаблон маркшейдера», «Хранение», «Диалог»; §3 PR 1; §4.

## 6. Модель данных и API

**Роли** (`design/spatial/cad/model.py`, код → подпись):

| Код | Подпись | К чему применима |
|---|---|---|
| `block_contour` | Контур блока | линии |
| `design_line` | Проектная линия | линии |
| `crest_top` | Бровка верхняя | линии |
| `crest_bottom` | Бровка нижняя | линии |
| `feature_line` | Характерная линия | линии |
| `contour_line` | Горизонталь | линии |
| `spot_heights` | Отметки поверхности | точки, знаки, 3D-линии |
| `situation` | Ситуация | всё |
| `ignore` | Не использовать | всё |

- Роль только для слоя: `crests_by_z` — «Бровки (по Z)».
- Происхождение: `template` — «шаблон», `auto` — «авто», `z` — «по Z», `manual` — «вручную».
- Роль слоя, неприменимая к сущности, заменяется совместимой. Точка с Z на слое бровок получает `spot_heights`, точка без Z — `situation`. Подписи (TEXT/MTEXT) наследуют «точечную» роль слоя.

**`CadEntity`:**
- Поля: `handle`, `layer`, `kind` (`LWPOLYLINE`, `POLYLINE2D`, `POLYLINE3D`, `LINE`, `ARC`, `CIRCLE`, `ELLIPSE`, `SPLINE`, `POINT`, `INSERT`, `TEXT`, `MTEXT`), `geometry` (`{"points": [[x, y, z], …]}` для линий, `{"point": [x, y, z]}` для точек и знаков, `{"point": …, "text": …, "height": …}` для подписей), `closed`, `closed_by_gap`, `vertex_count`, `length_m`, `z_kind` (`const`, `variable`, `zero`), `z_min`, `z_max`, `z_from_label`, `label_handle`, `color` (`#rrggbb`, по слою, если BYLAYER), `role`, `role_origin`.
- Геометрия — мировые координаты, уже умноженные на `scale`.

**`CadDrawing`:** `entities`, `layers` (имя → цвет), `insunits`, `extent`, `format` (`dxf`/`dwg`), `minimal_dxf`, `warnings` (`[{code, message, level}]`), `suggested_scale`.

**Константы `reader.py`:**
- `CLOSURE_TOLERANCE_M = 0.5` — допуск по умолчанию из §2. Замкнута по разрыву — только при ≥ 3 различных вершинах и разрыве ≤ 5 % длины.
- `DUPLICATE_TOLERANCE_M = 0.001`.
- `CURVE_SAGITTA_M = 0.05` (вопрос 4).
- `CONST_Z_TOLERANCE_M = 0.005`.
- `MAX_ENTITIES = 50_000`, `MAX_VERTICES = 1_000_000`: превышение — ошибка с числами, не обрезка.
- `SIGN_BLOCK_SIZE_M = 5.0`.

**Подписи (`labels.py`):**
- Z берётся из подписи, если у точки или знака Z = 0.
- Подпись — ближайший числовой TEXT/MTEXT в радиусе `label_radius_m` (по умолчанию 3 м). Приоритет у своего слоя; каждая подпись достаётся не более чем одной точке, по возрастанию расстояния.
- Число: `+?\d{1,5}([.,]\d{1,3})` или `+\d{1,5}`. Номер блока «66» отметкой не считается.
- Подпись без точки не используется.

**Единицы (`units.py`):**
- Сторона экстента > 20 000 → предупреждение «Похоже на миллиметры», `suggested_scale = 0.001`.
- `$INSUNITS` ∈ {мм, см, дюйм, фут} при экстенте в метрах → заметка «В файле указаны …, размеры похожи на метры — читаем в метрах».
- `$INSUNITS` нет (минимальный DXF) → заметка «единицы не указаны».

**Разбиение бровок по Z (`roles.py`):**
- Для каждой сущности z_ref = медиана Z вершин.
- Подошва: параметр `floor_z_m`, иначе число из имени слоя (`горизонт|гор.` + `[+−-]?\d{2,4}`).
- Высота уступа H: параметр `bench_height_m`. Фронт берёт его из паспорта (`crest_z − toe_z` текущего блока), иначе 10 м.
- Правило: нижняя, если z_ref ≤ подошва + H/2, иначе верхняя.
- Подошвы нет → разрез по наибольшему разрыву z_ref ≥ 2 м. Разрыва нет → все верхние и предупреждение «задайте отметку подошвы».
- Блок 66: подошва 410, порог 415 → нижние 733, 73B, 753, 75A, остальные 19 — верхние.

**Порядок разметки слоя:**
1. Шаблон объекта, если в нём есть ключ слоя.
2. Правила по имени и типу («авто»):
   1. «блок» + (номер или «границ») и замкнутая линия → `block_contour`; открытые линии слоя → `design_line`.
   2. «верхн… бровк» → `crest_top`; «нижн… бровк» → `crest_bottom`.
   3. `горизонт(?!ал)` или `бровк` и есть линии с `variable` Z → `crests_by_z`.
   4. `горизонтал|изолин` → `contour_line` для линий с `const` Z, остальные линии слоя → `feature_line`.
   5. Слои рельефа (`рельеф|съ[её]мк|отметк|пикет|высот|survey|topo`) → точки и 3D-линии `spot_heights`, остальные линии — `feature_line`.
   6. Любые точки и знаки с Z → `spot_heights`.
   7. Остальное → `situation`.
3. Ручные переопределения сущностей (`manual`) переживают повторный разбор.
