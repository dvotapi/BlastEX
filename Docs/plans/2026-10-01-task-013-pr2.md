# TASK-013 PR 2 — контур блока: план реализации

> **Для агентов-исполнителей:** обязательный навык — superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans. Шаги отмечаются чекбоксами (`- [ ]`).

**Цель:** из ролей, размеченных в PR 1, окно «Импорт чертежа» получает простой замкнутый контур блока одним из четырёх способов:

- готовый контур;
- щелчок внутри;
- сборка из участков;
- блок по бровке.

По контуру строятся два контура с общими тылом и флангами: по верхней бровке (S верх) и по нижней (S низ). Рёбра вдоль верхней бровки помечаются свободной поверхностью. Результат уходит в паспорт кнопкой «Построить блок». Режим «полоса между двумя бровками» удаляется целиком.

**Архитектура:**
- Геометрия — чистые модули в `design/spatial/cad/` на shapely ≥ 2. Они ничего не знают о БД и API:
  - `rings.py` — нормализация и проверки кольца;
  - `stitch.py` — сшивка фрагментов;
  - `contour.py` — четыре способа контура;
  - `two_contours.py` — свободная поверхность, нижний контур, площади, отметки уступа.
- Сервис `api/services/cad_contour_service.py` читает сущности источника (с изоляцией по организации) и зовёт геометрию.
- Роутер `api/routers/cad.py` получает два новых маршрута.
- Фронт делает только взаимодействие: привязку курсора, выбор участка щелчком, список участков. Кольцо, проверки, площади и свободную поверхность считает сервер: предпросмотр идёт запросом на каждое изменение.

**Стек:**
- Python 3.11, shapely ≥ 2 (новая зависимость), ezdxf, FastAPI;
- React и TypeScript, vitest.

Миграций Alembic нет: паспорт живёт в JSON `data/teams`, новых таблиц не нужно.

**Спека:** `TASK-013 — Импорт маркшейдерского чертежа….md` в корне основного чекаута. Используются §2 «Модель блока и контур», «Хранение», «Диалог», §3 PR 2 и §4. Память между PR — `Docs/plans/TASK-013-progress.md`, описание для разработчика — `Docs/CAD_IMPORT.md`.

## 4. На что смотреть ревью (входы, о которых спека молчит)

1. **Координаты МСК** (1,47·10⁶): контур, сдвинутый на (7 000 000; 500 000), даёт те же площади (± 0,01 м²), ту же валидность и ту же свободную поверхность. Тесты — в задачах 2 и 4.
2. **Стыки с микрозазором** 0–5 см и повтор точки на стыке: ни ложного «ребро короче 0,05 м», ни «самопересечения». Ошибка, если есть, показывает место. Тесты — в задачах 2 и 4.
3. **Самопересечение из-за замыкающего отрезка или восьмёрка** при сборке: ошибка с точкой, кнопка неактивна, красный маркер на холсте. Тесты — в задачах 4 и 10.
4. **Пустые и вырожденные входы:**
   - нет верхней бровки → нет свободной поверхности, S низ = S верх и предупреждение;
   - нет нижней бровки → «откос не учтён»;
   - фланг не доходит до нижней бровки;
   - щелчок вне областей;
   - роли без линий;
   - готовый контур с разрывом больше допуска;
   - одна точка в сборке.

   Каждый случай — понятная ошибка или предупреждение. Тесты — в задачах 4–6.
5. **Большой чертёж:** тысячи линий выбранных ролей. Предел сегментов с ясной ошибкой, без зависания. Предпросмотр не заваливает сервер: запрос через 250 мс после последнего изменения, устаревшие ответы отбрасываются. Тесты — в задачах 4 и 9.

## 6. Модель и API

### Константы (`design/spatial/cad/…`)

| Константа | Значение | Где |
|---|---|---|
| `DEDUP_TOLERANCE_M` | 0,01 — дубли и коллинеарные вершины (§2) | `rings.py` |
| `MIN_EDGE_M` | 0,05 — ребро короче — ошибка (§2) | `rings.py` |
| `DEFAULT_TOLERANCE_M` | 0,5 = `reader.CLOSURE_TOLERANCE_M` — стыковка и автозамыкание | `contour.py` |
| `DEFAULT_BRIDGE_M` | 5,0 — мост при щелчке внутри (Р1) | `contour.py` |
| `MAX_CONTOUR_SEGMENTS` | 20 000 отрезков линий выбранных ролей | `contour.py` |
| `STITCH_GAP_M`, `STITCH_MAX_TURN_DEG`, `COINCIDENT_M`, `GAP_REPORT_M` | 1,0; 60; 0,01; 5,0 (Р2) | `stitch.py` |
| `FREE_FACE_DISTANCE_M` | 1,0 (§2) | `two_contours.py` |
| `FLANK_BACKSTEP_M`, `FLANK_MAX_EXTENSION_M` | 5,0; 100,0 (Р3) | `two_contours.py` |
| `BENCH_HEIGHT_RANGE_M` | (2, 25) (Р10) | `two_contours.py` |

### Геометрические типы

- `XY = tuple[float, float]`.
- `RingIssue(code, message, point: XY | None)`. Коды:
  - `too_few_points`, `not_closed`;
  - `self_intersection` — сообщение «Контур пересекает сам себя в точке X; Y», координаты в метрах объекта;
  - `zero_area`;
  - `short_edge` — «Ребро N короче 0,05 м (0,03 м) у точки X; Y»;
  - `invalid` — прочие причины `explain_validity` с переводом;
  - `outside` — щелчок не внутри замкнутой области;
  - `not_on_crest` — точки блока по бровке не лежат на одной сшитой верхней бровке;
  - `side_required` — нижней бровки нет, сторону блока надо указать.
- `ContourItem` — участок сборки, три вида:
  - `part` — `handle`, `start_m`, `end_m`: отрезок полилинии по длине в плане от её начала; `flip: bool` — «развернуть» против автовыбора;
  - `segment` — `start: XY`, `end: XY`: прямой отрезок от вершины к вершине;
  - `polyline` — `points: list[XY]`, `label`: построенная линия, например тыл блока по бровке.
- `ItemInfo` — `layer`, `length_m`, `reversed`, `gap_to_next_m`, `link` (`joined` — стык ≤ допуска, `closing` — замыкающий отрезок).
- `ContourDraft` — `ring: list[XY] | None` (уже нормализовано: против часовой, без дублей), `items` (с фактическим направлением), `item_info`, `closings: list[tuple[XY, XY]]`, `issues`.
- `StitchedLine` — `points` (XYZ), `parts: list[(handle, reversed, start_m, end_m)]`.
- `StitchGap` — `a`, `b`, `distance_m`, `reason` (`gap` — разрыв больше 1 м; `turn` — излом больше 60°).
- `TwoContours`:
  - `top`, `bottom: list[XY] | None`;
  - `free_faces: list[tuple[int, int]]`;
  - `flanks: list[Flank(start, end, length_m | None)]`;
  - `area_top_m2`, `area_bottom_m2`, `area_mean_m2`, `perimeter_top_m`;
  - `warnings`.
- `BenchLevels` — `crest_z_m`, `toe_z_m`, `crest_source`, `toe_source`, `warnings`.
  - Бровка — медиана Z вершин верхней бровки не дальше 1 м от свободных рёбер; без свободных рёбер — верхних бровок в полосе 5 м вокруг контура.
  - Подошва — `params.floor_z_m`, иначе подошва из имени слоя (`summary.floor_z_m`), иначе медиана нижней бровки.

### API (`/api/v1/design/cad`)

| Метод и путь | Тело | Ответ |
|---|---|---|
| `POST /sources/{id}/contour/lines` | `{roles: [..] = [block_contour, design_line, crest_top]}` | `CadContourLinesResponse`:<br>• `splits: {handle: [м, …]}` — места разреза линий выбранных ролей в пересечениях;<br>• `intersections: [[x, y]]`;<br>• `crests_top`, `crests_bottom: [{points, parts}]` — сшитые бровки;<br>• `gaps: [{a, b, distance_m, reason}]` |
| `POST /sources/{id}/contour` | `CadContourRequest`:<br>• `method`: `ready`, `click`, `assembly` или `crest`;<br>• `handle?`, `point?`, `roles`, `items`;<br>• `crest: {start, end, width_m, side: auto/left/right}`;<br>• `tolerance_m = 0.5`, `bridge_m = 5` | `CadContourResponse`:<br>• `ok`, `issues`, `warnings`;<br>• `top: {points, area_m2, perimeter_m}`, `bottom: {points, area_m2} \| null`, `mean_area_m2`;<br>• `free_faces`, `flanks`, `closings`, `items`, `item_info`;<br>• `bench: {crest_z_m, toe_z_m, height_m, crest_source, toe_source}` |

- Ответ `/contour` всегда возвращает `items`: результат любого способа можно «Править как сборку».
- Ошибки:
  - неизвестный handle или роль → 422;
  - чужой или несуществующий источник → 404;
  - больше `MAX_CONTOUR_SEGMENTS` отрезков → 422 «Линий выбранных ролей слишком много (N отрезков, предел 20 000) — снимите лишние роли».
- Проблемы контура — не HTTP-ошибка, а `ok = false` и `issues`: предпросмотр показывает их у кнопки.

### Поле паспорта `contour.cad`

- `source_id`, `file_name`, `method`, `items`.
- `top: [[x, y]]`, `bottom: [[x, y]] | null`.
- `area_top_m2`, `area_bottom_m2`, `area_mean_m2`, `map_area_m2 | null`.
- `built_at`, `edited: bool`.

Бэкенд: `BlockContour.cad: dict | None`. В `to_dict` ключ пишется, только если поле не `None`. Схема: `BlockContourSchema.cad: CadContourInfoSchema | None = None`. Фронт: `BlockContour.cad?: CadContourInfo | null`.

### Задача 4. Способы контура: готовый, сборка, щелчок внутри

**Файлы:** `design/spatial/cad/contour.py`, `tests/test_cad_contour.py`, `tests/test_cad_block66_contour.py`.

**Интерфейс:**
- `split_lines(lines) -> tuple[dict[str, list[float]], list[XY]]` — места разреза по длине и точки пересечений. Поиск через `STRtree`; предел `MAX_CONTOUR_SEGMENTS` → `ContourInputError`.
- `ready_contour(entity, tolerance_m) -> ContourDraft`. Разрыв концов ≤ допуска замыкается, больше → `not_closed` «Линия не замкнута: разрыв N м — соберите контур из участков».
- `assemble(items, lines: dict[str, CadEntity], tolerance_m) -> ContourDraft`:
  - первый участок ориентируется по ближайшему концу второго, каждый следующий — по ближайшему концу к концу цепочки (§2);
  - `flip` разворачивает;
  - стык ≤ допуска сводит концы в среднюю точку (Р7), больше — замыкающий отрезок;
  - от последнего участка к первому — так же.
- `click_contour(lines, point, tolerance_m, bridge_m) -> ContourDraft`:
  - концы ≤ допуска сводятся;
  - висячие концы соединяются мостом с ближайшим висячим концом на расстоянии ≤ `bridge_m` (Р1);
  - затем `unary_union` → `polygonize`, берётся грань, содержащая точку;
  - дырки грани отбрасываются с предупреждением;
  - точка вне граней → `issue` «Щелчок не внутри замкнутой области…».

  В `items` возвращаются участки границы грани и мосты-отрезки.

**Тесты:**
- [ ] Готовый: замкнутая линия → кольцо. Разрыв 0,4 м → замкнута. Разрыв 0,8 м → `not_closed`.
- [ ] Сборка из двух частей и отрезка:
  - направление выбирается по ближайшему концу;
  - `flip` меняет направление и даёт `self_intersection`, если так и должно быть;
  - стык 3 см не рождает ребра 3 см;

- [ ] Сборка из одного участка-незамкнутой линии → замыкающий отрезок от конца к началу. Пустой список → `too_few_points`.

### Задача 5. Блок по бровке

**Файлы:** `design/spatial/cad/contour.py` (функция `crest_block`), `tests/test_cad_crest_block.py`.

**Интерфейс:**


### Задача 6. Два контура, свободная поверхность, отметки уступа

**Файлы:** `design/spatial/cad/two_contours.py`, `tests/test_cad_two_contours.py`, `tests/test_cad_block66_contour.py`.

**Интерфейс:**
- `free_face_edges(ring, top_lines) -> list[tuple[int, int]]`: ребро, всё лежащее не дальше 1 м от верхних бровок (Р5).
- `two_contours(ring, top_lines, bottom_lines) -> TwoContours`:
  - серии свободных рёбер — откосы;
  - фланги у их концов продлеваются лучом (Р3) до первой встречи со сшитой нижней бровкой;
  - нижний контур = несвободная цепочка + продления + кусок нижней бровки между точками встречи;
  - серий несколько — каждая заменяется своим куском.
- Особые случаи:
  - нет нижней бровки → `bottom = top` и предупреждение «Нижней бровки нет — откос не учтён: S низ = S верх» (§2);
  - нет верхней бровки или свободных рёбер → `bottom = top` и «Верхней бровки вдоль контура нет — свободная поверхность и откос не найдены»;
  - луч не встретил бровку за 100 м → `bottom = top` и «Фланг у точки X; Y не доходит до нижней бровки»;
  - нижний контур не валиден → `bottom = top` и предупреждение с причиной.
- `bench_levels(ring, free_faces, top_lines, bottom_lines, floor_z) -> BenchLevels`:
  - H вне 2–25 м → предупреждение «Высота уступа N м вне 2–25 м — проверьте подошву» (Р10);
  - в `warnings` также «Отметка бровки не найдена — оставлена отметка паспорта», если верхней бровки у контура нет.

**Тесты:**
- [ ] Прямоугольник 40 × 20, верхняя бровка вдоль восточной стороны, нижняя в 4 м восточнее и длиннее → свободна одна восточная сторона. S низ = 40 × 24, фланги по 4 м.

- [ ] Без нижней бровки, без верхней, луч мимо → S низ = S верх и нужное предупреждение.
- [ ] Ребро, касающееся бровки только концом, свободным не считается.
- [ ] Блок 66:
  - 6 несвободных рёбер общей длиной 186,45 ± 0,05 м — запад, север, юг; остальные 27 свободны (§3, Р5);

## 8. Риски

1. **Ошибка «ребро короче 0,05 м» на реальных линиях.** Контуры и бровки маркшейдеров бывают с рёбрами в 1–5 см. Ошибка показывает место, но исправить её в окне нельзя. Если на реальных файлах это будет мешать, предложу «Упростить контур» (удаление таких вершин). В PR 2 держусь §2.
2. **Направление фланга (Р3) — эвристика.** Для блоков с коротким флангом (< 5 м до тыла) берётся вся несвободная цепочка до тыла. Длина продления видна пользователю, промах луча даёт предупреждение.
3. **Площадь карты блока 66 ≈ S верх, а не S ср (Р4).** Это не ошибка кода, а открытый вопрос §5 к маркшейдеру. В описании PR — цифры.
4. **Предпросмотр запросом.** Нагрузка на API растёт с каждым действием в сборке: задержка 250 мс, небольшой ответ без сущностей, сущности читаются с фильтром по ролям и handle.
5. **SVG-холст с наложением.** Наложение — десятки путей, базовый слой не перерисовывается. Большой чертёж — задача PR 4.
6. **Хэш утверждённых паспортов.** Обеспечен тем, что ключа нет, пока поля нет (тест задачи 8). Если PR 3 поменяет формат `cad`, ему нужна та же осторожность.
