# TASK-013 PR 3 — поверхность, подошва, длины скважин: план реализации

> **Для агентов-исполнителей:** обязательный навык — superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans. Шаги отмечаются чекбоксами (`- [ ]`).

**Цель.** Окно «Импорт чертежа» строит кровлю блока: одну TIN с ограничениями по отметкам и линиям чертежа. Бровки в этой TIN — жёсткие ограничители. Подошва — проектная отметка числом. По кровле и подошве автоматически считаются:
- отметка устья и длина каждой скважины;
- объём блока.

Ручная правка длины или отметки устья помечается и пересчётом не затирается. В окне появляются шаги «Поверхность» и «Итог», «Построить блок» ставит кровлю в паспорт.

**Архитектура.**
- **Геометрия** — чистые модули в `design/spatial/cad/`:
  - `surface_data.py` — данные поверхности по ролям, конфликты отметок, отсечение по буферу;
  - `surface_builder.py` — интерфейс `SurfaceBuilder` и два пути: CDT (PythonCDT) и запасной scipy;
  - `surface.py` — порядок построения, защита плоских треугольников, граница, метрики качества, выбросы, пороги, объём.
- **Длины скважин** — `design/geometry.py` и новый `design/hole_recompute.py`. Это одна формула для генерации сетки, правок и автоматического пересчёта.
- **API:**
  - `POST /design/cad/sources/{id}/surface` — предпросмотр кровли;
  - `POST /design/holes/recompute` — пересчёт устьев и длин по кровле и подошве паспорта.
- **Фронт.** Шаги «Поверхность» и «Итог» в `cadImport/`. Автопересчёт скважин — эффект на странице «Проектирование» по изменению кровли, подошвы, перебура и сетки: запрос через 300 мс после последнего изменения, устаревшие ответы отбрасываются. Флаги в «Здоровье скважин», итоги в строке показателей.

**Стек.**

## 1. Разведка

**PythonCDT.**
- Релизов на PyPI нет. В репозитории (`artem-ogre/PythonCDT`, MPL-2.0) последний тег 1.4.5. Master от 20.09.2026 (`30f955d`) переведён на CDT 2.0.0.
- Сборка: setuptools + CMake + pybind11 (подмодули). `cmake` и `ninja` приходят колёсами через build isolation, нужен только компилятор C++ и git (для подмодулей).
- Локально (macOS arm64, Python 3.13) колесо собирается за 26 с.
- API проверено:
  - `Triangulation(VertexInsertionOrder.AUTO, IntersectingConstraintEdges.TRY_RESOLVE, 0.0)`;
  - `insert_vertices(N×2)`, `insert_edges(E×2 uintc)`, `erase_super_triangle()` / `erase_outer_triangles_and_holes()`;
  - `triangles_array()` (поле `vertices`), `vertices_array()` (`x`, `y`);
  - `piece_to_originals` — какие исходные рёбра дали кусок после разрешения пересечений.

**Docker и CI.**
- Docker собирается в несколько этапов. В builder есть `build-essential` (g++), git и cmake нет. Runtime копирует site-packages из builder, компилятора в нём нет.
- CI ставит `requirements-api.txt` (то есть `requirements.txt`) через pip прямо на раннере Ubuntu: там есть g++ и git.

**Паспорт сейчас.**
- `surfaces` — `SurfaceSet` с видами `top / floor / face / post_blast` (`design/spatial/surfaces.py`). TIN — `design/spatial/tin.py`:
  - чистый Python, Bowyer–Watson O(n²);
  - до 2500 точек;
  - ограничителей нет.
- `surfaces` и `holes` входят в `designed_sha256`. Новые поля пишутся только когда они заданы, как `contour.cad`.
- Отметка устья — `geometry.collar_elevation`: TIN кровли, вне её — `bench.crest_z_m`.
- Длина — `geometry.hole_depth_m`, перебур откладывается **вдоль оси**: L = (S − Z)/cos α + Δ. От этого зависят `Hole.bench_height_m` и заряжание.
- Скважины пересчитываются только при генерации сетки. Фронт длины не считает. Флагов ручной правки нет: `source: manual` означает «вставлена вручную».
- Объём — `geometry.block_volume`:
  - сеточный интеграл кровля − подошва по `contour.vertices` (контур по верхней бровке);
  - без кровли — площадь × H.

  Объём уходит в паспорт, отчёты, смету «Проектирования» (`_design_to_hole_and_block`) и массовый взрыв. На странице он виден только после генерации сетки, после открытия паспорта стоит «—».

## 2. Вопросы владельцу (ответ нужен до реализации)

1. **Перебур: по вертикали или вдоль оси?**
   - Формула спеки — по вертикали: L = (S − Z + Δ)/cos α.
   - Код и заряжание сейчас — вдоль оси: L = (S − Z)/cos α + Δ.
   - При α = 10° и Δ = 1 м разница 1,5 см. Тест спеки «при α = 10° — делённые на cos α, ± 0,01 м» написан под вертикаль.
   - Переход на вертикаль меняет и `Hole.bench_height_m`, то есть высоту уступа для зарядов наклонных скважин у существующих паспортов при пересчёте.
   - **Предлагаю оставить вдоль оси**: так и сейчас, и как в справочниках — перебур откладывается по скважине. Формулу спеки поправить, тест — под неё.
2. **Объём блока.**
   - Спека считает объём между кровлей и подошвой внутри контура **по нижней бровке**. Код сейчас считает по контуру по верхней бровке.
   - **Предлагаю:** `block_volume` берёт `contour.cad.bottom`, если он есть и контур не правили после построения (`cad.edited` = false), иначе — как сейчас. Новый объём уходит в паспорт и смету «Проектирования» — это нужная правка, а не побочный эффект.
   - Паспорта без `contour.cad` не меняются.
3. **«Построить блок» и поверхности.**
   - Кнопка ставит кровлю из чертежа в `surfaces.top` и **снимает** `surfaces.floor`, если он был. Подошва — проектная отметка числом (`bench.toe_z_m`). Наклонная подошва и подошва поверхностью — вне задачи.
   - Подтверждение «заменит контур…» перечисляет, что сменится.
   - Подходит?
4. **PythonCDT в зависимостях.**
   - Строка `PythonCDT @ git+https://github.com/artem-ogre/PythonCDT@<sha>` в `requirements.txt`, коммит закреплён.
   - Колесо собирается из исходников: в Docker-образе на этапе builder (+ `git`; около 30 с), в CI — на раннере (около 30–60 с к прогону), локально — так же. Тогда оба пути `SurfaceBuilder` проверяются тестами везде.
   - Путь выбирает переменная `BLASTEX_SURFACE_BUILDER=cdt|scipy`, по умолчанию `cdt`. Без установленного PythonCDT — `scipy` и предупреждение в журнале.

## 4. На что смотреть ревью (входы, о которых спека молчит)

1. **Координаты МСК** (1,5·10⁶): кровля, отметки устьев и объём при сдвиге на (7 000 000; 500 000) те же (± 1 мм по Z, ± 0,01 % по объёму). Вся работа — в локальной системе `LocalFrame`.
2. **Вырожденные входы:**
   - нет отметок → плоскость по средней Z верхней бровки с предупреждением;
   - нет верхней бровки → предупреждение «первый ряд без бровки»;
   - все точки на одной прямой;
   - дубли точек с разной Z;
   - отметка ровно на ограничителе;
   - ограничитель из одной точки.
3. **2D-линии (Z = 0)** в роли бровки или характерной линии: Z = 0 — отметки нет. Такие бровки — ограничители без собственной Z, отметка берётся по близости, как у характерной линии без Z.
4. **Большие входы:** тысячи отметок и горизонталей карьера вдали от блока отсекаются буфером до триангуляции. Предпросмотр — не дольше 1 с на блоке 66 и не дольше 5 с на 50 000 точках.
5. **Пересчёт скважин:**
   - ручная правка не затирается;
   - скважины с явной глубиной (контурные, предщелевые, заоткосные, stab — те, у кого в параметрах сетки задана своя глубина) сохраняют длину, двигается только устье;
   - отключённые скважины пересчитываются так же;
   - устаревший ответ пересчёта не применяется.
6. **Хэш:** открытие и сохранение старого паспорта без кровли из чертежа не меняет `designed_sha256`.

## 6. Модель и API

### Константы

| Константа | Значение | Откуда |
| --- | --- | --- |
| `SURFACE_BUFFER_M` | 20 | буфер вокруг контура (§2) |
| `MAX_EDGE_M` | 30 | рёбра длиннее отбрасываются (§2) |
| `CREST_STEP_M` | 1 | вершины бровок через ≤ 1 м (§2) |
| `CONTOUR_STEP_M` | 2 | точки горизонталей через 2 м (§2) |
| `CONFLICT_REPORT_M` | 0,2 | расхождение Z ограничителей в список качества (§2) |
| `SNAP_TO_CONSTRAINT_M` | 0,1 | точка ближе к ограничителю с другой Z берёт его Z (§2) |
| `OUTLIER_M` | 1,5 | выброс: отклонение от соседей (§2) |
| `THRESHOLD_M` | 0,5 | нижняя бровка выше подошвы → возможный порог (§2) |
| `SHORT_BENCH_M` | 1 | H < 1 м у скважины → флаг (§2) |
| `MAX_SURFACE_POINTS` | 50 000 | предел точек в буфере |

Приоритет Z на пересечении ограничителей: верхняя бровка > нижняя бровка > характерная линия > горизонталь > точка.

### Модель

- `SurfaceModel.cad: dict | None` — определение кровли из чертежа:
  - `source_id`, `file_name`;
  - роли в поверхности, исключённые точки (handle);
  - путь построения (`cdt` / `scipy`);
  - качество (число отметок, покрытие %, наибольшее расстояние до отметки, число выбросов и конфликтов);
  - `built_at`.

  Пишется, только если задано.
- `Hole.manual: list[str] | None` — `"collar_z"`, `"length"`. Пишется, только если не пусто.
- `contour.cad.map_volume_m3: float | None` — объём с блоковой карты (ввод в «Итоге»).

### API

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/v1/design/cad/sources/{id}/surface` | Предпросмотр кровли. Запрос: контур (`top`, `bottom`), роли в поверхности, исключённые точки, подошва. Ответ: TIN (вершины x, y, z и треугольники), качество, выбросы (handle, место, отклонение), конфликты (место, Z по линиям, принятая Z), пороги (отрезки нижней бровки), средняя высота, объём по поверхностям, S ср × H, путь построения, предупреждения. Ошибки входа — 422, ошибки поверхности — в ответе. |
| POST | `/api/v1/design/holes/recompute` | Запрос: скважины, контур, поверхности. Ответ: скважины с новыми устьями и забоями (ручные — как есть), флаги по скважине (`outside_surface`, `short_bench`), объём блока. |

## 8. Риски

- **Сборка PythonCDT** в CI и Docker: нужна сеть к GitHub и компилятор. Если CI не соберёт колесо — запасной путь scipy и пропуск тестов CDT с причиной, сборка в Docker остаётся обязательной.
- **Размер паспорта:** кровля блока с буфером — тысячи вершин. Если больше 5000 вершин — предупреждение о размере. Прореживания нет: отметки маркшейдера не выбрасываются.
- **Автопересчёт:** запрос на каждое изменение. Устаревшие ответы отбрасываются, пересчёт не входит в историю отмены, поэтому отмена не «залипает».
- **Изменение отметки устья вне TIN** (ближайшая вершина вместо бровки) меняет значения у старых паспортов с кровлей при следующем пересчёте. Утверждённые паспорта заблокированы для правок.
