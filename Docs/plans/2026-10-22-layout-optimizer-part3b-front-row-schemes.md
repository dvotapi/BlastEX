# Первый ряд у откоса: вертикальная у кромки, пара, плавный переход — план переделки части 3

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Генератор сетки строит первый ряд у откоса по трём схемам владельца — вертикальная у кромки, пара (вертикальная + наклонная на 1 м ближе к уступу), плавный переход на 2 ряда с шагом b у подошвы — а проверки ловят разрыв между рядами у подошвы и устья ближе минимального отступа от кромки.

**Architecture:** Работа в ветке `feat/front-rows-tilt` поверх уже сделанного (азимут к откосу, местный ранг ряда, ограничение угла по ЛСП с целью 0,8·W, предупреждения «выходит в откос», «ЛСП меньше допустимого»). Режим наклона «устья по сетке, низ к откосу» заменяется двумя режимами: «пара» и «плавный переход». Новая проверка «расстояние между рядами у подошвы» — в `design/toe_line.py`/`design/analysis.py`. Новый вид скважины `face_toe` — в `design/models.py`.

**Tech Stack:** Python 3.13, shapely ≥ 2, numpy; React + TypeScript, vitest.

**Spec:** `Docs/specs/2026-10-21-block-layout-optimizer-design.md`, раздел «ЛСП» → «Первый ряд у откоса», «Проверки любой раскладки», «Нижняя граница ЛСП»; ограничение 4.

## Global Constraints

- Ключи `pattern_params` (пишутся только когда заданы; без них сетка побитно как `REFERENCE_SIGNATURE`):
  - `front_rows_mode` ∈ `"pair"`, `"taper"`; нет ключа и `front_rows_tilt_count > 0` — `"taper"` (совместимость с уже введёнными ключами); нет ни того, ни другого — вертикальный первый ряд как сейчас.
  - `front_rows_tilt_count` — для `"taper"`: 1 или 2 ряда перехода.
  - `front_rows_tilt_deg` — наибольший угол α, 0–30°, умолчание 15°.
  - `min_crest_offset_m` — минимальный отступ устья от кромки (верхней бровки), умолчание `MIN_CREST_OFFSET_DEFAULT_M = 1.0`.
- **Главное правило раскладки** (владелец 22.10.2026): зарядная машина заезжает поперечными заходками — скважины соседних рядов должны стоять на одной линии (столбцы сетки не смещаются вдоль ряда). Поэтому любые сдвиги устьев и наклоны первых рядов идут **вдоль линии столбца** — по нормали к рядам в сторону откоса; азимут наклона — то же направление (а не перпендикуляр к местному участку бровки). Прямизна ряда вдоль бровки вторична: излом ряда на ступени бровки допустим.
- **Пара** (`"pair"`): для скважин ранга 1, у которых ЛСП вертикальной больше W·1,03, добавляется скважина вида `face_toe` («Наклонная у откоса»): устье на 1 м (`FACE_PAIR_OFFSET_M = 1.0`) ближе к откосу по линии столбца, без смещения вдоль ряда; азимут — вдоль линии столбца к откосу; угол — наибольший ≤ α, при котором её ЛСП не меньше 0,8·W (и не меньше 1 м); если и при 0° её ЛСП ≤ W·1,03 — она вертикальная. Устье пары не ближе `min_crest_offset_m` к кромке — иначе пара не ставится. Вертикальная скважина первого ряда остаётся на месте.
- Вид `face_toe`: номер `"<id вертикальной>T"` (например `5-08T`), `row`/`col` — как у вертикальной; входит в ЛСП (у откоса — она, вертикальная за ней закрыта); не входит в сетку темпа отбойки (как stab/satellite); сохраняется при перегенерации так же, как сгенерированные (не ручные) — пересоздаётся; подпись в интерфейсе «Наклонная у откоса».
- **Плавный переход** (`"taper"`): один угол на участок ряда — чтобы ряды остались прямыми (желательно) и столбцы на одной линии (обязательно). Участок ряда — скважины одного ряда решётки с одним рангом, идущие подряд. Угол участка ранга 1: α₁ = наибольший угол ≤ α, при котором ни у одной его скважины ЛСП не меньше max(0,8·W, 1 м) и низ не выходит в откос (минимум по скважинам участка из уже сделанного ограничения). Скважина ранга 2 — α/2 от угла участка ранга 1 перед ней в её столбце (при `front_rows_tilt_count = 2`); остальные — вертикально (общий угол паспорта). Шаг b — у подошвы: устья скважин ранга k ≥ 2 сдвигаются вдоль линии столбца к откосу на H·(tg α₁ − tg α_k) (α_k = 0 для k > count, H — высота уступа блока), устья ранга 1 — на месте. Так каждый участок ряда остаётся прямым; излом ряда возможен только на ступени бровки, где ранг меняется вдоль ряда. Скважины, у которых ЛСП после этого больше W + 3 %, остаются с предупреждением — перебор выберет для них пару.
- Ранг ряда — местный (`front_row_ranks`, уже есть).
- **Проверки** (`validate`, для любой раскладки): 
  - `floor_row_gap_excess` — расстояние у подошвы от скважины до ближайшей скважины соседнего ряда впереди (в её коридоре, тот же `corridor_blockers`) больше b·1,03: «Между рядами у подошвы {v} м — больше допустимого {max} м (b + 3%).»
  - `collar_too_close_to_crest` — устье ближе `min_crest_offset_m` к кромке: «Устье {id} ближе {min} м к кромке уступа.»
- Режим «устья по сетке, низ к откосу без сдвига рядов» удаляется (недопустим по спецификации); его тесты переписываются под «плавный переход».
- Подписи: «Первый ряд у откоса» — «Вертикальный», «Пара: вертикальная + наклонная», «Плавный переход»; «Рядов перехода» (1/2); «Наибольший наклон, ° от вертикали»; «Мин. отступ устья от кромки, м». JSON пользователю не показывать.

## Review Focus

- Без ключей сетка побитно совпадает с `REFERENCE_SIGNATURE` — Task 1, Task 2.
- Плавный переход: расстояние между рядами у подошвы равно b (±1 см) для рядов 1→2→3 — Task 1.
- Пара не ставится, если устье пары оказалось бы ближе минимального отступа к кромке или за пределами контура — Task 2.
- Перегенерация сетки не плодит дубли `face_toe` и не теряет ручные скважины — Task 2.
- Ступенчатая бровка и разные углы по столбцам: устья каждого столбца остаются на одной линии (проекция на ось ряда не меняется), нумерация не ломается — Task 1.
