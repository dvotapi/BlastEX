# TASK-010 PR 3a — ФОТ по методике в экономике блока (бэкенд): план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** экономика блока считает ФОТ экипажа бурения по методике TASK-010 (приведённые метры, сдельная премия на плановом темпе, постоянная часть по плановым сменам станка), строит цену метра и проверяет долю экипажа в марже метра.

**Architecture:** новый модуль `cost/model/block_payroll.py` вызывается из `engine.py` до `labor.compute` и пишет строки `LABOR_<position>` с `price_origin="PAYROLL"`; `labor.compute` и `unit.compute` пропускают должности, уже посчитанные методикой (Т4). Формулы не дублируются: вызываются `payroll.piece_premium`, `payroll.payroll_month`, `payroll.premium_cost_factor`, `payroll.margin_check`. Режим выбирается параметром вкладки `payroll_source` (`RATES` по умолчанию — расчёт по ставкам не меняется).

**Tech Stack:** Python 3.13, Decimal, pydantic 2, FastAPI, pytest.

**Spec:** `Docs/specs/2026-09-13-task-010-payroll-decisions.md` (Т4, Т8, Т9, Т11, Т14; §2.1–§2.2; тест-план «Экономика блока (PR 3a)»); находки ревью fe9cb09 к экипажу превью (п. 1–5 в задачах 3 и 5); `Docs/PAYROLL_MODEL.md`, `Docs/COST_MODEL.md`.

## Вопросы владельцу (до старта)

1. **Какие должности идут по методике.** Рекомендую: только экипаж операций бурения (`PRODUCTION_DRILLING`, `CONTOUR_DRILLING`) — машинист и помощник. Остальные сдельщики (водитель за километр, ТОиР за тонну) остаются на ставках: приведённых метров у них нет, премию по шкале на метрах бурения им не посчитать. Другой вариант — все прямые должности пакета; тогда нужна выработка по `piece_driver`, это отдельная задача.
2. **Данные прода.** Спека (память 04.10): у помощника нет ставки без условия бурения — проверить чтением до слияния (ставка с условием даёт предупреждение, не ошибку, но премия может уйти на другую ставку).

## Global Constraints

- Нормы — только в `cost/model/`, цены — только в справочниках; `cost/model` не импортирует `cost.drilling` и `cost.strategies`.
- Всё в Decimal; отсутствующая запись справочника — предупреждение (`context.warn`) и нулевая строка, не исключение (CLAUDE.md, «Модель себестоимости блока»).
- Режим `RATES` не меняет ни одной цифры: `tests/test_model_regression_smeta_2026_01.py` проходит без правок (фикстуру `smeta_2026_01` не трогать, Т19).
- Постоянная часть экипажа — по плановым сменам станка; косвенного персонала — по плановому объёму юнита (Т11). Двойного ФОТ нет (Т4).
- Субподрядное бурение (`drilling_executor = SUBCONTRACTOR`) — методика и проверка доли не выполняются.
- Плановый темп — по строке матрицы условий бурения, k блока входит только в `M_блока` (Т9): строка f 17 / Ø 250 на базовой скорости 12 м/ч, непроизводительные 1 ч, смена 11 ч → `m_план = 120`, `M_блока = п.м. × 1,968`.
- Происхождение строк — `price_origin = "PAYROLL"`; код строки `LABOR_<position>` сохраняется (Т14).
- Интерфейс не меняется, кроме подписи нового происхождения (остальное — PR 3b). Пользователю не показывается JSON.
- `pytest`, `tsc -b`, `vitest run` — на чистом чекауте без iCloud-дублей.

## Review Focus

- Должности нет в справочнике / нет ставки / нет шкалы: строка не падает, предупреждение, должность остаётся на ставках (нет двойного ФОТ).
- В справочнике нет «Параметров ФОТ» года или объекта (`PayrollInputError`): блок считается по ставкам с предупреждением, не 500.
- Блок без бурения (`drilling_m = 0`) или без станка/нормы: методика молча не запускается, как `drilling.compute`.
- Порода строки матрицы без `hardness_f`, у коронки нет диаметра или диаметра нет в таблице: k = 1 и предупреждение с названием породы/коронки, а не ошибка.
- Явный экипаж без машиниста (вкладка, `crew_scale` ≠ 1, headcount 0): машинист добавляется, предупреждение; доля не выпадает молча.
- Маржа метра ≤ 0, цена не строится: `margin_check = null` и предупреждение; плановых смен станка нет — ротация `None`, оклад по норме смен.
- Сравнение `RATES` и `PAYROLL` на той же фикстуре расходится в разы (ротационная численность) — это ожидаемо только после PR 0b; цифры «до/после» в тело PR.
