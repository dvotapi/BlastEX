# TASK-015 PR 2 — PDF паспорта на бурение (форма v0.7)

> **Для исполнителя:** обязательный навык — superpowers:executing-plans (или
> superpowers:subagent-driven-development). Шаги — чекбоксы `- [ ]`.

**Цель:** `GET /design/drilling-passports/revisions/{rid}/passport.pdf` выдаёт
PDF по утверждённой форме v0.7 (стр. 1–3 полностью, стр. 4 — место под план
PR 3), собранный только из `drilling_passport_revisions.context`.

**Архитектура:** расчёт и снимок остаются в `design/drilling_passport.py`
(добавляются сетка, диаметр и тексты профиля в снимок). Новый пакет
`design/reporting/drill/` делится на две части: `layout.py` — чистая
раскладка снимка в страницы и строки (все строки PDF как данные, тестируется
без PDF), `pdf.py` — отрисовка раскладки ReportLab (как
`design/mass_blast_rendering.py`), `rig_scheme.py` — векторная схема
установки станка (`reportlab.graphics`). Тексты мер безопасности и
технологии бурения — новый раздел справочника Cost V2 «Профиль паспорта на
бурение»; при выпуске ревизии они копируются в снимок.

**Стек:** Python 3, ReportLab 4.5 (уже в `requirements.txt`), шрифт Roboto
(TTF в репозитории), FastAPI.

**Спека:** `TASK-015 — Паспорт на бурение PDF, DWG скважин, файл выноса для
GNSS.md` (корень основного чекаута), §0, §2–§3, §6, §8–§9; решения PR 1 —
`Docs/plans/TASK-015-progress.md`. Эталон вида — `ГР.05.01 Паспорт на
бурение — форма v0.7 (пример блок 66).pdf` (Яндекс.Диск, `_Проекты/`),
генератор — `_генератор/make_drill_form.py`, `draw_rig_simple.py`,
`jk830_side.py`.

## Решения, которые надо подтвердить (до кода)

1. **Рендер — ReportLab, а не Jinja2 + WeasyPrint.** Спека ссылается на рендер
   TASK-014 PR 3 (Jinja2 + WeasyPrint + `complex.css`), но его в репозитории
   нет. Единственный PDF в коде — ReportLab (`mass_blast_rendering.py`).
   WeasyPrint тянет системные Pango/Cairo в Docker. ReportLab даёт
   детерминированный файл (`invariant=1`) и вектор без SVG-посредника.
   Шаблонов `*.html.j2` не будет; если позже придёт общий HTML-рендер
   TASK-014, раскладка `layout.py` переедет к нему без изменений.
2. **Профиль — новый раздел справочника** `drill_passport_profiles`
   («Профиль паспорта на бурение»): 10 пунктов мер безопасности, строка
   «Основание: …», текст «Технология бурения». В payload паспорта —
   `profile_code`. Пусто — встроенный профиль с текстами §2.1 спеки, без
   предупреждения; код задан, но не найден — предупреждение
   `drill_profile_not_found` и встроенный профиль. Текст попадает в
   `context["profile"]` при выпуске ревизии — PDF справочник не читает.
3. **Числа — по-русски:** запятая и неразрывный пробел тысяч: «2 280,5»,
   «s = 2,0 м», «10,0 – 13,8». Эталон v0.7 печатает точки (так вывел Excel),
   спека §9 пишет «2 280,5». В таблице глубин — «11,6».
4. **Стр. 4 в PR 2** — заголовок «Графическая часть» и пустое поле с
   подписью «План расположения скважин — в следующей версии». Правило чётной
   страницы плана работает уже сейчас; PR 3 подставит план в это поле.
5. **Golden-тест** против эталона v0.7 растром с порогом 2 % невыполним:
   эталон свёрстан Excel, ReportLab даст другие переносы и кернинг.
   Вместо него: (а) точные значения и состав — тестами `layout.py`;
   (б) растровое сравнение стр. 1–3 с нашими PNG в
   `tests/fixtures/drill_passport/golden/` (порог 2 %, пропуск без
   `pdftoppm`, в CI его нет — как DWG-тесты); (в) глазами — страницы
   сравниваю с эталоном и показываю владельцу.
6. **Повторная ревизия без изменений** (вопрос из PR 1): если
   `content_sha256` равен последней ревизии паспорта — вернуть её же, номер
   не растёт. Иначе один и тот же PDF расходится по номерам ревизий.
7. **Шрифт и логотип в репозитории:** `Roboto-Regular.ttf`,
   `Roboto-Bold.ttf` (Apache 2.0) и `logo.png` из `_генератор/` — в
   `design/reporting/drill/assets/`. Docker не меняется.

## Общие ограничения

- Всё за флагом `drill_passport` (`BLASTEX_DRILL_PASSPORT_ENABLED`): флаг
  выключен — маршрута нет (404).
- PDF строится только из `context` ревизии; формулы — только
  `design/drilling_passport.py`; PDF ничего не пересчитывает.
- Печатается s; c_min, W, Wпред, проверки ЛСПП, координаты, колонка
  «Оценка», реквизиты паспорта уступа, чертёж станка — **нет** (§2).
- Повторный выпуск той же ревизии — те же байты: без времени в metadata
  (`invariant=1`, `/CreationDate` и `/ID` постоянны).
- Полей в `BlastDesign` не добавлять; ключи снимка — только добавляются.
- Цвета: графит `#2E3237`, красный `#B71C1C`, светлый `#FCEDEE`, зебра
  `#F3F4F5`, линии `#C9CCD0`, серый `#6B7075`. Шрифт Roboto. Все страницы
  книжные A4.
- Подвал: «ООО «Комплексные решения» · Паспорт на бурение · стр. N из M».
- Пользовательский текст не становится разметкой ReportLab (`escape`).

## Review Focus

1. **Больше 200 скважин** (например, 201 и 401): таблица глубин
   продолжается на новых страницах 4 × 50, план — на чётной, перед ним при
   нечётном числе страниц — «Страница оставлена пустой». Тест — задача 3.
2. **Длинные тексты payload** (основание, порядок работ, ФИО на 120
   символов, номер паспорта на 120): переносятся внутри ячеек, страницы 1–2
   не уезжают на лишний лист. Тест — задача 4 (число страниц = 4).
3. **Пустые поля** (нет дат, станка, площади): печатается «—», объём и
   выход — «—», PDF выпускается. Тест — задача 3.
4. **Наклонные скважины**: угол и азимут только у них, у вертикальных
   ячейки пустые; «Угол наклона» — диапазон, а не «90° (вертикальные)».
   Тест — задача 3.
5. **Персонала больше 9**: таблица ознакомления растёт, строк не меньше
   8/9. Тест — задача 3.
