# TASK-015 PR 4 — выгрузка скважин паспорта на бурение в DXF и DWG

> **Для исполнителя:** по шагам, с галочками (`- [ ]`). Скилл исполнения —
> superpowers:executing-plans (или subagent-driven-development).

**Цель:** из неизменяемой ревизии паспорта на бурение выпускать чертёж
скважин для маркшейдера: DXF R2010 и DWG R2000 с устьями, номерами,
глубинами, первым рядом, забоями наклонных, контуром и бровками — в СК
объекта без пересчёта, чтобы файл ложился на чертёж маркшейдера.

**Архитектура:** чистая функция `design/export_survey.py::holes_dxf` строит
DXF ezdxf только из снимка ревизии (`context`), как PDF в PR 2–3. DWG —
внешней утилитой LibreDWG `dxf2dwg` (`design/spatial/dwg.py`, рядом с
`dwg2dxf`), затем обратное чтение `dwg2dxf` и сверка; не вышло — отдаётся
DXF с предупреждением. Маршруты `GET /revisions/{rid}/holes.dxf` и
`/holes.dwg` — в роутере паспорта за флагом `drill_passport`.

**Стек:** Python 3, ezdxf ≥ 1.4 (`requirements.txt`), GNU LibreDWG 0.14
(`dxf2dwg`, `dwg2dxf`, сборка в `dwg-builder` Dockerfile), FastAPI, pytest.

**Спека:** `TASK-015 — Паспорт на бурение PDF, DWG скважин, файл выноса для
GNSS.md` (корень основного чекаута), §3, §4, §6, §8 (PR 4), §9 «DXF / DWG»,
§10 вопрос 2; ход работ — `Docs/plans/TASK-015-progress.md`.

## Решения владельца (10.11.2026, до плана)

1. **DWG — R2000 (AC1015)** устраивает (§10 вопрос 2 закрыт). DXF — R2010.
2. **Числа в DXF — с точкой**, как в чертеже маркшейдера (`block66.dxf`:

## Что решено в плане (спека оставляет выбор)

- **Блок `BLX_HOLE`** — один: круг Ø 1 м и шесть ATTDEF `NUM`, `DEPTH`,
  `ANGLE`, `AZIM`, `ZCOL`, `ZTOE` (невидимые, флаг 1, высота 0,4).
  INSERT масштабируется равномерно до Ø скважины (масштаб = d/1000), круг —
  1:1. Атрибуты невидимы, потому что те же номер и глубина видны текстом на
  `BLX_HOLE_NUM` / `BLX_HOLE_DEPTH` — без двойных надписей; программы,
  читающие атрибуты (извлечение данных, свойства), видят все шесть.
- **Диаметр круга** — как на плане PR 3: `summary.bit_diameter_mm`, иначе
  `diameter_mm` строки, иначе 140 мм (`DEFAULT_CIRCLE_MM`) — у ревизии до
  PR 3 диаметра нет.
- **Форматы атрибутов** (точка): `DEPTH` — длина L, 1 знак («11.6»); `ZCOL`,
  `ZTOE` — 2 знака («419.21»); `ANGLE` — β, `AZIM` — азимут, целые; у
  вертикальных (`azimuth_deg is None`) `ANGLE` и `AZIM` пустые, как в PDF.
  `ZTOE` = `toe.z`; у ревизии без `toe` — `collar.z − length_m·sin β`.
- **Подписи:** номер — над кругом, глубина — под ним (TEXT, высота 0,4 м,
  выравнивание по центру, отступ r + 0,15 м).
- **`BLX_TOE`** — у наклонных: 3D LINE устье → забой (в плане — отрезок
  проекции) и 3D POINT забоя.
- **`BLX_FIRST_ROW`** — CIRCLE того же Ø вокруг устья, цвет 1 (красный).
- **Контур** — замкнутая LWPOLYLINE с `elevation` 0 (в снимке контур
  плоский); бровки — открытые LWPOLYLINE: `crest_top` → `BLX_CREST_TOP`,
  `crest_toe` → `BLX_CREST_TOE` (линия подошвы по углу или съёмке, как на
  плане PR 3). Ситуацию TASK-013 в DXF не кладём: она и есть чертёж
  маркшейдера.
- **Цвета ACI:** CONTOUR 7, CREST_TOP 30, CREST_TOE 32, HOLE 4, HOLE_NUM 7,
  HOLE_DEPTH 8, FIRST_ROW 1, TOE 6, INFO 7.
- **`BLX_INFO`** — MTEXT высотой 1,0 м, левый верх — над габаритом
  (min x; max y + 3 м), строки:
  «Паспорт на бурение № 66-26/Б, ревизия 1 от 09.11.2026»,
  «Блок 66, горизонт +410,0», «СК: МСК-66 зона 1 (EPSG …); высоты:
  Балтийская 1977», «Координаты в СК объекта без пересчёта, метры»,
  «BlastEX, формулы drill-v1». Не задано — «СК не задана (условная)»;
  ревизия до PR 4 — «СК не сохранена в ревизии».
- **СК в снимке:** `context["crs"] = {"name", "epsg", "height_system"}` из
  `design.coordinate_system` (`passport_context`). Снимок меняется — ревизия
  до PR 4 при повторном выпуске получит новый номер (флаг на проде
  выключен, как в PR 3).
- **Детерминизм:** `ezdxf.options.write_fixed_meta_data_for_testing` на время
  записи под `threading.Lock` (опция глобальная) — фиксирует `$TDCREATE`,
  `$TDUPDATE`, GUID и метку ezdxf. Порядок сущностей — порядок `holes`.
- **Кодовая страница DXF** — `$DWGCODEPAGE = ANSI_1251` (у ezdxf по
  умолчанию ANSI_1252): DXF R2010 всё равно UTF-8, а DWG R2000 хранит
  строки в кодовой странице чертежа — для русских программ это 1251.
- **ATTRIB** — на слое `BLX_HOLE` (у ezdxf по умолчанию слой ATTDEF «0»).
- **DWG:** `dxf2dwg -y --as r2000 -o out.dwg in.dxf`, вход — тот же DXF
  R2010. Обратное чтение — существующим `dwg_to_dxf`; сверка — число POINT,
  INSERT, TEXT, MTEXT, CIRCLE, LINE, LWPOLYLINE по слоям `BLX_*` (ATTRIB не
  считаются: `dwg2dxf` выводит их отдельно) и координаты INSERT на
  `BLX_HOLE` по `NUM` с допуском 0,001 м. Ошибка утилиты, нет утилиты,
  расхождение — DXF и предупреждение «DWG не сформирован, используйте DXF
  (открывается в AutoCAD / nanoCAD)».

### Опыт с LibreDWG 0.14 (10.11.2026, образ `dwg-builder`)

На прототипе блока 66 (196 скважин, контур, бровка, первый ряд, MTEXT):

- `dxf2dwg -y --as r2000` из DXF R2010 и из DXF R2000 — код 0, файл
  `AC1015` около 135 КБ; в выводе безвредное «Unstable Class object
  MLEADERSTYLE».
- Обратно `dwg2dxf`: все сущности на месте (196 POINT, 196 INSERT,
  196 TEXT, 44 CIRCLE, LWPOLYLINE, MTEXT), координаты вставок совпадают с
  выгрузкой SHOTPlus точно, атрибуты `NUM`/`DEPTH`/`ZCOL`/`ZTOE` целы.
- Повторная конвертация того же DXF даёт **те же байты DWG**.
- `dwg2dxf` пишет DXF в UTF-8 при любой `$DWGCODEPAGE` — ezdxf по
  умолчанию декодирует его по кодовой странице и портит кириллицу; читать
  обратный DXF надо как UTF-8 (`encoding="utf-8"`), тогда MTEXT с
  кириллицей совпадает. В ezdxf обратный DXF даёт предупреждения
  «non-unique entity handle» — читается.
- Открытие в nanoCAD / AutoCAD автоматически не проверить: после PR —
  глазами владельца или маркшейдера (DXF и DWG блока 66 из стенда).
- **HTTP:** `holes.dxf` — `image/vnd.dxf`, имя «Скважины 66-26-Б rev1.dxf»;
  `holes.dwg` — `image/vnd.dwg`, «… rev1.dwg»; при отказе DWG — 200 с DXF,
  его типом и именем `.dxf` и заголовком `X-BlastEX-Warning` (текст
  предупреждения, percent-encoding UTF-8).
