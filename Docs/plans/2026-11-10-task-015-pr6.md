> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** инженер в «Проектировании» заполняет паспорт на бурение, видит проверку первого ряда и предупреждения, смотрит черновой PDF, выпускает ревизию и скачивает все документы; флаг `drill_passport` включён по умолчанию.

**Architecture:** в этапе «Отчёт» рядом с «Проект МВ» — короткая панель «Паспорт на бурение» (статус, ревизия, скачивание); кнопка «Открыть паспорт» — большое окно `<dialog>` по образцу «Импорта чертежа»: слева форма, справа проверка первого ряда, предупреждения и предпросмотр PDF. API дополняется двумя маршрутами: список паспортов проекта и PDF черновика с пометкой «Черновик — не для работы». Чистая логика формы (поля, payload, источники, статусы проверки) — в отдельном модуле с unit-тестами, компоненты только рисуют.

**Tech Stack:** FastAPI + pydantic, ReportLab; React + TypeScript, vitest + Testing Library (jsdom).

**Spec:** `TASK-015 — Паспорт на бурение PDF, DWG скважин, файл выноса для GNSS.md` (корень основного чекаута, не в git): §3, §6, §7, §8 п. 6; решения PR 1–5 — `Docs/plans/TASK-015-progress.md`.

- Флаг включается в коде по умолчанию и попадает на прод с этим PR (до слияния — проверка на локальном стенде).

## Global Constraints

- Документы для работы строятся только из снимка ревизии; черновой PDF — только предпросмотр, в архив и ревизию не попадает.
- Полей в `BlastDesign` не добавлять.
- JSON пользователю не показывать — ни в форме, ни в ошибке, ни в окне предпросмотра (ответ с ошибкой не открывать в `<iframe>`).
- Источники величин — `provenance` ответа проверки: `MANUAL_OVERRIDE` «вручную», `REFERENCE` «справочник», `DESIGN` «проект блока», `CALCULATED` «расчёт».
- Выпуск ревизии — только при отмеченных «просмотрено» предупреждениях (`acknowledged_warnings`); 409 `unacknowledged_warnings` — перечитать проверку и показать неотмеченные.
- `stakeout_names_invalid` (path `block`) показывается у поля «Блок».
- DWG выключен (`BLASTEX_DWG_EXPORT_ENABLED`): `/holes.dwg` отдаёт DXF и `X-BlastEX-Warning` (percent-encoding) — показать текст подсказки.
- Пределы длины полей — как `TEXT_LIMITS`, `SIGNER_LIMITS`, `PERSON_LIMITS`, `MAX_PERSONNEL = 20`, `extra_approvals` ≤ 2 строк по 120 знаков (`api/schemas/drilling_passport.py`): `maxLength` у полей ввода.
- Весь текст интерфейса — по-русски; числа — `ruNumber` (`frontend/src/lib/format`).

## Review Focus

1. **Несохранённые правки проекта блока.** Паспорт строится по сохранённому `BlastDesign`; при `unsavedChanges` страницы панель и окно пишут «Паспорт строится по сохранённому проекту — сохраните правки» и не дают выпустить ревизию. Тест — задача 6.
2. **Несохранённые правки формы паспорта при выпуске.** «Выпустить ревизию» сначала сохраняет форму (PUT), затем проверяет и выпускает с `expected_version` из ответа сохранения — иначе ревизия выйдет из старого черновика или получит 409 версии. Тест — задача 5.
3. **Проверка с ошибкой** (`slope_angles_required`, `no_holes`): выпуск и предпросмотр недоступны, предпросмотр показывает текст «Предпросмотр недоступен: …» (422), а не пустую рамку. Тест — задачи 1 и 5.
4. **Справочники не прочитаны** (снимок справочников недоступен или нет прав): поля «Объект», «Станок», «Профиль» становятся текстовыми полями с кодом, окно работает. Тест — задача 5.
5. **Паспорт другого проекта / пустой список**: при открытии панели для проекта без паспорта — кнопка «Создать паспорт», а не ошибка; при нескольких — берётся последний изменённый (`list_passports` упорядочен по `updated_at`). Тест — задача 6.
