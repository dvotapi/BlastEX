## 2. Контекст документа v2 — `design/mass_blast_context.py`

Новая чистая функция `build_document_context_v2(payload, blocks, *, sources) -> dict`, где `blocks` — те же `ProjectBlock` (снимок v1 без изменений), а `sources` — по каждому блоку загруженный `BlastDesign` (его `designed_sha256` сверен со снимком) и записи справочника ревизии (`blast_safety` объекта, порода, материалы, профиль документов, реквизиты объекта), плюс охраняемые объекты из ситуации. Без БД и HTTP: всё читает сервис.

Контекст v2 — **надмножество** v1: все ключи v1 той же формы (`project`, `blocks`, `totals`, `responsibilities`, `safety_plan`, …) плюс новые. Так нынешняя заглушка рендера (`mass_blast_rendering.py`) продолжает выпускать документы и по ревизии v2, пока PR 3 не сделает свой рендер. `safety_plan.danger_zone_radius_m` в v2 — уже результат расчёта (зона для людей), а не ручной ввод.

```text

project, blocks, totals, responsibilities, safety_plan, signal_plan, guard_posts, notifications, attachments   # как v1
```

## 4. Таблица параметров (прил. 11) — по каждой скважине

Строка: № (`hole_id`), признак первого ряда, d, H_у = L − l_пер, L Р, l_пер Р, столб воды (из `water_intervals`, пусто — нет воды), ЛСПП Р (только первый ряд, `floor_burdens`), a Р, b Р, масса заряда Р (по декам, **округление до 5 кг** — шаг из профиля документов, по умолчанию 5), забойка Р, ПД шт, примечание. Два источника, оценка — `safety.objects.assess_objects` (четыре типа, решение В11):

## 7. Валидация v2 — `validate_project_context_v2`

Все проверки v1, кроме ручного радиуса опасной зоны (в v2 он расчётный), плюс:

| Код | Уровень | Когда |
|---|---|---|
| `volume_mismatch` | предупреждение | объём по таблице параметров отличается от объёма по контуру больше чем на 10 % |
| `q_deviation` | предупреждение | q расчётный отличается от q по ТП больше чем на 10 % |
| `q_just_missing` | ошибка | отклонение > 10 %, а обоснования (`q_just`) нет — п. 411 (вопрос В7) |
| `q_tp_missing` | предупреждение | нет q по ТП у объекта и в проекте |
| `object_in_zone_no_measures` | ошибка | объект «В ЗОНЕ» без мероприятий по защите |
| `expert_required` | ошибка | из `safety` (п. 808) |
| `guard_posts` | ошибка | нет постов (как в v1) |
| `blast_station_missing` | ошибка | не указано место взрывной станции (п. 11 распорядка); точки на Г.5 — PR 4 |
| `relief_unknown` | предупреждение | из `safety` (п. 785) |
| `manual_below_calculated`, `manual_reason_missing` | ошибка | ручная зона меньше расчётной или без причины |
| `situation_missing` | предупреждение | у блока нет ситуации карьера — объекты только из ручного списка |
| `signer_no_authority` | предупреждение | §5 |
| `personnel_missing` | предупреждение | не заполнена роль распорядка (ФИО не выдумываем — в документе останется пустая строка) |
| `blast_time_missing` | ошибка | нет времени взрыва — распорядок без времени не выпускается |
| коды `safety` и расхода PR 1 | как в PR 1 | переносятся с путём блока |

На блоке 66 эталона объём по таблице 26 365 м³ против 29 366 м³ по контуру (10,2 %) — `volume_mismatch` сработает и на самой форме; это ожидаемо и попадёт в отчёт теста.

## 9. Слои: проект → документы дня взрыва (§2.1 TASK-018)

Миграция `20261111_0014_mass_blast_layers`:

- `mass_blast_layers`: `id`, `organization_id`, `project_id`, `kind` (`NARYAD`, `NOTIFICATION`, `READINESS_ACT`, `TALON`, `ACCEPTANCE_ACT`), `project_revision_id` (на какой ревизии проекта основан), `status` (`draft` / `issued`), `payload` (введённое вручную: запас, номера, время, подписанты, адресат), `version`, кто и когда создал и изменил;
- `mass_blast_layer_revisions` — неизменяемые: `layer_id`, `revision_no`, `project_revision_id`, `context` (перенесённые данные проекта + `payload`), `content_sha256` по `canonical_json`, кто и когда.

Правила:
- Открытие: наряд-путёвка, уведомление, акт готовности — после `approved`; талон-допуск и акт приёмки — после `executed`. Акт готовности не открывается, если бурил и взрывает один участок Общества («бурение выполнил: Общество», п. 413).
- Перенос (`layer_seed(kind, project_revision_context)`, чистая функция): блоки, скважины и заряды, ВМ по видам и маркам из расхода (ВВ, ПД, НСИ скважинные, поверхностные по марке и замедлению, стартеры), ответственные, зоны, дата и время. Наряд: строки ВМ «по проекту / запас / к выдаче», запас по умолчанию — из `blast_safety` (`reserve_*_pcs`) или 0; «к выдаче» = по проекту + запас; расчёты проекта запас не трогает.
- «Устарел»: `project_revision_id` слоя не равен текущей ревизии проекта. `refresh` возвращает расхождение (что изменится), а с подтверждением переносит заново; введённое вручную (запас, номера, время, подписанты) сохраняется.
- Слой перевыпускается своей ревизией без новой ревизии проекта.
- API за флагом (`/mass-blast/{project_id}/layers…`: список, создать, изменить, `refresh`, выпустить ревизию; при выключенном флаге — 404), выпуск и изменение — `require_human`. Печать слоёв — PR 3, MagEX — PR 7.
