## 1. Рендер — ReportLab, а не WeasyPrint (вопрос В1)

TASK §1 и §6 п. 3 просят Jinja2 + WeasyPrint и общий `complex.css` с паспортом на бурение по правилу «кто первый, тот делает; второй рендер не заводить». Первым был TASK-015 PR 2 — он сделан на **ReportLab** (`design/reporting/drill/`, шрифты Roboto и логотип в `drill/assets`, фирменные цвета, `invariant=1`). Предлагаю следовать тому же правилу и остаться на ReportLab:

| | ReportLab (предлагаю) | Jinja2 + WeasyPrint |
|---|---|---|
| Общий стиль с паспортом | общий модуль `design/reporting/brand.py` (шрифты, цвета, логотип, шапка, подвал) — паспорт импортирует его, его байты не меняются | второй движок вёрстки рядом с ReportLab паспорта — то, что TASK запрещает |
| Деплой | без новых зависимостей | WeasyPrint тянет Pango/HarfBuzz/fontconfig в Docker-образ; сборка на VPS и так 17–50 минут |
| Повторяемость | `invariant=1`: та же ревизия — те же байты (как у паспорта) | метаданные и подмножества шрифтов надо фиксировать отдельно |
| Точная раскладка | страница = заданный набор строк (63/73 скважины, талон по середине листа) — прямо | через CSS-разрывы, проверять сложнее |

Шаблоны HTML и `complex.css` не появляются; «фирменный стиль» — константы и функции `brand.py`.

## 2. Формулы — LaTeX-запись → векторные контуры (без JS, без PNG)

- Запись — mathtext matplotlib (подмножество LaTeX; matplotlib уже в зависимостях), шрифт Computer Modern, как в эталоне (`_генератор/render_formulas.py`, `mathtext.fontset = cm`).
- Отрисовка: `matplotlib.textpath.TextPath` → контуры глифов → `canvas.drawPath` ReportLab. В PDF — вектор, без встроенных шрифтов и картинок, повторяемо по байтам. Это то же «LaTeX → SVG на сервере», только без промежуточного SVG-файла.
- Формулы — общий вид формы (P, Q, q — разд. 4; r_разл, η_з, η_заб — 13; Q_э, r_в — 14; r_с — 15), они постоянны и живут в рендере (`formulas.py`, тексты из `render_formulas.py`). Подстановки и результаты — строки из данных (`formula`, `substitution`, `value`).
- Индексы в подписях данных («H_у», «l_заб», «K_р») печатаются подстрочными (`H<sub>у</sub>`); пользовательский текст экранируется (как `_p` паспорта).

## 3. Модули

```text
design/reporting/brand.py                 # Roboto, цвета, логотип, шапка/подвал (общий с паспортом на бурение)
design/reporting/mass_blast/
  fmt.py            # числа (неразрывные пробелы, запятая), даты, «—» для пустого, подстрочные индексы
  formulas.py       # mathtext → контуры ReportLab (Flowable)
  charge_column.py  # рисунок колонки заряда (вектор, по `draw_charge_column.py`)
  frame.py          # документ = набор страниц с шапкой/подвалом; DocumentPart(name, footer_label, pages)
  title.py          # 1: титул + оборот «Состав проекта»
  techcalc.py       # 2: технический расчёт (по блоку)
  param_table.py    # 3: таблица параметров (по блоку), раскладка 63/73
  schedule.py       # 4: распорядок
  readiness.py, notification.py, naryad.py, talon.py, acceptance.py   # 6–10
  duplex.py         # склейка документов: лицевая, пустые обороты, сквозная/своя нумерация

api/services/mass_blast_documents_v2.py   # чтение ревизии/слоёв, права, статус, отдача байтов
```

Каждый документ — чистая функция `(context) -> DocumentPart` без ввода-вывода. Сборка PDF — один проход ReportLab по готовым частям (`BaseDocTemplate` с шаблонами страниц: книжный, альбомный для наряд-путёвки, пустой оборот).

## 6. Двусторонняя печать и нумерация (логика `_генератор/duplex_mv.py`)

- Документ PDF собирается в два шага: раскладка каждой части (страниц известно заранее, ReportLab повторяем), затем одна сборка с пустыми оборотами. Пересчётов данных нет.
- Каждый документ начинается с лицевой: после части с нечётным числом страниц — пустой оборот «Страница оставлена пустой» с подвалом этой части. Титул и «Состав проекта» — одна часть.
- Нумерация: документы проекта (1–4, позже Г) — сквозная «Стр. N из M» с учётом пустых оборотов; документы дня взрыва — у каждого своя «Стр. 1 из 1», пустой оборот слоя — без номера (эталон v0.11). Отдельно скачанный документ проекта — своя нумерация.
- Эталон блока 66 без «Реквизитов» и графики: титул 2 + техрасчёт 2 + таблица 3 (+1) + распорядок 2 = 10 страниц проекта.

## 7. Выдача: маршруты и PACKAGE

Печать v2 — **на лету из неизменяемой ревизии**, как у паспорта на бурение (`/revisions/{rid}/passport.pdf`): та же ревизия — те же байты, хранить файлы не нужно (В2). Ревизия v1 — по-прежнему `POST /{project_id}/documents` и сохранённые файлы.

| Маршрут | Что |
|---|---|
| `GET /mass-blast/revisions/{rid}/documents/{doc}.pdf`, `doc` ∈ `title`, `technical-calculation`, `parameter-table`, `schedule`, `project` | документы 1–4 по одному и «проект» (1–4 подряд, двусторонне) |
| `GET /mass-blast/revisions/{rid}/package.zip` | PACKAGE |
| `GET /mass-blast/layers/revisions/{lrid}/document.pdf` | документ слоя по его ревизии |
| `GET /mass-blast/{project_id}/preview/{doc}.pdf`, `GET /mass-blast/layers/{layer_id}/preview.pdf` | предпросмотр черновика с пометкой «ЧЕРНОВИК — не для работы» на каждой странице (как `preview.pdf` паспорта; нужен PR 6), с ошибками проверки — 422 |

- Права — как у нынешних документов проекта МВ (организация); документы проекта — после `approved` (как сейчас), слоя — по его выпущенной ревизии.
- `POST /{project_id}/documents` для ревизии v2 — 409 с указанием нового маршрута (заглушка v2 больше не печатает).
- Новые ревизии v2 выпускаются с `document_template_version = vm0903-v0.11` (v1 — прежний `mass-blast-standard-v1`).
- **PACKAGE** (ZIP): `00_Комплект.pdf` (всё подряд в порядке TASK §2, двусторонне) + документы по одному в том же порядке (`01_Титул.pdf`, `02_Технический_расчёт_66.pdf`, …, `07_Уведомление_<адресат>.pdf`, …) + `manifest.json` (ревизия, `content_sha256`, ревизии слоёв, sha256 файлов, что не вошло и почему). Слои — последняя выпущенная ревизия каждого слоя на **этой** ревизии проекта (уведомления — все адресаты, наряд-путёвки — все); устаревшие и невыпущенные не входят, перечислены в `manifest` (В8). ZIP — с постоянным временем (`archive.fixed_zip` паспорта).
