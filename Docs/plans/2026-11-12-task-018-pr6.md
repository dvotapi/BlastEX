## 2. Где живёт интерфейс

Как у паспорта на бурение: **панель «Проект МВ» в этапе «Отчёт»** «Проектирования» (там, где сейчас `MassBlastPanel`) и **окно проекта** (`frontend/src/pages/design/massBlast/`).

- Панель коротко: проект блока (последний изменённый, в котором есть этот блок), № и статус, ревизия, кнопки «Открыть проект», «Весь комплект» (после утверждения) и, если проекта нет, «Создать проект МВ».
- «Создать проект МВ» — маленькое окно: дата и время взрыва (обязательны: даты не выдумываем), блоки проекта (этот блок + другие сохранённые проекты блоков того же объекта — списком с галочками, а не ID через запятую). Остальное сервер заполняет сам (§7.1), потом открывается окно проекта.
- Проект v1 (создан до включения флага) открывается прежней панелью без изменений; у черновика v1 — кнопка «Перевести на форму ВМ.09.03» (только вперёд, `context_version: 2`, решение по умолчанию плана PR 2).

## 3. Окно проекта: вкладки по разделам §5

Слева вкладки, справа форма; внизу окна всегда — строка замечаний проверки (число ошибок и предупреждений, щелчок ведёт к полю по `path`) и кнопки «Сохранить», «Проверить». В статусе, отличном от `draft`, форма только для чтения.

| Вкладка | Поля (payload проекта) | Подсказки |
|---|---|---|
| **Реквизиты** | № и дата проекта, ТП (основание), составил / проверил, заказчик, подрядчик, «УТВЕРЖДАЮ» заказчика и подрядчика (должность, ФИО, технический руководитель, основание полномочий), «Согласовано» маркшейдер и геолог, исполнитель съёмки, «бурение выполнил» | пустое поле — серым значение из контекста и откуда оно («справочник объекта») |
| **Блоки** | по каждому блоку: код, горизонт, порода текстом, гидрогеология, назначение, площадь; примечания к скважинам («скважина → действие») | автоматическое «снизить заряд» (ЛСПП < 0,8·W) — списком из `parameter_table`, только просмотр |
| **ВМ и СИ** | долото и k разбуривания, способ инициирования, схема, конструкция заряда, материал забойки, марка стартера, q по ТП, обоснование удельного расхода | расход ВМ по проекту — таблица из `consumption` (только просмотр); q расчётный и отклонение — из техрасчёта |

| **Распорядок** | заряжание (дата, смена с–по), порядок заряжания и монтажа, станция, укрытие, сбор, выход людей, сирена, мероприятия (п. 14), особые условия, УВВ на здания, транспорт ВМ, средства очистки, дата инструктажа, фланг начала заходок СЗМ | время сигналов и допуска — из `schedule` (взрыв − 1 ч, + 15, + 30 мин), только просмотр |

## 4. Точки постов, станции, укрытия и сбора — щелчком по плану

План — SVG по данным Г.5 из контекста (`graphics`: контуры блоков, кольца зон людей / механизмов / зданий, линии ситуации, охраняемые объекты, точки), север вверх, масштабирование колесом и перетаскивание.

- Слева выбор: «Пост № …» (из списка постов), «Взрывная станция», «Укрытие», «Место сбора»; щелчок по плану ставит точку выбранного вида (у поста — привязку к коду), точку можно перетащить или удалить; X и Y можно поправить числом.
- Возле точки — расстояние до блока; пост или станция внутри зоны для людей — предупреждение сервера (`guard_post_inside_zone`, `station_inside_zone`) прямо на плане.
- Без ситуации карьера план показывает только блоки и кольца зон; ставить точки всё равно можно (на Г.5 — пометка «привязать по плану карьера», как в PR 4).
- Координаты — СК объекта, как в контексте (`x` — восток, `y` — север).

## 5. Проверка, предпросмотр, выпуск, документы

- «Проверить» — `POST /validate`, замечания группами (ошибки / предупреждения) со ссылкой на вкладку и поле.
- **Предпросмотр каждого документа**: «Титул», «Технический расчёт», «Таблица параметров», «Распорядок», «Графика», «Весь проект» — PDF черновика открывается в новой вкладке браузера; при ошибках проверки сервер отвечает 422 — показываем его текст. Несохранённые правки сначала сохраняются (как в окне паспорта на бурение).
- Жизненный цикл кнопками: «Выпустить ревизию на согласование» (`draft → in_review`), «Согласовать как …» по ролям (видна только назначенной учётке), «Утвердить», «Вернуть в черновик», после утверждения — «Взрыв произведён» (`approved → executed`, с подтверждением и примечанием), «Закрыть проект» (`executed → closed`).
- **Документы ревизии** (после `approved`): кнопки PDF «Титул», «Технический расчёт», «Таблица параметров», «Распорядок», «Графика», «Проект целиком» и **«Весь комплект»** (`package.zip`) — и в окне, и на панели. У ревизии без графики кнопка «Графика» скрыта (сервер ответил бы 409). Состав комплекта: какие слои вошли и какие нет (`omitted_layers` манифеста) — подсказкой под кнопкой по списку слоёв.

## 6. Вкладка «День взрыва»: слои

Карточка на каждый вид слоя, в порядке комплекта: наряд-путёвка, уведомление, акт готовности, талон-допуск, акт приёмки, «Факт» (исполнительная таблица и Г.1 по съёмке). Ещё не открытый слой — кнопка «Открыть» или причина, почему нельзя (из `GET …/layers/available`, §7.3: правило одно — `layer_open_issue`).

У открытого слоя: статус (черновик / выпущен, ревизия № …), пометки «устарел» (новая ревизия проекта), «факт изменился» (`fact_changed`), «факт перевыпущен» (`fact_layer_stale`), форма ручного ввода, замечания слоя, кнопки «Сохранить», «Предпросмотр», «Выпустить ревизию», «Скачать PDF» (последняя ревизия).

| Слой | Форма |
|---|---|
| **Наряд-путёвка** | № , дата выписки, склад, разрешение, индекс взрывника, транспорт, водитель, доставка, «ВВ изготавливаются на месте»; таблица ВМ: наименование, ед., **по проекту / запас (ввод) / к выдаче**; после `executed` — ещё **выдано / израсходовано / возвращено** (ввод; пусто — серым значение, посчитанное из факта); итоги и запас по группам. Нарядов может быть несколько — «Ещё наряд-путёвка» (больше ВМ после выдачи — новый наряд, а не правка) |
| **Уведомление** | адресат — выбор из справочника карьера (`GET …/notification-addressees`, §7.2; адресат, которому уже есть уведомление, недоступен); без справочника — должность, ФИО, обращение вручную; исх. №, дата, подписант. «Уведомления всем адресатам» — по одному на каждого ещё не уведомлённого |
| **Акт готовности** | дата, 7 условий «да / нет / —» (тексты — из `seed.conditions`), замечания, заключение, передал / принял, «съёмка передана». Не открывается при «бурение выполнил: Общество» — показываем причину |
| **Талон-допуск** | дата и время выдачи, выдал, получил, **фактические дата и время взрыва** (подсказка «не ранее» = факт + 30 мин из `view`) |
| **Акт приёмки** | дата акта, договор (№, дата), № приложения, представитель заказчика, объём к оплате (подсказка — объём по контуру), особые замечания; по факту или по проекту — подпись из `view.fact` |
| **Факт** | дата и время взрыва, **отказы** списком «блок:номер» (в проекте из одного блока — просто номер), примечания по факту к скважинам; сводка «бурение N из M, заряжание N из M» и предупреждения о пропусках |

**Перенос заново** («устарел», «факт изменился», «факт перевыпущен»): кнопка «Перенести данные заново» сначала зовёт `refresh` без подтверждения и показывает расхождение таблицей «что / было / станет» (скважины и графы Ф у «Факта»), введённое вручную — отдельной строкой «сохранится»; «Подтвердить перенос» — `refresh` с `confirm: true`.

## 7. Что добавить на сервере (небольшое, без изменения расчёта)

1. **Предзаполнение нового проекта v2** (`api/services/mass_blast_prefill.py`, по образцу `drilling_passport_prefill.py`): `POST /design/mass-blast-projects` с `context_version: 2` заполняет не заданные в запросе поля. Объект — объект проекта блока или активный объект организации; наименование объекта, заказчик — из справочника объекта. Из **прошлого проекта v2 того же объекта** — люди (составил, проверил, подписанты, согласования, исполнитель съёмки, персонал, учётки ролей) и постоянные тексты распорядка (станция, укрытие, сбор, выход, сирена, транспорт, средства очистки, порядок заряжания и монтажа, мероприятия, «бурение выполнил»). Не переносятся: №, даты, время, блоки, охраняемые объекты и их мероприятия, посты и точки на плане, примечания к скважинам. Реквизиты из `mass_blast_sites` в payload не копируются — контекст и так берёт их из справочника, когда поле пустое.
2. **Адресаты уведомлений**: `GET /{project_id}/notification-addressees` → код, подпись для списка («должность — ФИО, способ, за N сут»), есть ли уже уведомление. Подпись собирает сервер — фронт полей справочника не знает.
3. **Какие слои можно открыть**: `GET /{project_id}/layers/available` → по каждому виду: можно ли открыть, причина, можно ли ещё один (наряд, уведомление). Правило — прежнее `layer_open_issue`.
4. **Флаг по умолчанию включён** (`config.mass_blast_v2_enabled`), `/features` уже отдаёт `mass_blast_v2`.

Всё — за флагом (404 при выключенном), чтение — `require_internal_access`.

## 8. Справка «?»

`MassBlastHelp` (как `DrillPassportHelp`): что такое проект и слои, порядок работы (черновик → проверка → ревизия → согласование ролями → утверждение → слои дня взрыва → «Взрыв произведён» → талон, акт приёмки, факт → закрытие), откуда берутся значения (проект блока, справочники объекта, ручной ввод главнее), что считается само (зоны, расход, время сигналов), запас в наряде не меняет расчёт, двусторонняя печать и «Весь комплект», печать Г.1–Г.5 в 100 % без «вписать в страницу».

### Отступления от плана и уточнения

- Создание нового проекта — отдельный маршрут `POST /new` (дата, время, блоки), а не `POST` с `context_version: 2`: обязательные поля прежней схемы (объект, наименование) заполняет сервер.
- Блоки в окне создания — все сохранённые проекты блоков организации (у проекта блока нет ссылки на объект, «того же объекта» отобрать нельзя).
- Проверка v2 не берёт из проверок v1 «профиль сигналов» и «получатель уведомления» (`V1_CODES_NOT_IN_V2`): сигналы — из профиля документов (п. 163), уведомления — слои по адресату. Иначе новый проект v2 с самого начала показывал ошибку, которую в окне нечем исправить.
- Роли распорядка с подписями приходят с сервера (`hints.personnel_roles`), чтобы окно не дублировало `PERSONNEL_ROLES`.
- Расхождение переноса — подписи и тексты значений собирает сервер; служебные номера (UUID ревизий) в тексте не показываются, даты — по-русски.
- Предпросмотр: вкладка браузера открывается сразу в обработчике щелчка, адрес PDF подставляется после сохранения (иначе браузер блокирует её как всплывающее окно).
