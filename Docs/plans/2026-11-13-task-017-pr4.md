# TASK-017, PR 4. Графическая правка коммутации на плане — план реализации

> **Для исполнителя:** шаги — чекбоксы (`- [ ]`), выполнять по порядку, TDD.

**Цель:** связи, ступени, стартовые и замедление в скважине правятся прямо на
плане (по образцу ShotPlus): палитра номиналов над планом, инструменты
«Связь» / «Ступень» / «Стартер» / «В скважине», выделение и удаление связей,
меню по линии, перецепка конца. Времена и «без сигнала» видны сразу после
правки — клиентский расчёт. Список «Ручная правка связей» из панели убран.

**Архитектура:** все правки — чистые функции `tieEdits.ts` над
`InitiationNetwork` (одна функция — один вызов `SET_NETWORK`, то есть одна
запись отмены; каждая ставит `origin = "edited"` через
`retie.ts::markNetworkEdited`). Клиентские времена — `networkTimes.ts`, порт
`design/timing.py::resolve_network`; совпадение держит общая фикстура
`frontend/src/pages/design/testing/networkTimesFixture.json`, её пишет и
сверяет `tests/test_network_times_fixture.py`. Номиналы — с сервера
(`GET /design/tie/catalog` из констант `design/timing.py`), фронт их не
дублирует. Жесты плана — в `PlanCanvas` (режим `tie`), геометрия попаданий по
линиям — `tieHits.ts`. Состояние палитры (активная ступень, замедление в
скважине) — у страницы: его показывают и план, и панель.

**Стек:** Python 3, FastAPI, pytest; React 19 + TypeScript, vitest + Testing Library.

**Задача:** `TASK-017 — Сдвиг скважин мышкой, пересчёт и графическая правка коммутации.md`
(основная папка проекта, не в git), «Требования → 4», «5. Справка» и «Тесты →
Фронт, коммутация» в части PR 4.

## Общие ограничения

- Номиналы: СИНВ — 17 / 25 / 42 / 67 / 109 мс, ДШ — реле 10 / 20 / 25 / 35 / 42 мс,
  электронная — те же, что у СИНВ, плюс «своё, мс». Цифры 1–5 — номинал по порядку.
- Клавиши инструментов: T — «Связь», D — «Ступень», S — «Стартер», H — «В скважине»
  (и русская раскладка: е, в, ы, р). V — «Выбор», пробел — панорама.
- Активная ступень при открытии режима — `timing_params.trunk_ms` сети, иначе 25 мс.
- Новая связь к скважине с входящей заменяет прежнюю: линия мигает 1 с, подсказка
  «Связь 4-02 → 4-03 заменена». Два входа одной скважине не бывает.
- Цикл не создаётся: «Цикл: скважина 4-03 уже срабатывает раньше» (4-03 — цель
  новой связи, она уже раньше источника). Те же правила — у разворота и перецепки.
- Любая правка — `origin = "edited"` и одна запись отмены; протяжка цепочки — тоже одна.
- Клиентские времена — как `resolve_network`: кратчайший путь от стартовых
  (`starter_items` с их задержкой, иначе `starters` с 0) по связям
  (`surface_connectors`, иначе `connectors`) и отрезкам ДШ (расстояние в плане /
  скорость + реле, в обе стороны), плюс замедление в скважине; электронные
  каналы и `electronic_times_ms` главнее. Только включённые скважины.
- Серверный анализ — по кнопке; после правки он сбрасывается (как сейчас) и
  панель «Тайминг» пишет, что расчёт устарел.
- Только план, 3D не трогаем. Хэш утверждённых паспортов не меняется (новых
  полей в документе нет).

## Решения исполнителя (не из задачи)

- Режим `tie` плана сейчас недостижим (этап «Тайминг» ставит `timing`, план ведёт
  себя как «Скважины»). Этап «Тайминг» теперь ставит план в `tie`; анимация —
  по этапу, а не по режиму. Скважины в этом режиме не перетаскиваются.
- Инструмент по умолчанию в режиме `tie` — «Связь».
- Начало связи кликом запоминает сам план (а не страница): состояние
  `pendingTieFromId` страницы убрано.
- Стартовая для источника новой связи добавляется, как и раньше, только когда у
  источника нет ни входящей связи, ни отметки стартовой.
- Протяжка: соседние скважины пути связываются по порядку; отрезок, дающий цикл,
  пропускается с подсказкой, остальные ставятся. Скважина, уже бывшая в пути, не
  добавляется повторно.
- «Ступень» рамкой — связи, отрезок которых пересекает рамку.
- Перецепка — тянуть за конец (в пределах радиуса попадания по скважине) у
  выделенной связи; отпущено над другой скважиной — перецепка, иначе ничего.
- «В скважине»: у СИНВ — номиналы `DOWNHOLE_NSI_MS_OPTIONS` (450…1000 шагом 50),
  у ДШ и электронной номиналов нет — поле «своё, мс». Пишется в
  `downhole_delay_ms`, `downhole_connectors` (на скважину) и в скважинный
  `detonators`, если он есть. Активное по умолчанию — `timing_params.downhole_delay_ms`,
  иначе умолчание системы (`DEFAULT_DOWNHOLE_MS`).
- Шнуры ДШ (`detonating_cords`) правка связей не меняет — у «Магистраль + цепочки»
  их нет; у старых схем ДШ шнур и время задаёт он.
- Цвет связи — по номиналу палитры (индекс); не номинал — серый.
- Delete на уровне страницы в режиме `tie` скважины не удаляет (Delete — связям).
- Кнопка «Стартовые из выделенных» остаётся (выделение рамкой инструментом «Выбор»).

## Внимание при ревью

1. Электронная сеть с каналами: правка связей не меняет времена каналов — подсказка не врёт, клиентские времена = серверные.
2. Сеть, где связи только в `connectors` (старые паспорта): правка пишет обе формы и не теряет связи.
3. Стартовая скважина как цель новой связи: стартовая остаётся, вход появляется — времена по кратчайшему пути.
4. Связь на скважину, исключённую из расчёта: связь ставится, но без сигнала не помечается (нет в расчёте).
5. Перенумерация и удаление скважин после правки: связи с исчезнувшими скважинами чистит прежний `pruneLoadsAndNetwork`.
