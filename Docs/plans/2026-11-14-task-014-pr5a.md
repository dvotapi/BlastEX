# TASK-014 PR 5а — импорт исполнительной съёмки и правка проекта: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Файл исполнительной съёмки маркшейдера загружается в BlastEX. Для текущего блока скважины сопоставляются, оцениваются по допускам паспорта на бурение, и одним действием с одним шагом отмены факт переносится в проект блока. Для старого блока, которого нет в BlastEX, файл сохраняется на объекте.

**Architecture:** Чистые модули `design/survey/` (чтение, сопоставление, оценка, применение). Применение считает новые скважины, заряды и записи факта на сервере и ничего не сохраняет. Фронт кладёт результат в документ одним действием `APPLY_SURVEY` и сохраняет обычным `PUT /design/plans/{id}`. Утверждённый проект не правится: «Копия по съёмке» — это `fork` и применение на копии. Съёмка без проекта хранится в новой таблице `blastex.site_surveys`.

**Tech Stack:** Python 3.12, FastAPI, pydantic v2, SQLAlchemy + Alembic (PG), ezdxf через `design/spatial/cad/reader.py`, openpyxl; React + TypeScript, vitest.

**Spec:** `Docs/specs/2026-11-14-task-014-pr5-survey-design.md` (§6 М1, М3, М6–М9, §7, §13). Ветка `task-014-pr5-design` от `main` `c5738ba0`. PR 5б–5г — отдельными планами.

## 0. Отступления от дизайна (решения при планировании)

- **М10 (`site_code` у проекта блока) и пометка «заменён копией по съёмке» переносятся в 5б.** В 5а они не нужны: соседей ещё нет, а «заменён» выводится по цепочке `parent_design_id`, когда у потомка есть `survey_applications`. Отдельный ключ не нужен вообще.
- **Описание точки выноса (`L10.7`, `A.. AZ..`, `R1`) — проектные значения.** Импорт **не** берёт из него глубину. Глубина — только из колонки таблицы или из ручного ввода.
- **М1 в 5а — только оценка скважин.** Допуски в тексте акта готовности и порог красных номеров Г.1 (снимок в `seed` слоя «Факт») — в 5г, вместе с актом.
- **Допуски — из ревизии паспорта.** Статуса «выпущен» у паспорта на бурение нет, неизменяемы ревизии. Берём `current_revision_id` последнего по `updated_at` паспорта блока (`list_passports(org, design_id)`). Нет такого — идём по `parent_design_id`, нет и там — умолчания с предупреждением `survey_tolerances_default`.

## Global Constraints

- Ключи в `BlastDesign.to_dict` пишутся только когда заданы (иначе меняется хэш утверждённых паспортов).
- Поля справочников — только схемами Cost V2; JSON пользователю не показывать.
- Утверждённое не меняется: в `approved`/`executed` разрешены только мутации `execution`, `measured`, `metadata` (`lifecycle.ALLOWED_MUTATIONS`).
- Расчёт не знает об интерфейсе; всё, что нужно фронту, — через `api/`.
- Не трогать: технологический расчёт сетки, тайминг, Kuz-Ram, экономику; выпущенные ревизии паспортов на бурение, проектов МВ и слоёв печатаются байт в байт.
- Допуски по умолчанию: глубина ±0,3 м, устье ±0,3 м, угол ±1°, ЛСПП ±5 %, расстояние между скважинами ±5 %.
- «Без изменения»: разница в плане и по отметке устья < 0,001 м, по глубине < 0,01 м.
- Сопоставление по близости — в плане, не дальше 2·`tol_collar_m`.
- Смещение устья считается в плане (XY). Нужная длина — L_нужн = (Z_уст.ф − Z_подошвы)/cos α + Δ, подошва проектная: Z_подошвы = Z_уст.проект − `Hole.bench_height_m`.
- Подписи статусов (UI): `ОК`, `ДОБУРИТЬ`, `ПЕРЕБУР`, `СМЕЩЕНИЕ`, `УГОЛ`, `ЛСПП`, `ШАГ`, «глубина не замерена», «по близости», «точка без скважины», «две точки», «нет съёмки».
- Стадия проекта: «предварительный» / «по съёмке».
- Тесты Python — `unittest`/`pytest`, хранение планов — `tempfile` + `patch("cost.persistence.data_root")`; PG — `tests/pg_public.py::requires_pg`. Фронт — из `frontend/`: `npx vitest run <file>`, `npx tsc -b`.

## Review Focus

1. **Таблица маркшейдера с колонками «X», «Y» по-русски** (X — север, Y — восток) — точки должны лечь на блок, а не отразиться относительно диагонали. Тест в задаче 1 (`test_table_russian_xy_detected_by_design`).
2. **CSV из русского Excel**: разделитель `;`, десятичная запятая, BOM, кодировка cp1251 — читаются так же, как `,` и точка. Тест в задаче 1.
3. **Файл выноса, возвращённый как съёмка**: глубина из описания `L10.7` не берётся, у всех скважин «глубина не замерена». Тест в задаче 1 (`test_stakeout_description_is_not_depth`).
4. **Лишние точки в файле** (репер, станция, точка забоя `_T`) не сопоставляются молча с ближайшей скважиной, если до неё дальше 2·допуска, и не попадают в «Применить». Тест в задаче 2.
5. **Утверждённый проект**: «Применить» на сервере для `approved` даёт 409 с подсказкой «Копия по съёмке», а не тихо меняет сетку. Тест в задаче 5.
