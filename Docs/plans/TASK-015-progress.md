### Решения по ходу

- Единица углов в схемах — «°» (в справочниках единицы русские), а не `deg`.
- В паспорт идут все включённые скважины, включая контурные: их тоже бурят.
- Высота уступа скважины — существующее `Hole.bench_height_m` (вертикаль минус
  вертикальная часть перебура); у вертикальных совпадает с формулой §2.2.
- Нет вылета e — по спеке §2.2 e = 0 (c_min = s) с предупреждением
  `axis_offset_missing`; план предлагал c_min = None, спека главнее. Принятое
  расстояние c не задано — берётся c_min, поэтому W считается всегда, когда
  посчитан s.
- α: паспорт → справочник объекта → проект блока. План ставил проект раньше
  объекта, но в интерфейсе у нового блока угол откоса по умолчанию 75°, и он
  молча перекрывал бы техпроект. Угол проекта, отличный от принятого, —
  предупреждение `alpha_mismatch`.
- Нет Wпред — предупреждение `w_max_missing` (до TASK-014 оно будет у каждого
  паспорта без ручного Wпред и требует отметки «просмотрено»).
- Объект и тип станка — коды `site_code` и `rig_type_code` в payload паспорта;
  без `site_code` при создании берётся активный объект организации. Площадь
  блока — по контуру `BlastDesign`, payload её переопределяет.
- Новых полей в `BlastDesign` нет — хэши утверждённых паспортов БВР не
  меняются.

- **Бесконечность в числах payload** — 422 (`allow_inf_nan=False`), а не 503.

### PR 1b — форма v0.7 (09.11.2026)

План — `Docs/plans/2026-11-09-task-015-pr1b.md`, та же ветка `task-015-pr1`,
три коммита поверх правок по ревью.

- **Hs — высота уступа для безопасного расстояния** (решение владельца
  09.11.2026). У объекта — `design_bench_height_m` (3–30 м, «Высота рабочего
  уступа по проекту отработки»), в паспорте — `bench_height_for_s_m` (до
  30 м). Источник: паспорт (`MANUAL_OVERRIDE`) → объект (`REFERENCE`) → H₁
  (`CALCULATED`); ключ — в `inputs` и `provenance`. Bпр = Hs·(ctg γ − ctg α),
  s округляется как прежде; W и c_min — по фактической высоте каждой
  скважины первого ряда. В `first_row_check` — `hs_m`, `hs_source`.
- **`bench_above_design`** — H₁ > Hs + 0,5 м: предупреждение с номерами до
  5 скважин с наибольшей высотой; Hs из H₁ — без предупреждения.
- **Поля payload v0.7**: `site_preparation` (по умолчанию «бульдозером под
  руководством горного мастера заказчика; приём площадки по акту»),
  `extra_approvals` (до 2 строк по 120 символов, по умолчанию «маркшейдер»,
  «геолог» — без «ведущий»), `tol_depth_m` и `tol_collar_m` (0 < x ≤ 2 м,
  по умолчанию 0,3). Подписанты и персонал нового черновика по-прежнему
  пустые — «ведущий» нигде не подставляется.
- **Версия формул** — `drill-v1`: PR не слит, флаг выключен, ревизий
  `drill-v1` на проде нет.
- Контроль на блоке 66: α 75°, γ 65°, Hs 10,0 → Bпр 1,98, s 2,0 и
  `bench_above_design` (11,7 > 10,5); без Hs — s 4,0 / 2,4, W 5,14, как
  раньше.

### Правки по ревью Codex (09.11.2026)

- **Направление наклона в ЛСПП.** Формула §2.2 W = H·(ctg α − ctg β) + c
  верна только для наклона к откосу: наклон в массив занижал W (пример
  Codex: H 10, α = β = 75°, c 2 → 2 м вместо 7,36 м). Теперь W = H·ctg α +
  c − d, где d — проекция смещения оси на уровне подошвы
  (`toe_line.floor_point`) на направление от устья к ближайшей точке
  бровки (`DrillHoleRow.face_shift_m`). У вертикальных d = 0 — числа блока
  66 прежние. Нет бровки — d по формуле §2.2 (как к откосу) и
  предупреждение `first_row_tilt_direction_unknown`.
- **Горизонтальная скважина** давала деление на ноль и 503 — теперь ошибка
  проверки `hole_not_downward` с номерами скважин (забой не ниже устья).

### Правки по ревью PR #168 (агент без контекста, 09.11.2026)

- **Запас ситуации** — не меньше 1,4 наибольшей стороны габарита (и не
  меньше 60 м): у вытянутого блока поле листа шире ±60 м, и ситуация
  обрывалась внутри поля.
- **Стрелка «С»** — в легенде справа, а не на поле: на поле она ложилась на

- **Место под подписи** — 8 мм справа от самых восточных скважин
  (`LABEL_RESERVE_MM`): подписи не выходят за рамку; масштаб считается по
  ширине без него.
- **Кегль подписей** — ближайший сосед через `cKDTree` (было O(n²): 4000
  скважин — секунды на PDF).

- **Почему сверка не поймала:** обратное чтение делает та же LibreDWG — её

  как»». Код записи, сверка и `dxf2dwg` в образе остаются.
- **Когда включать:** выйдет выпуск LibreDWG с исправлениями записи R2000 →
  поднять `LIBREDWG_VERSION`, включить флаг на стенде и дать маркшейдеру
  открыть DWG в AutoCAD; только после этого — на проде.

- **Пределы чисел** схемы API (α 30–90°, γ 20–90°, e 0–5 м, Hs до 30 м,
  допуски до 2 м, № и дата) проверяются в окне по-русски — 422 сервера
  приходит с английскими текстами.
- Попутно: предпросмотр недоступен при ошибке проверки; при неизменённом
  снимке — «новая не выпущена»; 409 — без служебных кодов.

### Все поля нового паспорта заполнены (решение владельца 10.11.2026)

- **Объект** — активный объект организации; не определился (кнопка «Создать
  паспорт» шлёт только проект) — объект последнего паспорта организации.
- **Справочники:** «Объект в паспорте» — название объекта, «Заказчик» —
  контрагент объекта или «Заказчик текстом», горизонт — медиана подошвы
  скважин до 1 м («+410» у блока 66).
- **Прошлый паспорт того же объекта** (последний изменённый): подписи,
  ознакомление, согласования, «Составлен на основании», допуски, Wпред,
  станок (тип, название, №, диаметр) — главнее умолчаний кода.
- **Первый паспорт объекта:** станок — из «Условий бурения» объекта или
  единственный буровой станок справочника, название — типа станка, № —
  инвентарный (или заводской) его единицы техники, диаметр — коронка нормы
  бурения (`pick_condition` модели себестоимости).
- **Даты:** начало — дата паспорта, окончание — объём бурения / (скорость ×
  (часы смены − непроизводительное время) × 2 смены в сутки), вверх до суток;
  нет нормы — дата начала и предупреждение `drilling_norm_missing`.
- Подписи и Wпред в первом паспорте объекта вводятся один раз — справочника
  людей у паспорта нет.
