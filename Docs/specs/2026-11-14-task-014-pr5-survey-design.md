# TASK-014 PR 5 — исполнительная съёмка: проект МВ по результатам, соседние блоки и стаканы

Nov 14, 2026 · дизайн, обсуждён с владельцем 14.11.2026

Заменяет в `TASK-014` §2.4 и этап «PR 5 — импорт съёмки и акты». Сменный рапорт бурения (`DRILL_SHIFT_REPORT`) отсюда вынесен в отдельную задачу. Справочник персонала и ЭДО остаются за PR 6 TASK-014.

## 1. Зачем

После бурения маркшейдер снимает фактическое положение устьев, а мастер меряет глубины. Обычно всё в допуске, но если нет, проект подгоняют под факт. **Проект массового взрыва подписывают по результатам съёмки** (решение владельца 14.11.2026). Значит, съёмка должна править сам проект блока, а не только печататься в графах «Ф».

Две стадии проекта (решение владельца 14.11.2026):

- **Предварительный проект МВ** — работа инженера до бурения на проектной сетке: подбор раскладки, расположения зарядов и темпа отбойки. По нему печатают паспорт на бурение. Отдельным документом он не подписывается.
- **Проект МВ** — то же после исполнительной съёмки, на фактических скважинах: заряды и замедления подстроены, документ подписывается.

```
Предварительный проект (проектная сетка): раскладка, заряды, темп отбойки
   ↓ паспорт на бурение → бурение → исполнительная съёмка
Импорт съёмки: сопоставление, оценка по допускам, «Применить к проекту»
   ↓ заряды — по правилам сразу; замедления — подбор с карточками
Проект МВ (фактические скважины) → подписи → день взрыва
```

Вторая потребность (владелец, 14.11.2026): на предварительном проекте видеть исполнительную съёмку уже взорванных блоков **сверху и по бокам**, чтобы не ставить новые скважины в **стаканы** старых. Съёмку старых блоков берём **из BlastEX и из файлов маркшейдера**: многих старых блоков в BlastEX нет.

## 3. Цели, не-цели, анти-цели

**Цели**
1. Импорт исполнительной съёмки файлом: к проекту блока или без проекта (старый блок).
2. Оценка каждой скважины по допускам паспорта и «Применить к проекту» — проект блока становится исполнительным.
3. После съёмки заряды пересчитываются по правилам, замедления подбираются на фактических скважинах (карточки, выбор инженера).
4. Соседние взорванные блоки и стаканы видны на предварительном проекте. Устье в стакане — нарушение в живой проверке, в `validate` и в отбраковке подбора.
5. Проект МВ создаётся по исполнительному проекту блока; акт готовности проверяет съёмку и допуски.

**Не-цели**
- Сменный рапорт бурения, моточасы, ДТ, коронки, экономика.
- Форматы конкретных буровых станков (MWD), съёмка с дрона, облака точек.
- Повторный подбор сетки после съёмки: скважины уже пробурены, двигается только коммутация.
- Справочник персонала, ЭДО, УКЭП.

**Анти-цели** (провал, даже если всё работает)
- Подписанный проект МВ отличается от того, что пробурено, и никто об этом не знает.
- Подбор сам меняет коммутацию утверждаемого проекта без взгляда инженера.
- Импорт молча сопоставляет скважину не с той (две точки на одну скважину, точка без пары) — это всегда видно в таблице до «Применить».
- Скважина прошла по акту и не прошла по паспорту: два разных допуска на одну величину.
- Уже выпущенные ревизии паспортов, проектов МВ и слоёв меняют хэш или вид.

## 5. Подходы

**Куда идёт съёмка**

| | Суть | Почему нет / да |
|---|---|---|
| A. Только факт рядом | съёмка — в `as_drilled`, проект не меняется, факт в графах «Ф» | проект МВ подписан до результатов — против решения владельца |
| B. Проект МВ считает по факту | проект блока прежний, документы берут факт | две правды: план одно, документы другое; Р и Ф совпадают и теряют смысл |
| **C. Съёмка правит проект** ✓ | импорт → оценка → «Применить»: устья, глубины, вода в проект; `as_drilled` — история | выбран: один источник правды, переиспользует TASK-017 и `hole_recompute` |

**Подстройка после съёмки**

| | Суть | |
|---|---|---|
| Только показать | подсветить, где темп и ЛСПП вышли за границы | не цель владельца |
| Сразу в проект | лучший вариант применяется сам | коммутация утверждаемого документа без взгляда человека |
| **Подбор с карточками** ✓ | заряды — по правилам сразу; замедления — кнопка, перебор коммутации на зафиксированных скважинах, инженер выбирает карточку | выбран владельцем 14.11.2026 |

**Съёмка старых блоков:** только из BlastEX — на первых блоках слой пуст; **из BlastEX и из файлов** ✓ — выбран владельцем.

## 6. Решения

Владелец (14.11.2026): две стадии проекта; проект МВ подписывается по результатам съёмки; подстройка замедлений — подбор с карточками; стаканы — из BlastEX и из файлов.

Решения модели (владелец проверяет при чтении):

- **М1. Один источник допусков.** Оценка скважины и текст акта готовности берут допуски из **последней выпущенной ревизии** паспорта на бурение блока (`tol_depth_m`, `tol_collar_m`, ±0,3 м по умолчанию) — то, что было напечатано у бурильщиков. Угол — новое поле `tol_angle_deg` (±1° по умолчанию, пишется только когда задано). У копии по съёмке паспорт ищется по цепочке `parent_design_id`. Нет паспорта — умолчания с предупреждением. Условие 2 акта подставляет эти числа вместо зашитого «±0,5 м». Красные номера Г.1 по съёмке (`reporting/mass_blast/graphics/plans.py`, своя `OFFSET_TOLERANCE_M = 0.5`) берут допуск из **снимка ревизии слоя** «Факт»: новые ревизии кладут его в `seed`, у выпущенных ключа нет — печатается прежние 0,5 м.
- **М2. Утверждённый проект блока.** Черновик правится на месте. Утверждённый — «Копия по съёмке»: `fork_design` с переносом записей факта и сразу применённой съёмкой; новая копия утверждается человеком. Паспорт на бурение остаётся у прежней версии. Правило «утверждённое не меняется» не трогаем. Исходный блок получает пометку «заменён копией по съёмке» (метаданные); поиск соседей (5б) берёт последнего потомка по `parent_design_id`, так что один физический блок не даёт двойных стаканов.
- **М3. Стадия не хранится отдельным полем.** «Предварительный» / «по съёмке» выводится из проекта: съёмка применена (есть запись применения, см. 5а) — «по съёмке», иначе «предварительный». Подпись стадии — в шапке «Проектирования» и в списке проектов. Запись применения — в исполнительской части паспорта (`EXECUTION_PAYLOAD_KEYS`): сама по себе она `designed_sha256` не меняет.
- **М7. Оценка скважины.** Смещение устья — в плане (XY), не в 3D: разница отметок на неровной площадке не смещение. Отметка устья по съёмке идёт в проект отдельно. Глубина сравнивается с **нужной** длиной при снятой отметке устья: L_нужн = (Z_уст.ф − Z_подошвы)/cos α + Δ (та же формула `geometry.hole_depth_m`, подошва — проектная). Устье на 0,4 м выше при проектной длине — `ДОБУРИТЬ`.
- **М8. Вода съёмки** заменяет при «Применить» проектные интервалы воды скважины (`water_intervals`, роль `designed`, источник — съёмка): правила заряжания читают только их (`geology.designed_water_intervals`). Правила заряжания не меняются, заряды других паспортов не сдвигаются.
- **М9. Заряды** при «Применить» перестраиваются правилами только у скважин, которые «Применить» изменило; остальные (в том числе правленные руками) не трогаются. Это часть 5а, а не 5в.
- **М10. Объект блока.** У `BlastDesign` нет поля объекта. Добавляется `site_code` (пишется только когда задан): выбирается в «Съёмке», по умолчанию — объект CAD-источников паспорта. Без объекта соседей нет, слой пуст с подсказкой.
- **М11. Стаканы не входят в паспорт.** Они подтягиваются живьём из съёмок объекта при проверке и запуске подбора; в дочерний процесс подбора — как входные точки, в отпечаток итога подбора — их хэш (новый сосед — «Устарел»).
- **М4. Минимальное расстояние от устья до стакана — 1,0 м**, поле объекта в справочнике Cost V2 (`SitePayload`, `x-unit` м).
- **М5. Порядок PR** — 5а → 5б → 5в → 5г (ниже). Стаканы раньше подстройки: они нужны уже на предварительном проекте следующего блока.
- **М6. Импорт читает те же профили, что пишет вынос** (`stakeout_profile`), плюс CSV / XLSX с колонками (номер, X, Y, Z, глубина, угол, азимут, вода — что есть). Профиль своего справочника работает в обе стороны.

## 7. PR 5а — импорт съёмки и правка проекта

**Импорт к проекту**
- Файл → таблица точек. Сопоставление: по имени точки (`point_name` выноса или номер скважины `Hole.id`); имени нет или не найдено — ближайшее проектное устье в пределах 2·`tol_collar_m`, с пометкой «по близости». Две точки на одну скважину, точка без пары, скважина без точки — строки таблицы со статусом, «Применить» их не трогает, пока инженер не решит (сопоставить вручную, пропустить, отключить скважину).
- Глубина: из файла, если есть; иначе вводится в той же таблице. Пусто — глубина проектная, статус «глубина не замерена».
- Вода: отметка «обводнена» (и уровень, если есть) по скважине.
- Оценка по скважине — по допускам М1 и правилам М7: `ОК`, `ДОБУРИТЬ` (короче нужной длины больше допуска), `ПЕРЕБУР` (длиннее), `СМЕЩЕНИЕ` (устье в плане дальше допуска), `УГОЛ`, `ЛСПП` (первый ряд, отклонение больше 5 %), `ШАГ` (расстояние до соседей по смешанной сетке, больше 5 %). Несколько нарушений — все.

**«Применить к проекту»** — одно действие, один шаг отмены. Переносятся **все** скважины с точкой съёмки, в допуске и вне его (решение владельца В1). Разница меньше 1 мм в плане и по отметке, 1 см по глубине (округление файла) — «без изменения», скважина не трогается. Для перенесённой:
- устье → снятая точка: для скважины сетки — сдвиг с пометкой TASK-017 (`manual` `"xy"`, `manual_offset` от узла), для ручной — новое устье;
- отметка устья из съёмки → `manual` `collar_z`; замеренная глубина → длина, `manual` `length`; угол и азимут, если есть, — из съёмки, иначе проектные;
- вода — по М8;
- заряд — по М9;
- коммутация помечается устаревшей и пересчитывается тем же путём, что после сдвига мышкой (TASK-017 PR 3);
- в `as_drilled_holes` пишется запись по каждой применённой скважине (`provenance.method = "survey_import"`, имя файла, дата съёмки);
- запись применения: дата съёмки, файл (имя и sha256), кто применил, число скважин по статусам. Хранится в проекте блока (ключ пишется только когда есть). Она же делает стадию «по съёмке» (М3).

**Импорт без проекта (старый блок)**
- Файл ложится на объект (`site_code`) как «исполнительная съёмка блока»: название блока, горизонт (отметка подошвы), дата, точки (номер, X, Y, Z устья, глубина, угол, азимут — что есть). Своя таблица, версии по дате, как ситуация объекта.
- Блок BlastEX со статусом `executed`/`closed` и применённой съёмкой — тоже источник для соседей; отдельно его не импортируют.

**Интерфейс** — панель «Съёмка бурения» вместо «Факт бурения»: загрузка файла, профиль, таблица сопоставления с оценкой, «Применить к проекту» / «Копия по съёмке» (утверждённый). Ручной ввод по одной скважине остаётся.

## 8. PR 5б — соседние блоки и стаканы

- Соседи нового блока: исполнительная съёмка блоков того же объекта (BlastEX и импорт без проекта), у которых скважины ближе 15 м к контуру нового блока в плане.
- **Сверху**: блок вышележащего горизонта (его подошва в пределах ±1 м от кровли нового блока у скважины). Стакан — точка пересечения оси старой скважины с кровлей нового блока (поверхность TASK-013, без неё — плоскость отметки блока); без угла ось вертикальная; глубина стакана — часть скважины ниже кровли.
- **По бокам**: блоки того же горизонта — их скважины у общей границы, для глаза (без проверки стаканов).
- Слой «Соседние блоки» в «Виде» (план и 3D): устья соседей, стаканы кружком с радиусом М4; подпись блока и даты съёмки; «по проекту», если у соседа нет съёмки.
- Проверка `collar_in_socket`: устье ближе М4 к стакану. Живая проверка при сдвиге (`liveChecks.ts`), `validate` и отбраковка подбора раскладки (как `floor_beyond_toe`). Уровень — **предупреждение с высоким приоритетом** (решение владельца В3): в списке проверок первым и красным, на плане стакан и устье подсвечены. Утверждение проекта и выпуск ревизии паспорта на бурение при таких предупреждениях требуют отметки «Принимаю: устья в стаканах — N скв.» (решение модели); отметка с перечнем скважин пишется в журнал. Проверяются стаканы всех соседей: по съёмке (применённой в BlastEX или импортированной файлом) и «по проекту» у взорванных блоков без съёмки; у последних в сообщении — «стакан по проекту». Стаканы — по М11.

## 9. PR 5в — подстройка после съёмки

- Заряды пересчитываются уже в 5а (М9).
- Замедления: кнопка «Подобрать замедления» — подбор коммутации на зафиксированных скважинах, без смены сетки. Перебор: фланг вруба и ступени магистрали и цепочек из допустимых для системы инициирования; оценка и ранжирование — как у подбора раскладки, без критериев геометрии сетки (площадь без скважин и ЛСП не меняются). Фон, один подбор на сервер, карточки, «Применить» одним шагом отмены — как у подбора раскладки.
- **Где работает** (решение модели): только схема «магистраль + цепочки» и системы НСИ / ДШ — как у подбора раскладки. Блок на другой схеме — карточки предлагают перевести на «магистраль + цепочки» (видно в карточке); электронная система — кнопка недоступна с пояснением (электронный режим тайминга схема не применяет). Сеть, правленная руками (`ORIGIN_EDITED`), — перед запуском предупреждение, что применённая карточка заменит ручные правки.
- Подбор доступен и на предварительном проекте (полезен после ручных сдвигов).

## 10. PR 5г — проект МВ по факту и акт готовности

- Создание проекта МВ из блока на стадии «предварительный» — предупреждение и обязательная причина («бурение по проекту, съёмка не делалась» и т. п.), причина — в журнал проекта МВ и в примечание таблицы параметров.
- Акт готовности: условие 2 — допуски М1; плюс допуск **5 %** от проектного значения на ЛСПП и расстояния между скважинами (решение владельца В2): поля паспорта на бурение `tol_burden_pct`, `tol_spacing_pct` (умолчание 5, пишутся только когда заданы), оценка 5а добавляет статусы `ЛСПП` (первый ряд) и `ШАГ` по смешанной сетке. Акт **можно выпустить без съёмки** (В2): тогда проверка съёмки не выполняется, а в акт и журнал идёт причина, с которой создан проект МВ. При съёмке — предупреждение (не ошибка) у включённых скважин без записи съёмки или вне допуска. Скважины, отключённые инженером, в проверку не входят.
- Графы «Ф» и слой «Факт» остаются: после применённой съёмки Р и Ф совпадают по геометрии, расходятся после заряжания.
