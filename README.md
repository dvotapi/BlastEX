# BlastEX

Калькулятор параметров взрывных работ и сметы БВР: новый React-интерфейс,
подбор сетки скважин по модели Кузнецова, интерактивная схема заряда,
расчёт стоимости бурения и агрегированная смета по сценариям.

## Возможности

- **Технологический расчёт** — оптимизация удельного расхода ВВ, ЛНС, сетки скважин, оценка негабарита.
- **Смета** — переменные и постоянные затраты, ФОТ, стоимость бурения, несколько сценариев (`drill_blast`, `blasting`, `drilling` и др.).
- **Справочники организации** — породы, ВВ, амортизация ОС, объекты работ, бурстанки, номенклатура и цены; сохранение в `data/teams/{id}/`.
- **Проектирование блока** — контур, импорт съёмки уступа (XYZ/CSV/DXF/GeoJSON), TIN-поверхности, геологические домены и интервалы по скважинам, сетка скважин по реальному рельефу, факт бурения / заряжания / взрыва без перезаписи проекта, результаты после взрыва (кусковатость, PPV, развал, вывал, забой, смета факт), неизменяемые снимки датасетов, калибровка площадки (невязка Kuz-Ram / PPV поверх инженерного базиса) и специализированный прогноз исходов (X50 / X80 / негабарит / PPV / риск забоя) с интервалом, флагом экстраполяции и списком драйверов (важность / SHAP-стиль / дельта рекомендации), сравнение инженерных сценариев (диаметр / сетка / q) без изменения утверждённого паспорта, детерминированный поиск Парето по оверлеям (стоимость / негабарит / погонаж / PPV / целевой X50) без замены проекта, только как рекомендация, глобальный prior и адаптация площадки, реестр моделей с ручным продвижением, мониторинг дрифта (только сигналы), скважинный / окрестностный ML-слой predicted (X50 / негабарит / забой / остатки) без перезаписи зарядов и сетки, оценка развала и вывала (оценка / estimate, слой predicted, не физическая симуляция), официальный паспорт БВР с колонками DESIGNED / EXECUTED / PREDICTED / MEASURED (без автоутверждения).
- **REST API** — расчёты БВР и сметы без Streamlit UI.
- **Внутренний доступ** — обязательный вход по email/паролю и роли `admin`, `reference_editor`, `user`.

Подключение внешних организаций в текущей версии отключено заглушкой.

## Быстрый старт

### 1. Виртуальное окружение

```bash
cd BlastEX
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Новый веб-интерфейс (React)

В первом терминале запустите API:

```bash
export BLASTEX_SESSION_SECRET="локальный-секрет"
export BLASTEX_COOKIE_SECURE=false
uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Откроется `http://127.0.0.1:5173`. Vite передаёт запросы `/api` локальному
FastAPI. React-интерфейс реализует все четыре раздела Streamlit-версии: расчёт
БВР (оптимизация сетки, схема заряда, смета), расчёт стоимости бурения, ФОТ и
справочники — с тем же рабочим пространством команды (объект работ, сценарий,
сохранение/загрузка) и тем же ролевым разграничением редактирования.

### 3. Резервный интерфейс (Streamlit)

```bash
source .venv/bin/activate
streamlit run app.py
```

Откроется `http://localhost:8501`.

**Внутренние пользователи:**

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
python3 scripts/hash_password.py
# вставьте полученный password_hash и задайте email/роль в secrets.toml
```

Роли:

- `admin` — расчёты, справочники и администрирование;
- `reference_editor` — расчёты и редактирование справочников;
- `user` — расчёты и просмотр справочников.

Альтернатива файлу secrets — JSON-массив пользователей в
`BLASTEX_USERS_JSON`. Старые установки с `BLASTEX_ADMIN_PASSWORD` или
`[blastex].admin_password` продолжают работать с email `admin@localhost`
(его можно переопределить через `BLASTEX_ADMIN_EMAIL`).

После смены пароля или создания `secrets.toml` перезапустите Streamlit.

### 4. REST API (опционально)

```bash
source .venv/bin/activate
pip install -r requirements-api.txt
export BLASTEX_API_KEY="длинный-случайный-секрет"
uvicorn api.main:app --reload --host 0.0.0.0 --port 8000
```

- Swagger UI: `http://localhost:8000/docs`
- Health: `http://localhost:8000/health`

### 5. Единый запуск через Docker

Создайте хеш пароля и `.env`:

```bash
python3 scripts/hash_password.py
cp .env.example .env
# замените секреты, email, название организации и password_hash
docker compose up --build
```

Откроется `http://localhost`. FastAPI не публикуется отдельным портом, а данные
`data/teams` сохраняются в Docker volume.

Для VDS с доменом задайте в `.env`:

```dotenv
BLASTEX_SITE_ADDRESS=blast.example.ru
BLASTEX_CORS_ORIGINS=https://blast.example.ru
BLASTEX_COOKIE_SECURE=true
```

Caddy автоматически настроит HTTPS, если DNS домена указывает на VDS и наружу
открыты порты 80 и 443.

Все маршруты `/api/v1/*` требуют заголовок `X-API-Key`. Без переменной
`BLASTEX_API_KEY` API закрывается с кодом `503`; `/health` остаётся доступным
для проверки состояния контейнера.

### 6. Автоматический production-деплой

Workflow `.github/workflows/deploy.yml` запускается после каждого push в
`main`: выполняет Python-тесты, собирает React-фронтенд и по SSH обновляет
production VPS. Ручной запуск доступен через `workflow_dispatch`.

Для GitHub Environment `production` нужны секреты:

| Секрет | Назначение |
|--------|------------|
| `VPS_HOST` | IP-адрес или hostname сервера |
| `VPS_USER` | SSH-пользователь деплоя |
| `VPS_SSH_PRIVATE_KEY` | отдельный приватный deploy-ключ |
| `VPS_KNOWN_HOSTS` | закреплённый SSH host key сервера |

На сервере репозиторий должен находиться в
`/root/complex-services-web/blastex`, а `.env` и внешняя Docker-сеть
`blastex-edge` создаются при первичном ручном развёртывании. Скрипт
`scripts/deploy_vps.sh` сохраняет предыдущие Docker-образы и откатывает их,
если новая версия не проходит health-check. Ключ GitHub Actions на VPS должен
быть ограничен forced command `/usr/local/sbin/deploy-blastex` и опцией
`restrict`, чтобы его нельзя было использовать для произвольного SSH-доступа.

## Веб-интерфейс

Ниже — состав разделов, одинаковый в обоих интерфейсах (React — основной,
Streamlit — резервный, см. «Быстрый старт»).

| Вкладка | Назначение |
|---------|------------|
| **Расчёт** | Технический расчёт БВР, схема заряда, смета по сценарию |
| **Расчёт стоимости бурения** | Калькулятор цены бурения за 1 п.м. |
| **Расчёт ФОТ** | Фонд оплаты труда |
| **Справочники** | Породы, ВВ, амортизация ОС, объекты и станки, номенклатура, постоянные расходы |

Панель над вкладками: внутренняя организация текущего пользователя, объект
работ, сценарий, кнопки **Сохранить** / **Загрузить**.

### Справочники

Подвкладки на **«Справочники»**:

| Раздел | Данные |
|--------|--------|
| Горные породы | Плотность, UCS, трещиноватость |
| Взрывчатые вещества | Плотность, теплота, подпись на схеме |
| Амортизация ОС | Стоимость, СПИ, смены; норма в смену считается автоматически |
| Объекты и станки | Мобилизация, ДТ, амортизация и расход топлива БУ |
| Номенклатура и цены | ВВ, СВ, СИ (цены без НДС) |
| Постоянные расходы | Разделы 2.1–2.6 сметы |

Справочники команды хранятся в `data/teams/{team_id}/references.json` и подставляются в расчёт БВР, бурения и сметы. Без входа администратора справочники доступны только для просмотра.

### Калибровка площадки (BDX-012)

Обучение читает только неизменяемый снимок `/datasets/{id}`. Новая модель всегда
со статусом `candidate` и не подключается к производственному расчёту, пока её
явно не пометить как `production`. Прогноз — слой рекомендации
`базис + невязка`; паспорт БВР ML не меняет и не утверждает.

### Прогноз исходов (BDX-013)

Отдельные модели `FragmentationModel`, `VibrationModel`, `OversizeModel` и
`ToeRiskModel` (деревья sklearn, без нейросети по умолчанию) предсказывают
замеренные исходы напрямую, а не одной универсальной сетью. Обучение — только
по неизменяемому снимку. Прогноз — слой рекомендации с версией модели;
паспорт БВР не изменяется и не утверждается.

### Неопределённость прогноза (BDX-014)

Каждый прогноз калибровки и исхода возвращает не только точку, но и
`uncertainty` (ожидаемый интервал), `confidence`, `similarity_score` и
`applicability_warning`. Признаки запроса сравниваются с min/max снимка
обучения: диаметр 311 мм при истории 152–229 мм помечается как экстраполяция,
уверенность снижается, интервал расширяется. UI показывает интервал,
уверенность, число сопоставимых взрывов и предупреждение.

### Объяснимость прогноза (BDX-015)

Каждый прогноз калибровки и исхода возвращает `explanation`: список драйверов
(доля вклада, SHAP-стиль по пути дерева sklearn, глобальная важность) и
дельты рекомендации вида «снижение ЛНС → ожидаемый X50 −34 мм». Это слой
объяснения текущего оверлея, а не полный движок сценариев (BDX-016) и не
оптимизатор (BDX-017). UI показывает список драйверов в панелях прогноза.

### Сценарии сравнения (BDX-016)

Инженерные альтернативы (диаметр, ЛНС × шаг, удельный расход q) считаются
как копии/оверлеи утверждённого паспорта. Скважины и заряды проекта не
перезаписываются. Сравнение — таблица погонажа, массы ВВ, X50 / X80 /
негабарита, MIC / PPV, прямых затрат и прогнозной сметы. Если есть
production-модели исходов или калибровки, они подставляются как слой
рекомендации. Это не оптимизатор (BDX-017) и не движок ML-рекомендаций
(BDX-018).

### Оптимизация Парето (BDX-017)

Детерминированный перебор дискретной сетки переменных (диаметр, ЛНС, шаг,
перебур, забойка, тип ВВ, наклон, замедления) поверх движка сценариев
BDX-016. Каждый кандидат — оверлей: утверждённый паспорт не мутирует и не
заменяется выбранной точкой. Цели — прогнозные (PREDICTED): затраты,
негабарит, погонаж бурения, PPV и отклонение от целевого X50 (мм, без
скрытой конвертации). Фронт — недоминируемые решения; компромисс — точка
ближайшая к утопии. RL нет, ML не перепроектирует блок.

### Рекомендация проекта (BDX-018)

ML предлагает оверлей, но не утверждает паспорт. Профили: `BALANCED`,
`LOW_COST`, `FINE_FRAGMENTATION`, `LOW_VIBRATION`. Кандидат берётся с
Парето-фронта BDX-017 (через движок сценариев BDX-016). «Почему» —
сравнение с утверждённым проектом плюс драйверы BDX-015; если есть
production-модели, к оверлею добавляются интервал, уверенность, сходство
и флаг экстраполяции BDX-014. Рекомендация никогда не применяется сама:
инженер решает, сохранить её как сценарий сравнения или оставить паспорт.

### Глобальное и площадочное обучение (BDX-019)

Два уровня внутри одной команды: глобальный prior и адаптация площадки.
Обучение только по неизменяемым снимкам. Снимки и модели одной команды
не видны другой. Новая модель остаётся `candidate`, пока её явно не
продвинут в реестре (BDX-020).

### Реестр моделей (BDX-020)

Формальный жизненный цикл поверх уже обученных артефактов BDX-012 / 013 / 019:
версии, контрольная сумма (`artifact_sha256`), происхождение неизменяемого
снимка датасета, кто продвинул и когда. Статусы:
`candidate → staging | production → retired | archived`. Продвижение только
вручную (`confirm=true` и идентификатор человека). Автодеплоя нет, обучение
из живых паспортов запрещено. Реестр не копирует estimator — это обёртка
над существующими каталогами команды, с той же изоляцией `team_id`.

### Оценка развала и вывала (BDX-023)

Эмпирическая кинематическая **оценка** (оценка / estimate) отброса,
вывала и разрыхления. Это не валидированный движок физики и не
«симуляция физики». Результат — только слой `predicted`: скважины,
заряды и сетка паспорта не перезаписываются. API:
`GET /design/movement/models`, `POST /design/movement`.

### Официальный паспорт БВР (BDX-024)

Инженерный документ, не дамп ML. В одной таблице держатся четыре независимые
роли: **DESIGNED** (проект), **EXECUTED** (факт бурения / заряжания / взрыва),
**PREDICTED** (дробление, PPV, оценка развала) и **MEASURED** (замер после
взрыва). Плановая смета остаётся проектной, фактическая — замером. Документ
не утверждает паспорт и не переписывает скважины. API:
`GET /design/passport/roles`, `POST /design/passport`,
`POST /design/passport.html`, `GET /design/plans/{id}/passport`.

### Жизненный цикл паспорта (BDX-025)

Формальные статусы **Draft → In Review → Approved → Executed → Closed**.
Смена статуса только вручную (`confirm=true`, человеческий актор). После
утверждения слой DESIGNED заморожен; закрытый паспорт нельзя менять вовсе.
Сценарии, оптимизация и ML остаются оверлеями и не двигают статус.
API: `GET /design/lifecycle/meta`, `GET|POST /design/plans/{id}/lifecycle`,
`POST /design/plans/{id}/fork`.

### Рабочая станция инженера (BDX-026)

UI паспорта повторяет инженерный маршрут: съёмка → геология → сетка →
заряд → тайминг → симуляция → исполнение → интеллект → сценарии → отчёт.
Каждая панель с оверлеем подписана **DESIGNED / EXECUTED / PREDICTED /
MEASURED**. Утверждённый или закрытый паспорт нельзя править в интерфейсе:
кнопки жизненного цикла требуют подтверждения, ревизия открывается как
черновик. Единицы показываются как хранятся, без скрытого перевода.
API: `GET /design/workstation/meta`.

## Модуль `Blast.py` — технология

Движок `BlastEngine` подбирает минимальный удельный расход `q` (кг/м³) при заданном пороге негабарита.

**Входные данные:**

| Класс | Поля |
|-------|------|
| `RockProperties` | порода, плотность, UCS, трещиноватость |
| `ExplosiveProperties` | название, плотность заряжания, теплота взрыва |
| `TargetParams` | размер негабарита, высота уступа, перебур, коэфф. сетки a/W |

**Выход оптимизации:** диаметр коронки, ЛНС `W`, сетка `a×b`, `x50`, `% негабарита`, удельный расход `q`.

Модель дробимости — **Кузнецов** + распределение **Розина–Рамблера** для оценки негабарита.

Породы и ВВ в UI берутся из справочников команды (вкладка «Справочники»), а не из констант в коде.

## Схема заряда скважины

После оптимизации в `app.py` появляется блок **«Схема заряда скважины»**: две колонки для сравнения вариантов (по умолчанию АСП / ЭВВ), как в Excel-смете.

### Формулы (`blast_hole.py`)

| Показатель | Формула |
|------------|---------|
| **Выход ВГМ** | `a × b × (глубина − перебур)` |
| **Длина заряда** | `глубина − недозаряд` |
| **Масса заряда** | `длина × π×d²/4 × ρ_ВВ` |
| **Удельный расход** | `масса / выход` |

На схеме: **недозаряд + заряд = полная глубина скважины**. Выход породы считается по эффективной высоте уступа `(глубина − перебур)`.

### Использование

1. Задайте параметры и нажмите **Рассчитать**.
2. Выберите вариант в **«Вариант для схемы заряда»**.
3. Меняйте **тип ВВ** и **недозаряд (верх скважины), м** — таблица и рисунок пересчитываются сразу.

## Логика Excel-сметы (кратко)

**Блоки сметы:**

- **Переменные:** ВМ и СИ (1.1), буровой инструмент (1.2)
- **Постоянные:** хранение и доставка (2.1), суточные (2.2), ФОТ (2.3), ГСМ (2.4), амортизация (2.5), общепроизводственные (2.6)
- **Итог:** себестоимость + АХР + рентабельность → цена без НДС → × 1.2 с НДС

**Стоимость бурения** — отдельный лист «Расчет стоимости бурения» → цена за 1 п.м., подставляется в главную смету.
