# TASK-002 — Единый контур технических и экономических расчётов

## Цель

Связать модули в единый воспроизводимый поток:

`project1 → технический расчёт БВР → технический паспорт → себестоимость операции → экономика карьера → экономика производственного юнита`.

Единым источником справочных данных для технического расчёта, Cost V1 и Cost V2 являются версионные справочники схемы `blastex` в PostgreSQL `project1`.

## Целевое поведение

### Вкладка «Расчёт»

- Сохранить выбор наименования объекта из `sites`.
- Оставить только технические входы и результаты: удельный расход, сетка, геометрия, объём, скважины, бурение, масса ВМ и дробление.
- Убрать из видимого интерфейса Cost V1 `CostPanel`.
- Сохранять неизменяемую версию технического паспорта. Исправление создаёт новую версию.

### Вкладка «Экономика»

Разделить на три режима:

1. «Одна операция / взрыв» — прямая и приростная себестоимость по техническому паспорту и пакету работ.
2. «Карьер: месяц / год» — один типовой паспорт на месяц с масштабированием физических драйверов по объёму горной массы.
3. «Производственный юнит» — агрегация карьеров, мощностей и общепроизводственных расходов со сравнением «До / После / Изменение».

Рыночная цена, выручка и маржа отображаются отдельно и не влияют на внутреннюю себестоимость.

## Данные и API

- Добавить справочники `rocks` и `blast_design_parameters`.
- Добавить таблицы `technical_passports`, `legacy_workspace_settings`, `legacy_cost_scenarios`.
- Расширить `calculation_runs` областью расчёта, объектом, периодом и ссылкой на паспорт.
- Добавить API `GET/POST /economics/technical-passports`, `GET /economics/technical-passports/{id}` и `POST /economics/calculations/event`.
- Добавить `technical_passport_id` в месячный план Cost V2 без нарушения старых запросов.
- Сохранить контракты `/workspace`, `/workspace/snapshot`, `/workspace/active-scenario` и `/cost/calculate`, заменив JSON-персистентность на PostgreSQL-репозиторий.
- При недоступности `project1` возвращать `503`; тихий fallback на JSON запрещён.

## Миграция

1. Создать резервную копию `data/teams` вне приложения.
2. Выполнить идемпотентный dry-run импорта.
3. Опубликовать сопоставленную ревизию справочников.
4. Сравнить эталонные расчёты Cost V1 до копейки.
5. Включить PostgreSQL как единственный runtime-backend.
6. Для отката предоставить экспорт PostgreSQL обратно в совместимые JSON-файлы.

## Критерии приёмки

- На первой вкладке видно наименование объекта, но нет денежных расчётов.
- Технический паспорт воспроизводится по снимку входов, формул и справочников.
- Типовой паспорт корректно масштабируется на месячный объём, а год равен сумме месяцев.
- Cost V1 до и после миграции даёт одинаковые результаты.
- Приростная и полная себестоимость не смешиваются.
- Рыночная цена может быть ниже себестоимости и не меняет затраты.
- Сохраняются все десять пакетов работ и их границы ответственности.
